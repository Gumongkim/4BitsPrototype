# 유물 비트 메이커 — Claude 지침서

`relic-beat-tool/`에서 일할 때 읽는 문서다. 툴 사용법, 조정할 수 있는 값, 설계서(.md) 양식, 설계서를 직접 쓰거나 게임에 옮길 때의 규칙, 툴을 고칠 때의 주의점을 담는다.
값의 원본은 `tool.js`다. 이 문서와 코드가 다르면 코드를 따르고 이 문서를 고친다. 답변은 한국어로 쓴다(프로젝트 루트 `CLAUDE.md` 규칙).

> **폐기 안내 (2026-11-08):** 유물과 게임 BGM을 연동하는 작업은 구현이 어려워 폐기했다. 이 툴과 `relic-beats-*.md` 설계서, `*-roles.md` 역할표는 보존만 한다. 게임 코드(`config.js`, `game.js` 등)에 옮기지 않으며, 사용자가 다시 요청하기 전에는 연동 작업을 제안하거나 진행하지 않는다. 아래 "게임에 옮길 때", "게임에서는 무기 킥에 맞춘다" 같은 내용은 폐기 전 기록이다. 툴이 내보내는 설계서의 '게임 반영 시 주의' 문구도 같은 이유로 지금은 의미가 없다.

## 1. 이 툴은 무엇인가

- 게임의 유물마다 고유한 16박 비트(악기 1종)를 찍고, 최대 5개를 겹쳐 믹스로 들어 보고, 설계서(.md)와 WAV로 내보내는 웹 툴이다. 원래 게임 BGM의 유물별 층으로 쓸 데이터를 만들려 했으나 연동은 폐기됐다(맨 위 폐기 안내).
- **두 모드:** 위쪽 '모드'에서 고른다.
  - **유물 악기 모드**(기본): 유물마다 악기·음·리듬이 정해져 있다. 이 문서의 1~9장은 이 모드 기준이다.
  - **슬롯 악기 모드**: 믹스 바 5칸(슬롯)이 악기·역할·음역·믹스 설정을 갖고, 유물은 리듬과 코드 기준 높낮이(degree)만 갖는 '패턴 유물'이다. 유물을 얻은 순서대로 슬롯 1 → 5에 들어가 그 슬롯의 악기로 연주된다. 자세한 것은 10장.
  - 두 모드의 유물 목록·믹스 바는 따로 저장되고, 전역 설정(템포, 격자, 키, 스케일, 스윙, 사이클, 딜레이, 데모 드럼, 펌핑 기준)은 같이 쓴다.
- 게임 코드(`config.js` 등)와 독립이다. 웹 링크(Artifact)에 넣지 않으므로 툴만 고쳤으면 재게시하지 않는다.
- 파일: `index.html`(화면), `tool.css`(스타일), `tool.js`(전부), `relic-beats-*.md`(설계서 예시·작업물), 이 문서.
- 기술 제약: 바닐라 JS, 클래식 `<script>`, 외부 라이브러리·오디오 파일 없음, `index.html` 더블클릭(file://)으로 동작. 소리는 Web Audio로 합성한다. AudioWorklet은 file://에서 모듈 로드가 막혀 쓰지 않는다. 수치 상수는 `tool.js` 맨 위 `TOOL`에 둔다.

## 2. 시간 기준

| 항목 | 값 |
|---|---|
템포(`state.bpm`)와 격자(`state.grid`)는 전체 설정이다. 칸 수·칸 시간·루프 길이는 상수가 아니라 `gridSteps()`, `stepSeconds()`, `loopSeconds()`로 계산한다.

| 항목 | 값 |
|---|---|
| 템포 | 60~180BPM 정수, 기본 130 (4분음표 기준). 게임 링 박자와 묶여 있지 않다 |
| 1박 | 4분음표 = 60 / bpm초 (130BPM이면 약 0.4615초) |
| 격자 | 8(기본): 1칸 = 0.5박 = 8분음표 = 30 / bpm초, 32칸. 16: 1칸 = 0.25박 = 16분음표 = 15 / bpm초, 64칸 |
| 루프 | 16박 = 4마디(4/4) = 칸 수 x 1칸 (130BPM이면 약 7.385초), 반복 |
| 칸 번호 | 8분: 0~31, "박.위치"로 칸 0 = 1.0, 칸 1 = 1.5, 칸 31 = 16.5. 16분: 0~63, 칸 0 = 1.0, 1 = 1.25, 2 = 1.5, 3 = 1.75, 칸 63 = 16.75 |
| 박 번호 → 칸 | 8분: 칸 = (박 - 1) x 2 (예: 4.5박 → 칸 7). 16분: 칸 = (박 - 1) x 4 (예: 4.75박 → 칸 15) |
| 칸 i의 시각 | i x 1칸 + (i가 홀수면 swing x 1칸). 16분 격자에서는 16분 스윙(e·a 칸)이 된다 |

- **템포 바꾸기:** 재생 중에 바꾸면 처음부터 다시 재생한다(예약해 둔 칸 시각이 모두 바뀌므로, 루프 중간에서 이어 붙이지 않는다). 격자 바꾸기도 같다.
- **격자 바꾸기:** 8 → 16은 모든 노트의 `step`·`length`를 2배로 해 소리가 같다. 16 → 8은 홀수 칸에서 시작하는 노트가 있으면 확인 창에 개수를 알리고, 확인하면 그 노트를 지우고(앞 칸으로 옮기지 않는다) 나머지를 반으로 한다(`length`는 올림). 롤(`repeat`)은 그대로다. `convertRelicGrid`가 한다.
- **옛 설계서:** 2026-11-08 이전 버전은 1박 0.3초(8분음표 100BPM, 2마디)였다. `bpm`·`grid`가 없는 설계서는 8분 격자·130BPM으로 읽는다(원래 소리로 되살리는 변환은 하지 않는다). JSON `timing`은 참고값이라 불러올 때 쓰지 않는다.
- **이전 툴과의 호환:** 16분 격자 설계서(칸 0~63)를 8분 격자만 아는 이전 툴로 열면 범위 밖 칸 때문에 거부된다.

## 3. 화면과 조작

- **왼쪽:** 유물 목록(+ 추가, 이름 중복 불가·30자, 체크박스 = 내보내기 대상, ✎ 이름 변경, × 삭제, '체크한 유물 삭제'), 악기 프리셋 목록(카테고리 머리글), 오디오 내보내기(WAV)와 'WAV에 데모 드럼 포함', 'WAV 길이'(한 루프 / 한 사이클), 설계서 내보내기, 불러오기(파일 선택 또는 화면에 끌어다 놓기).
- **위쪽:** 모드(유물 악기 / 슬롯 악기, 10장), 키(C~B), 스케일, 행 수(8/15) 선택, 믹스 바 5칸(+ 넣기, × 빼기, 칸 볼륨 0~150%), 믹스 재생, 랜덤 믹스(전체 유물에서 무작위로 5칸 채움). 둘째 줄은 전역 설정: 템포(숫자 입력, BPM), 격자(8분 32칸 / 16분 64칸), 사이클(1/2/4/8루프), 스윙 0~50%, 딜레이(8분/점8분/4분/점4분), 데모 드럼(없음/록·J-pop/붐뱁/하우스·EDM/일렉트로닉 팝/투스텝·UK 개러지)과 킥·스네어 켜기 체크박스, 킥 음색(기본 / 909 / 딥), 드럼 볼륨, 펌핑 기준(데모 킥 / 4분 정박), 바이닐 노이즈.
- **가운데 편집기:** 세로 음높이(위가 높음), 가로 32칸(8분) 또는 64칸(16분). 15행이면 행 높이가 18px로 준다. 마디(4박) 경계가 가장 굵고 박 경계가 굵다. 16분 격자에서는 8분 경계를 중간 굵기로 긋고, 칸 최소 너비가 14px이라 화면이 좁으면 가로 스크롤이 생긴다. 편집기 위에 '입력 세기'(강/중/약), '새 노트 길이'(8분 1/2/4/8칸, 16분 1/2/4/8/16칸), '코드'(없음/3화음/7화음/sus4/add9: 누른 행을 근음으로 스케일 위에 행 간격 [0,2,4] / [0,2,4,6] / [0,3,4] / [0,2,4,8]을 한 번에 찍는다. 행 범위를 넘는 음과 이미 그 칸에서 시작하는 행은 뺀다. 타악이면 꺼진다), '롤'(없음/2/3/4번, 2 이상이면 1칸 롤 노트를 찍고 길이 선택은 쓰지 않는다). 롤 노트는 칸 안에 (롤 수 - 1)개의 가는 세로 선이 보이고 길이 손잡이가 없다.
  - 빈 칸 클릭: 찍기. 노트 시작 칸 클릭: 지우기. 드래그: 처음 동작(찍기/지우기)을 이어서.
  - Shift+클릭 또는 우클릭: 세기를 강 → 중 → 약 → 강으로.
  - 음높이 노트의 마지막 칸 오른쪽 끝(7px)을 끌기: 길이 바꾸기. 같은 행의 다음 노트에서 멈춘다.
  - 긴 노트가 이어지는 칸에 찍으면 앞 노트가 그 칸 직전까지 줄고 새 노트가 생긴다.
  - 같은 칸에 여러 행(화음)을 찍을 수 있다. 찍을 때 그 음이 한 번 들린다. 재생 중에는 흰 선이 현재 위치이고, 사이클이 2루프 이상이면 편집기 제목 옆에 '루프 2/4'처럼 사이클 위치가 보인다.
- **오른쪽:** 선택한 유물 단독 재생, 유물 볼륨(0~150%), 노트 모두 지우기, 믹스 설정 슬라이더(사이드체인, 리버브 센드, 딜레이 센드, 로파이, 저음 깎기, 고음 깎기, 코러스, 홀 리버브, 테이프, 각 0~100%. 저음·고음 깎기는 필터 Hz도 보인다), 유물 설정(스윙 슬라이더와 '전체 스윙 따름' 체크, 팬 -100~+100, 옥타브 -2~+2 선택(타악은 꺼짐), 필터 스윕 켜기와 시작·끝 슬라이더·스윕 모양, 사이클이 2루프 이상이면 등장 루프 체크박스 줄), 정보(악기, 음높이 범위, 노트 수, 특징).
- 단독 재생과 믹스 재생은 동시에 돌지 않는다. 재생 중 편집·볼륨·칸 변경이 바로 반영된다.
- 작업 상태는 localStorage `relicBeatTool.state`에 자동 저장된다. 이전 버전이 저장한 상태도 없는 항목을 기본값으로 채워 연다.

## 4. 조정할 수 있는 값

### 4-1. 유물별 값 (설계서 JSON에 들어간다)

| 값 | 범위 | 기본 | 뜻 |
|---|---|---|---|
| `preset` | 프리셋 id | `marimba` | 악기 1종 |
| `volume` | 0 ~ 1.5 | 1 | 유물 볼륨 |
| `sidechain` | 0 ~ 1 | 0 | 펌핑 기준 칸마다 소리를 (1 - 값)까지 0.01초에 눌렀다가 0.2초에 되돌린다. 기준이 '데모 킥'이면 데모 드럼 킥이 울리는 칸(데모 드럼 '없음'이나 킥 끔이면 효과 없음), '4분 정박'이면 매 박 머리 |
| `reverbSend` | 0 ~ 1 | 0 | 공통 리버브로 보내는 양 |
| `delaySend` | 0 ~ 1 | 0 | 공통 딜레이로 보내는 양 |
| `lofi` | 0 ~ 1 | 0 | 계단 곡선(12비트 → 3비트) + 로우패스(18kHz → 2.5kHz) |
| `lowCut` | 0 ~ 1 | 0 | 저음 깎기: 하이패스 20 x (800 / 20)^값 Hz (0.5 → 126Hz, 1 → 800Hz), Q 0.707 |
| `highCut` | 0 ~ 1 | 0 | 고음 깎기: 로우패스 20000 x (800 / 20000)^값 Hz (0.5 → 4kHz, 1 → 800Hz), Q 0.707 |
| `chorus` | 0 ~ 1 | 0 | 스테레오 코러스(로파이 뒤, 팬 앞). 좌우 지연 15ms를 ±3ms 반대 위상으로 흔든다. LFO 1마디에 한 번(bpm / 240 Hz), 루프 머리에서 위상 0. 젖은 소리 = 값, 마른 소리 = 1 - 값 x 0.5 |
| `hallSend` | 0 ~ 1 | 0 | 두 번째 리버브 '홀'(4초)로 보내는 양. 어떤 유물도 0보다 크지 않으면 홀 버스를 만들지 않는다 |
| `tape` | 0 ~ 1 | 0 | 테이프 질감(필터 스윕 뒤, 로파이 앞): 포화 tanh drive 1 + 4 x 값(출력 레벨 보정), 흔들림 8ms 지연을 ±0.6 x 값 ms로 2박에 한 번(bpm / 120 Hz), 고음 감쇠 로우패스 18000 x (6000/18000)^값 Hz. 로파이 = 디지털 샘플러(비트 감소), 테이프 = 아날로그 녹음(포화·흔들림) |
| 노트 `velocity` | 0 ~ 1 | 1 | 노트 게인 배율. 입력 단계는 강 1.0 / 중 0.7 / 약 0.4 |
| 노트 `length` | 1 ~ (칸 수 - 시작 칸) | 1 | 칸 수. 음높이 악기만 쓴다(타악은 무시). 같은 행에서 노트끼리 겹치지 않는다 |
| 노트 `repeat` | 1 ~ 4 | 1 | 롤: 그 칸(스윙 반영)을 N등분해 같은 세기로 N번 친다. 한 번의 게이트는 그 간격. 2 이상이면 `length`는 1로 맞춘다 |
| `swing` | 0 ~ 0.5 또는 없음 | 없음 | 있으면 이 유물만 이 스윙으로 홀수 칸을 늦춘다. 없으면 전체 스윙을 따른다(데모 드럼과 펌핑은 항상 전체 스윙·킥 기준) |
| `octaveShift` | -2 ~ 2 정수 | 0 | 행 0의 MIDI에 12 x 값을 더한다. 음높이 악기만 |
| `pan` | -1 ~ 1 | 0 | 0이 아니면 로파이 뒤에 StereoPanner. 리버브·딜레이 센드는 팬 앞(가운데)에서 뽑는다. -1이면 오른쪽 채널 무음 |
| `filterSweep` | `{ from, to, shape? }` 각 0 ~ 1 또는 없음 | 없음 | 사이클(루프 x `cycleLoops`) 동안 로우패스 컷오프를 움직인다(0~1 -> Hz는 `highCut`과 같다: 0 = 20kHz, 1 = 800Hz, Hz 지수 램프). `shape`: up(from -> to, 기본, 내보내지 않음) / down(to -> from) / upDown(사이클 앞 절반 from -> to, 뒤 절반 to -> from, 사이클 끝과 머리가 같아 튀지 않는다). 사이클 머리마다 처음 값으로. `highCut`과 따로 직렬로 건다. 켤 때 기본 from 0.8(약 1.5kHz), to 0(20kHz). 사이클 1에 up이면 이전과 같다 |
| `loops` | 불리언 배열(최대 8) 또는 없음 | 없음(모두 켜짐) | 사이클 안 루프별 등장. false인 루프에서는 노트를 예약하지 않는다(꼬리·리버브는 남고 사이드체인·필터 스윕은 계속). 길이가 사이클과 다르면 앞에서부터 쓰고 모자라면 켜짐. 모두 켜짐이면 지운다 |

### 4-2. 전역 값

| 값 | 범위 | 기본 | 설계서 | 뜻 |
|---|---|---|---|---|
| 스케일 | `SCALES` 11종 | C 마이너 펜타토닉 | `scale` | 음높이 행의 음. C 마이너/메이저 펜타토닉, C 자연 단음계, C 장음계, C 도리안, C 블루스, C 프리지안, C 믹솔리디안, C 하모닉 마이너, C 리디안, C 반음계 |
| 키 `root` | 0 ~ 11 정수 | 0 (C) | `root` (0이 아닐 때만) | 모든 음을 C에서 root 반음 올린다. 스케일 이름은 C 기준 그대로, 설계서에는 "A 자연 단음계 (C 자연 단음계 + root 9)"처럼 쓴다 |

데모 드럼용 909 킥·딥 킥(`DEMO_DRUM_SOUNDS.kick909`·`deep`)은 유물 프리셋이 아니다(킥·스네어 정책). 보컬 모음 4종(우·오·이·에)은 `vocal_chop`과 같은 오실레이터·비브라토·엔벨로프에 숨소리 노이즈(`noise.gain` 0.08)를 더했고, 포먼트는 성인 남녀 평균을 섞은 출발점이다(들어 보고 조정). 2026-11-08 2차 추가분(보컬 챱 ~ 슈퍼소 패드 7종)의 노트 피크는 모두 0.95 이하다.

### 4-5. 프리셋 파라미터 형식 (`params`)

| 항목 | 형식 | 뜻 |
|---|---|---|
| `oscs` | `[{ type, ratio?, fixed?, detune?, gain? }]` | 오실레이터. `ratio`는 음높이 배수, `fixed`는 고정 Hz(타악), `detune` 센트 |
| `noise` | `{ gain, filter? }` | 노이즈. `filter`가 있으면 그 필터만 거쳐 메인 필터를 지나지 않는다 |
| `filter` | `{ type, freq, Q, from?, sweep? }` | 메인 필터. `from`이 있으면 노트 시작에 from Hz에서 sweep초 동안 freq로 |
| `pitchSlide` | `{ semis, time }` | 시작 음높이가 semis 반음 위(음수면 아래)에서 time초 동안 제 음으로 |
| `env` | `{ attack, decay, sustain, release }` | 초, sustain은 0~1 |
| `bursts` | `{ count, gap }` | 짧은 타격을 겹침(클랩) |
| `gain` | 수 | 최대 음량 |
| `distortion` | `{ drive }` | 선택. 오실레이터 합에 tanh WaveShaper, 필터 앞 |
| `fm` | `{ ratio, index, decay }` | 선택. 사인 모듈레이터, 깊이 = index x 모듈레이터 Hz가 decay초 동안 0으로 |
| `vibrato` | `{ rate, depth, delay }` | 선택. LFO가 detune을 ±depth센트로, delay초 뒤 시작 |
| `hold` | 초 | 선택. 게이트의 하한 |
| `filterLfo` | `{ rate, depth }` | 선택. 사인 LFO가 메인 필터 주파수에 ±depth Hz를 rate Hz로 더한다(`from`/`sweep` 스윕 위에 얹힌다). 노트 시작에 위상 0. 메인 필터가 있어야 하고 depth < `filter.freq`로 정한다. 1박에 한 번 = 130 / 60 = 약 2.17Hz, 1칸에 한 번 = 약 4.33Hz |
| `spread` | 0 ~ 1 | 선택. 오실레이터마다 StereoPanner를 두어 좌우로 벌린다(첫 오실레이터 -spread, 마지막 +spread, 사이는 고르게). 기존 프리셋에는 없다 |
| `formants` | `[{ freq, Q, gain }]` | 선택. 있으면 메인 필터 대신 오실레이터 합이 병렬 밴드패스들을 지나 합쳐진다(보컬 모음). `filter`와 같이 있으면 `formants`가 우선하고 `filterLfo`는 쓰지 않는다. 자체 필터가 없는 `noise`도 포먼트 밴드패스를 지난다(숨소리) |
| `tremolo` | `{ beats, depth, stereo }` | 선택. 노트 게인을 사인 LFO로 1 - depth ~ 1 사이에서 흔든다. 주기는 beats박(템포를 따른다). 위상은 루프 머리 기준(노트 시작 t에서 (t - 루프 머리) / 주기의 소수 부분, PeriodicWave로 준다)이라 같은 칸의 노트가 루프마다 같다. stereo면 좌우를 반대 위상으로(오토팬) |

게이트 = max(노트 길이 x 1칸(스윙 반영), attack + decay, hold). 게이트 끝에서 release 동안 사라진다. 프리셋 하나의 노트 피크는 마스터 전 0.95 이하로 맞춘다(기존 `sub_bass`만 1.06이며 호환성 때문에 그대로 둔다).

## 5. 소리 경로

- 노트 → 유물 체인: 볼륨 → 사이드체인 덕킹 게인 → (저음 깎기 하이패스) → (고음 깎기 로우패스) → (필터 스윕 로우패스) → (테이프: tanh 포화 → 흔들림 지연 → 로우패스) → (로파이: 계단 WaveShaper → 로우패스) → (코러스: 마른 소리 + 좌우 지연 → ChannelMerger) → (팬) → 마스터 입력, 그리고 팬 앞(코러스를 지난 소리)에서 리버브·홀·딜레이 센드. 필터 스윕은 사이클 안 루프마다 `sweepAt(chain, relic, t, loopIdx)`가 그 루프 구간의 램프를 건다(실시간 재생은 칸 0 예약 때, WAV는 뒤 자리에도 걸어 접은 꼬리가 같은 필터를 지난다). 코러스·테이프 LFO는 `startSyncedLfo`로 루프 머리(재생 시작 시각 또는 0)에서 위상 0이 되게 시작한다(재생 중에 체인이 생기면 다음 주기 머리부터 흔든다). 값이 0이면 그 노드를 만들지 않아 이전과 소리가 같다. 실시간 재생은 `chainKey`(로파이 값, 필터·센드·팬·필터 스윕·코러스·테이프·홀 유무)가 바뀌면 체인을 새로 만들고, 필터 주파수·센드 양·팬·코러스 양·테이프 값은 바로 바꾼다.
- 마스터: 입력 게인 0.6 → 압축기 → 리미터. 리버브(감쇠 노이즈 임펄스 컨볼버)와 딜레이(피드백 경로 로우패스) 버스 출력은 입력 게인에 합친다(압축기·리미터 앞). 홀 리버브 버스(`makeHall`: 컨볼버 → 하이패스 250Hz → 로우패스 6000Hz)는 hallSend가 있는 체인이 생길 때 `bus.ensureHall()`로 만들고 같은 곳에 합친다. 딜레이 시간은 `delaySeconds()`이고, 재생 중 템포·딜레이 음표를 바꾸면 `Player.syncDelay`가 맞춘다(최대 시간을 넘으면 버스를 새로 만들고 다시 재생).
- 데모 드럼: 드럼 볼륨 게인 → 마스터 입력. 덕킹·로파이·센드를 거치지 않는다. 칸마다 `drumHits`(킥·스네어 소리)와 `pumpsAt`(덕킹 여부)을 본다.
- 재생 스케줄러: 25ms마다 AudioContext 시간으로 0.15초(탭이 가려지면 1.5초) 앞까지 예약한다. 노트 시각은 `시작 시각 + stepTime(재생 시작부터 센 칸 번호)`로 매번 계산해 오차가 쌓이지 않는다. 사이클 안 루프 번호 = floor(칸 번호 / 칸 수) % cycleLoops이고, 등장 루프가 꺼진 유물은 그 루프의 노트를 예약하지 않는다(`Player.stats.loops`에 루프별 번호를 남긴다).
- WAV(`renderLoop`): ① 반복 단위(한 루프, 또는 '한 사이클'이면 루프 x cycleLoops) 노트를 압축기 앞까지 '자리' 여러 개 길이로 렌더(자리 수 = 홀이 없으면 2, 있으면 ceil((단위 + 홀 프리딜레이 + 4초 + 0.1) / 단위). 사이드체인 덕킹·필터 스윕은 모든 자리에 건다) → ② 뒤 자리들을 모두 첫 자리에 접어 더함(자리 2개면 이전과 같다) → ③ 그 한 바퀴를 두 번 반복 재생하며 압축기·리미터를 거쳐 두 번째 바퀴를 쓴다. 44.1kHz 16비트 스테레오, 정확히 한 바퀴(`loopSeconds()`, 130BPM이면 약 7.385초, 샘플 수는 반올림), 반복해도 이음매가 없다. 체크한 유물마다 1개 + 체크한 유물 전부를 합친 믹스 1개. 'WAV에 데모 드럼 포함'이면 드럼 소리도 넣고, 사이드체인은 체크와 상관없이 펌핑 기준을 따른다.

## 6. 설계서 양식 (`relic-beats-YYYYMMDD-HHMMSS.md`)

맨 아래 JSON 코드블록이 원본이다. 위의 표와 글은 JSON에서 만든 것이고, 둘이 다르면 JSON을 따른다. 툴의 불러오기도 JSON만 읽는다.

### 6-1. 구성 (툴이 내보내는 순서)

1. `# 유물 비트 설계서`와 한 줄 소개.
2. `## 읽는 법`: 시간 기준(템포, 격자, 칸 시간), 칸 번호, 음 표기, 세기, 노트 길이, 스케일, 스윙, 믹스 설정 상수, 스케일(키·행 수), 유물 설정, 데모 드럼은 데이터에 없음, JSON이 원본, 게임 반영 시 주의, 선택 파라미터.
3. `## 요약`: `| 유물 | 악기 | 음높이 범위 | 노트 수 | 특징 |` 표. 특징은 자동 문장이다(칸 밀도 빽빽함/보통/성김, 정박/엇박, 음 종류와 폭, 화음 있음, 강약 있음, 긴 노트 있음, 롤 있음, 믹스 설정 있음, 유물 설정 있음). 믹스 바에 든 유물이 있으면 `믹스 바: 1번 이름 (100%) …` 한 줄.
4. 유물마다 `## 유물 이름`: 악기(이름, id, 음높이 악기/타악, 행 0 옥타브), 볼륨(믹스 칸이면 칸 번호와 칸 볼륨), 노트 수, 믹스 설정 한 줄(하나라도 0이 아닐 때만: `사이드체인 N%, 리버브 센드 N%, 딜레이 센드 N%, 로파이 N%, 저음 깎기 N% (Hz), 고음 깎기 N% (Hz)`, Hz는 0이 아닐 때만), 유물 설정 한 줄(스윙·옥타브·팬·필터 스윕 중 하나라도 있을 때만), 합성 파라미터 목록, 박 단위 표, 한 줄 패턴.
5. `## 데이터 (JSON)`: 필드 설명 한 줄과 ```json 코드블록.

### 6-2. 노트 표기 (박 단위 표와 한 줄 패턴)

| 표기 | 뜻 |
|---|---|
| `C4` | 음높이 노트(과학적 음이름, C4 = MIDI 60, 샵 표기) |
| `X` | 타악 노트 |
| `-` | 쉼 |
| `C4+G4` | 같은 칸의 여러 음(화음) |
| `@m`, `@w` | 세기 중(0.55 이상 0.85 미만), 약(0.55 미만). 강은 표기 없음. 타악은 `X@m` |
| `C3*4` | 시작 칸에서 4칸 이어지는 노트(길이 1이면 생략) |
| `X/3` | 롤: 그 칸에서 3번 나눠 친다(1이면 생략). 롤 노트는 길이를 쓰지 않는다 |
| `=` | 앞에서 시작한 긴 노트가 이어지는 칸(그 칸에 시작하는 노트가 없을 때) |

- 박 단위 표: 1박 = 4분음표 기준 1~16행. 8분 격자 `| 박 | .0 | .5 |`(`.0`은 칸 2(박-1), `.5`는 칸 2(박-1)+1), 16분 격자 `| 박 | .0 | .25 | .5 | .75 |`(칸 4(박-1) ~ 4(박-1)+3).
- 한 줄 패턴: 코드블록 안에 `1.0:C4 1.5:- 2.0:E4*2@m 2.5:= …` 칸 수만큼(32개 또는 64개) 토큰. 16분 격자는 `1.0 1.25 1.5 1.75 2.0 …`.
- 순서: 음, 길이, 롤, 세기 (예: `C3*4@m`, `C3/2@m`, `X/3@w`).

### 6-4. 불러오기 규칙

- JSON 코드블록(```json)만 읽는다. 여러 개면 마지막 블록이다. 표·글은 무시한다.
- 스키마 이름이 다르거나 버전이 v1이 아니면, 스케일·프리셋 id를 모르거나 `step`·`row`가 범위 밖이면 이유를 알리고 불러오지 않는다.
- 새 항목은 범위를 벗어나면 범위 안으로 맞추고(예: `sidechain` 3 → 1, `swing` 2 → 0.5), 모르는 필드는 무시한다. `length`는 루프 끝까지로 자르고 같은 행에서 겹치면 다음 노트 직전까지로 줄인다.
- 이름이 같은 유물은 덮어쓴다. 파일 내용이 곧 그 유물이라 파일에 없는 새 항목은 기본값으로 돌아간다. 없는 이름은 새 유물로 추가한다. 목록에만 있는 유물과 믹스 바는 그대로다.
- 파일의 스케일, 키(없으면 C), 행 수(없으면 8), 스윙(없으면 0), 템포(없으면 130), 격자(없으면 8), 딜레이 음표(없으면 점4분)를 툴 전체에 적용한다. 행 수가 15 -> 8로 바뀌면 파일에 없는 유물의 행 8 이상 노트를 지운다(확인 창에 개수를 알린다). 격자가 바뀌면 파일에 없는 유물의 노트를 같은 시각으로 옮긴다(16 → 8이면 홀수 칸 노트는 지운다). 덮어쓰기·스케일·키·행 수·스윙·템포·격자·딜레이 변경이 있으면 확인 창에 알리고 취소할 수 있다.

## 7. Claude가 설계서를 직접 쓸 때

- JSON을 먼저 정하고, 박 단위 표·한 줄 패턴·요약 표·믹스 설정 줄은 JSON과 정확히 맞게 쓴다. 가능하면 툴에 불러온 뒤 '설계서 내보내기'로 다시 만들어 표를 JSON에서 생성한다.
- `row`가 실제 음을 정한다. `midi`·`pitch`는 그 스케일과 프리셋 옥타브로 계산한 값을 적는다(4-4의 식). 스케일을 바꾸면 같은 `row`가 다른 음이 된다.
- 기본값인 새 항목은 쓰지 않는다. 타악 노트에는 `length`를 쓰지 않는다. 같은 행의 노트가 길이 때문에 겹치지 않게 한다.
- 데모 드럼과 바이닐 노이즈는 데이터에 없다. 장르 의도(권장 데모 드럼, 코드 진행 등)는 제목 아래 인용문(`>`)으로 적어도 된다. 불러오기는 무시한다.
- 사이드체인은 4분 정박 킥 기준으로 설계한다(툴이 내보내는 읽는 법에도 그렇게 적힌다). 하우스·일렉트로닉 팝은 `bpm`·`grid`를 최상위에 적는다(예: 125, 16).
- 파일 이름은 `relic-beats-장르-버전.md`처럼 내용을 알 수 있게 짓고 이 폴더에 둔다(툴이 내보낸 원본 이름은 `relic-beats-YYYYMMDD-HHMMSS.md`).

## 8. 게임에 옮길 때 주의 (폐기됨, 기록용)

유물-BGM 연동이 폐기되어 이 절은 적용하지 않는다. 연동을 다시 시작할 때만 참고한다.

- 툴은 130BPM이고 게임 링 박자는 0.3초라 템포가 다르다. 게임에 넣을 때 템포를 맞출지, 칸을 게임 박 격자로 옮길지, 루프가 게임의 무엇에 맞춰 시작하는지는 게임 연동 작업에서 정한다.
- 킥·스네어는 게임에서 무기가 낸다. 사이드체인은 데모 드럼 킥이 아니라 무기 킥 시각에 맞춰 눌러야 한다.
- 볼륨(`volume` x `mixVolume`)은 상대값이다. 합성 파라미터는 Web Audio 기준(오실레이터 파형, BiquadFilter, 게인 엔벨로프, WaveShaper, Convolver, Delay)이라 같은 엔진이면 그대로 옮길 수 있다.
- 유물은 최대 5개(믹스 바 5칸 = 게임 유물 소지 상한)가 동시에 울린다는 전제로 만든다.

## 9. 툴을 고칠 때

### 9-1. 호환성 규칙

- 스키마 이름 `4bit-prototype-relic-beat-tool/v1`을 바꾸지 않는다. 새 필드는 선택 항목으로 넣고, 기본값이면 내보내지 않고, 없으면 기본값으로 읽는다. 값이 범위를 벗어나면 맞추고, 모르는 필드는 무시한다.
- 기존 프리셋의 id·이름·파라미터·옥타브를 바꾸지 않는다. 새 프리셋은 뒤에 붙이고 `category`로 묶는다.
- 새 기능이 기본값이면 소리가 이전과 같아야 한다. 기본값일 때 노드를 만들지 않는 식으로 구현한다.
- localStorage에 저장된 이전 작업이 열려야 한다(`loadState`가 없는 항목을 채운다).
- 툴 설명은 프로젝트 루트 `README.md`의 '유물 비트 메이커' 절에도 있다. 기능을 바꾸면 그 절과 이 문서를 함께 고친다. 루트 `CLAUDE.md`의 relic-beat-tool 항목은 한 줄 요약만 둔다.

### 9-3. 알려진 함정

- **시각 계산:** 노트 시각은 `g x stepSeconds()`처럼 곱셈 하나로 계산한다. `loopSeconds() + s x stepSeconds()`처럼 나눠 더하면 반올림으로 샘플이 1개씩 어긋나 기준 렌더와 달라진다. 칸 시간도 `30 / bpm`(16분은 `15 / bpm`)처럼 나눗셈 한 번으로 만든다.
- **딜레이 최대 시간:** `createDelay(최대 시간)`의 최대 시간이 다르면 같은 지연이어도 렌더가 아주 조금(구간 RMS 상대 약 5e-5) 달라진다. 그래서 딜레이가 1초 이하면 이전처럼 최대 1초로 만들고, 넘을 때만 `DELAY_MAX_SECONDS`를 쓴다.
- **loadState와 전역 state:** `loadState`가 도는 동안은 전역 `state`가 아직 없다. 그 안에서 `gridSteps()`처럼 `state`를 읽는 기본 인자를 쓰면 오류가 나서 저장 상태를 잃으므로 칸 수를 인자로 넘긴다.
- **엔벨로프:** 디케이 끝과 게이트 끝은 한 번만 계산해 게이트 끝이 디케이 끝보다 앞서지 않게 한다. 앞서면 감쇠 램프가 무시되고 노트가 최대 음량으로 남는다.
- **주파수 자동화:** 음높이 슬라이드·FM·비브라토처럼 주파수가 움직이는 오실레이터는 브라우저가 렌더 시각마다 위상을 조금씩 다르게 만든다(일정한 주파수는 같다). 같은 노트도 시각이 다르면 파형이 다르므로, 이런 프리셋은 샘플 단위 비교 대신 RMS로 보고, 루프 이음매는 꼬리를 접는 `renderLoop` 방식으로 맞춘다.
- **노이즈:** 노이즈 버퍼는 컨텍스트마다 `Math.random`으로 한 번 만든다. 렌더를 비교할 때는 `Math.random`을 시드 고정 함수로 바꿔 렌더한다. 리버브 임펄스는 자체 시드라 영향이 없다.
- **리버브 렌더 흔들림:** 브라우저의 컨볼버(리버브)는 긴 임펄스의 뒷부분을 별도 스레드에서 처리해, 같은 코드로 같은 설계서를 렌더해도 `reverbSend`가 있으면 결과가 렌더마다 조금 달라진다(샘플 최대 차이 약 6e-3, 50ms 구간 RMS 상대 약 7e-4). 리버브를 끄면 1e-5 이하로 같다. 기준 비교에서 리버브를 쓰는 파일만 이 정도 차이가 나면 이 흔들림이다. 의심되면 한 번 더 렌더하거나 `reverbSend`를 0으로 바꿔 비교한다.
- **LFO 주기와 이음매:** 시간에 따라 움직이는 것(코러스·테이프 LFO, 트레몰로, 필터 스윕)은 한 바퀴(또는 사이클)에 정수 번 돌도록 주기를 템포에서 계산하고(1마디·2박·beats박) 위상을 루프 머리에 맞춘다. Hz를 고정값으로 두면 템포에 따라 WAV 이음매에서 위상이 튄다. 기존 `wobble_bass`의 `filterLfo`는 프리셋 고정값(130/60Hz)이라 이 규칙 밖이다.
- **홀 꼬리 접기:** 홀 꼬리(최대 노트 끝 + 4.03초)는 빠른 템포의 한 바퀴보다 길 수 있어 한 번 접기로 모자라다. `renderLoop`는 자리 수를 꼬리 길이에서 계산해 모두 접는다. 홀이 없으면 자리 2개라 이전 렌더와 같다.
- **피크:** 5층을 모두 150%로 올린 극단적인 믹스는 피크가 0.96~0.99까지 간다(1.0은 넘지 않는다). 리미터 값을 바꾸면 기존 소리가 바뀌므로 함부로 바꾸지 않는다.

### 9-4. 검증 방법

- 동작 확인은 내장 브라우저로 한다. 내장 브라우저는 file:// 페이지를 정적 스냅샷으로만 열어 스크립트가 돌지 않으므로, 임시 로컬 서버(`.claude/launch.json`, 루트를 `relic-beat-tool/`로)를 띄워 확인하고 끝나면 `.claude/`를 지운다. 이 PC에는 `npx`가 없으므로 PowerShell `HttpListener` 스크립트로 띄우고, 스크립트는 한글이 없는 경로(예: `.claude/serve.ps1`)에 둔다(한글 경로는 `-File` 인자가 깨진다). file:// 실행은 사용자에게 직접 확인을 부탁한다.
- **기준 렌더:** 이 폴더의 `relic-beats-*.md`(슬롯 모드 파일 `relic-beats-slot-*.md`처럼 JSON에 `mode: "slot"`이 있는 것은 빼거나 슬롯 렌더로 따로 비교한다)를 `parseDesign`으로 읽어 `renderLoop`로 렌더하고(`Math.random` 시드 고정), 50ms 구간 RMS와 유물별 RMS를 기준값으로 저장한다. 수정한 뒤 같은 방법으로 렌더해 상대 오차로 비교한다(같은 코드를 다시 돌려도 1e-6 정도 차이가 난다). 수정 전 코드를 스크래치패드에 복사해 다른 포트로 띄우면 언제든 비교할 수 있다.
- **노트 하나:** `OfflineAudioContext`에 `scheduleNote(ctx, ctx.destination, preset, midi, t)`로 렌더해 무음 여부, NaN, 피크(0.95 이하)를 본다. 음높이 악기는 스케일 11종 x 15행을 모두 돈다(키·옥타브 이동 극단값에서 MIDI 0~127도 본다).
- **박자:** `Player.stats`(`late` = 늦게 예약된 노트 수, `firstTimes` = 루프별 첫 칸 시각)로 루프를 여러 번 돌려 늦은 예약 0개, 루프 간격 = `loopSeconds()`를 확인한다(8분/16분 격자 x 여러 템포). 예약 시각은 `scheduleNote`를 감싸 기록하면 볼 수 있다(데모 드럼 칸 위치 확인에도 쓴다).
- **이음매:** 내보낸 루프의 끝 샘플 → 첫 샘플 변화를 평소 샘플 간 변화와 비교한다. 소리가 큰 구간에서는 1차 변화만으로는 판단이 어려우므로, 이음매의 2차 차분 |x0 - 2x(N-1) + x(N-2)|이 루프 전체 2차 차분의 99% 지점보다 작은지 본다(코러스·홀·테이프·트레몰로·사이클은 100·124·180BPM과 8분·16분 격자에서).
- **화면 조작:** 편집기 칸에 `MouseEvent`(mousedown/mouseover, `shiftKey`, `button: 2`, 오른쪽 끝 `clientX`)를 보내 확인한다. 다운로드는 `downloadBlob`을 바꿔 가로채 내용만 본다(실제 파일을 내려받지 않는다).
- 소리의 좋고 나쁨은 코드로 판단할 수 없다. 사용자가 들어볼 수 있게 어떤 유물을 어떤 값으로 들으면 되는지 짧게 알려 준다.

## 10. 슬롯 악기 모드

`request-slot-mode.md`로 더한 두 번째 작업 방식이다. 믹스 바 5칸(슬롯)이 악기를 정하고, 유물은 리듬과 음 높낮이(코드 기준 단계)만 정한다. 어떤 5개가 모여도 악기·음역·쌓이는 순서가 고정이라 베이스 없음·중음 몰림·화음 충돌 같은 조합 문제가 원천적으로 줄어든다. 쌓이는 순서가 곧 곡의 형식이다.

### 10-1. 상태와 저장

- `state.mode`: `'relic'`(기본) / `'slot'`. 재생 중에 바꾸면 재생을 멈춘다(`setMode`).
- `state.relics`·`state.mix`·`state.selectedId`는 **항상 지금 모드의 것**이다. 다른 모드의 것은 `state.inactive`({ relics, mix, selectedId })에 있고, `setMode`가 맞바꾼다. 그래서 유물 악기 모드에 쓰던 함수(목록·편집기·믹스 바·랜덤 믹스·삭제)가 슬롯 모드에서도 그대로 돈다.
- `state.slotMode`: { slots(5칸), progression(마디 4개), selectedSlot(0~4, 오른쪽 패널·패턴 단독 재생이 쓰는 슬롯), focus('relic' 패턴 / 'slot' 슬롯) }.
- 격자를 바꾸면 두 모드의 유물을 함께 옮긴다(`setGrid`, 불러오기). `loadState`는 `slotMode`·`inactive`가 없으면 기본값으로 채운다.

### 10-2. 슬롯 (`SLOT_DEFAULTS`, 딥하우스 v4에서 가져옴)

| 값 | 범위 | 뜻 |
|---|---|---|
| `preset` | 프리셋 id | 슬롯의 악기. 왼쪽 프리셋 목록이 선택한 슬롯의 악기를 고른다(타악 프리셋이면 역할이 타악으로, 타악 역할에 음높이 프리셋이면 리드로 바뀐다) |
| `role` | `chord` / `bass` / `lead` / `pad` / `perc` | 패턴을 실제 음으로 바꾸는 규칙(10-5) |
| `octaveShift` | -2 ~ 2 | 음역 이동. 슬롯 음역 = 프리셋 옥타브 + octaveShift의 C ~ 두 옥타브 위 |
| `voices` | 2 ~ 4 | chord·pad의 화음 음 수 |
| `volume` | 0 ~ 1.5 | 슬롯 볼륨(믹스 칸 볼륨은 쓰지 않는다) |
| 믹스 설정 | 유물 악기 모드와 같음 | `sidechain`, `reverbSend`, `delaySend`, `lofi`, `lowCut`, `highCut`, `chorus`, `hallSend`, `tape`, `pan`, `filterSweep`, `swing` |

| 슬롯 | 악기 | 역할 | 옥타브 | 볼륨 | 믹스·슬롯 설정 |
|---|---|---|---|---|---|
| 1 | `rhodes_trem` | chord (voices 4) | 0 | 0.35 | 사이드체인 0.25, 코러스 0.35, 홀 0.25, 테이프 0.3, 리버브 0.1, 팬 -0.1 |

- 1번이 로즈인 이유: 유물이 1개일 때 혼자 들려도 화음과 리듬이 같이 들려야 한다. 볼륨과 리버브·팬은 요청서 표에 없어 딥하우스 v4 역할표의 값을 그대로 가져왔다.
- `loops`(등장 루프)는 슬롯이 아니라 패턴 유물에 둔다.

### 10-3. 코드 진행 (`progression`)

- 마디 4개 각각 `{ root, size }`. root = 스케일 행(0~6), size = 3(3화음) / 4(7화음) / 5(9화음). 코드는 root 행부터 스케일 위로 3도씩(행 +2씩) size개를 쌓는다(`chordTones`). 마디 안에서 바뀌는 진행은 지원하지 않는다.
- 기본값 `[{0,5},{0,5},{3,5},{3,5}]` = C 자연 단음계 + root 5에서 Fm9, Fm9, B♭m9(툴 표기 A#m9), B♭m9.
- 화면: 위쪽 둘째 줄 '코드 진행'(슬롯 모드에서만 보임). 마디마다 근음(스케일 음 이름)과 3/7/9화음, 코드 이름(`chordName`).

### 10-4. 패턴 유물과 degree

- 패턴 유물: `{ id, name, preset: 'pattern', notes: [{ step, row, length?, velocity?, repeat? }], loops?, checked }`. 내부에서는 degree를 `row`에 담는다(설계서 JSON에서는 `degree`). `'pattern'`은 `PRESET_BY_ID`에만 있는 가상 프리셋(`pattern: true`, 8행 고정)이라 편집기·길이·롤·정리 함수를 그대로 쓴다. 이 프리셋으로는 소리를 내지 않는다.
- degree: 0 = R, 1 = 3, 2 = 5, 3 = 7, 4 = R'(한 옥타브 위), 5 = 3', 6 = 5', 7 = 9'. 그 칸 마디 코드의 `d % 4`번째 음 + `floor(d / 4)` 옥타브, d = 7은 9음. 3화음이면 7음 자리는 근음 한 옥타브 위, 3·7화음이면 9음 자리는 5음 위(`degreeSemi`).
- 편집기: 세로 8행(아래 = R), 행 이름 `R 3 5 7 R' 3' 5' 9'`, 마디 첫 칸에 그 마디 코드의 실제 음 이름을 흐리게 보인다. 코드 찍기 도우미와 행 수 선택은 꺼진다. 찍을 때 들리는 음과 단독 재생은 선택한 슬롯('미리듣기 슬롯')의 악기·역할로 낸다.

### 10-5. 역할별 변환 (`resolvePattern(relic, slot, progression)`)

| 역할 | 변환 |
|---|---|
| `bass` | 단음. degree의 코드 음을 슬롯 음역의 가장 낮은 옥타브에. degree 4~6은 한 옥타브 위. 7음(3)·9음(7)은 근음(아래·위 옥타브)으로 |
| `chord` | 화음. degree 음(lead 규칙)을 맨 위로 두되 [음역 아래 + 12, 음역 위]로 접고, 그 아래 한 옥타브 안에 코드 음 voices-1개(`chordVoicing`). 채움음은 3음·7음·5음·근음에서 고르고 **9음은 쓰지 않는다**(9음은 패턴의 9'로만). 한 화음 안에서 단2도로 붙는 조합은 피한다. 앞 화음이 있으면 음 이동 합이 가장 작은 조합 |
| `lead` | 단음. low + 키 + degree 반음을 슬롯 음역으로 접는다 |
| `pad` | chord와 같은 화음. 길이를 다음 패턴 노트 직전 또는 코드가 바뀌는 칸 직전까지 늘인다 |
| `perc` | 음높이를 버리고 그 칸·세기·롤로 친다. 슬롯 악기가 타악 프리셋이면 역할과 상관없이 이렇게 한다. 음높이 프리셋에 perc 역할이면 근음(lead 규칙)을 친다 |

- **경계 처리:** 노트가 코드가 바뀌는 칸(앞 마디와 코드가 다른 마디 머리)을 넘으면 거기서 끊는다. 그 음이 다음 코드에도 있으면(공통음) 이어 간다. 화음은 음마다 따로 판단한다.
- 결과는 `{ step, midi, length?, velocity?, repeat? }`. `scheduleRelicStep`은 노트에 `midi`가 있으면 그 음을 쓰고, 없으면 지금처럼 `row`로 음을 정한다(유물 악기 모드에는 영향이 없다).

### 10-6. 소리 경로와 재생

- `slotRelic(i, pattern)`이 슬롯 i의 악기·볼륨·믹스 설정과 패턴의 변환 노트·`loops`로 '가상 유물'(id `slot-i`)을 만든다. 재생(`Player.layers`)·WAV(`renderLoop`)·체인(`makeChain`)은 이 가상 유물을 유물 악기 모드 유물과 똑같이 다룬다. 체인은 슬롯마다 하나다.
- 믹스 바 칸 = 슬롯: 위에 슬롯 악기(역할), 아래에 들어간 패턴. 칸을 누르면 그 슬롯을 선택하고 오른쪽 패널이 슬롯 설정(악기·역할·화음 음 수·볼륨·믹스 설정·슬롯 설정)이 된다. 패턴을 누르면 오른쪽이 패턴 설정(미리듣기 슬롯, 등장 루프)이 된다.
- '순서대로 채우기'(슬롯 모드의 랜덤 믹스): 무작위로 고른 패턴을 1번 슬롯부터 채운다.
- '쌓기 재생'(`Player` 모드 `'stack'`): 채운 슬롯을 1 → 1·2 → … 순서로 한 사이클(사이클 1이면 한 루프)씩 늘리고 마지막 단계를 반복한다(`Player.stackStage`). 편집기 제목 옆에 '쌓기 3/5'. `Player.stats.stages`에 루프별 단계를 남긴다. 체인은 처음부터 모든 슬롯에 만들고 단계 밖 슬롯은 노트만 치지 않는다.
- WAV: 채운 슬롯마다 `relic-slot-슬롯번호-유물이름-시각.wav` + `relic-slot-mix-시각.wav`. 'WAV 길이' 설정은 그대로 쓴다.

### 10-7. 설계서 (`relic-beats-slot-장르-버전.md`)

- 스키마 이름은 그대로이고 최상위 `"mode": "slot"`으로 구분한다. 구성: 제목 → 읽는 법(슬롯·코드 진행·degree·역할별 변환·경계 처리·표기) → 슬롯 표 → 코드 진행 표(코드 이름, 코드 음) → 요약 표 → 유물별 상세(노트 수, 등장 루프, '1번 슬롯에 넣으면' 실제 음 한 줄, 박 단위 표, 한 줄 패턴) → JSON.
- 패턴 표기: degree 기호(`R 3 5 7 R' 3' 5' 9'`), 쉼 `-`, 화음 `+`, 길이 `*n`(이어지는 칸 `=`), 롤 `/n`, 세기 `@m`·`@w`.
- JSON 최상위: `schema`, `mode`, `timing`(참고값), `scale`, 선택 `bpm`·`grid`·`root`·`cycleLoops`·`delayNote`·`groove`, `progression`(4개), `slots`(항상 5개: preset, role, voices(chord·pad일 때만), volume, 선택 octaveShift·믹스 설정·swing·pan·filterSweep), `relics`(name, mixSlot(참고값), pattern: [{ step, degree, length?, velocity?, repeat? }], loops?).
- 불러오기: `mode`가 `"slot"`이면 확인 창을 거쳐 툴을 슬롯 모드로 바꾸고 슬롯·코드 진행·전역 설정을 파일 내용으로, 패턴은 이름이 같으면 덮어쓰고 없으면 추가한다(`importSlotDesign`). 믹스 바와 유물 악기 모드 목록은 그대로다. `mode`가 없으면 지금처럼 유물 악기 모드로 읽고, 슬롯 모드에 있었다면 확인을 누를 때 유물 악기 모드로 바꾼다.
- **의도한 비호환:** 슬롯 모드 파일은 `notes`·`preset`이 없어 슬롯 모드를 모르는 이전 툴에서 거부된다.
- 내보내기: 슬롯 모드에서 '설계서 내보내기'는 체크한 패턴 유물과 슬롯·코드 진행을 `relic-beats-slot-시각.md`로 내보낸다.

### 10-8. Claude가 슬롯 모드 설계서를 쓸 때

- 패턴은 리듬 성격(정박·뒷박·당김·성긴 긴음·16분 촘촘·부름/응답)으로 나눠 어떤 5개가 모여도 서로 빈 곳을 채우게 한다. 킥 칸(마디 안 0·4·8·12)을 쓰는 패턴은 17개 중 5개 이하로 둔다.
- 등장 루프는 장식 성격 패턴 2~3개에만 쓴다(뼈대가 늦게 나오면 첫 루프가 빈다).
- m9 코드는 9음과 단3도가 반음이다(Fm9의 G·A♭, B♭m9의 C·D♭). 9'(degree 7)는 패드·코드 슬롯의 3음과 반음으로 겹치기 쉬우므로 예시에서는 쓰지 않았다. 쓰려면 조합 검증으로 충돌을 센다.
- 검증: 17개 중 5개 조합 6188가지 x 조합당 무작위 순서 20가지를 `resolvePattern` 결과로 바꿔 동시에 울리는 음 사이의 단2도 계열(1·13·25반음) 충돌을 센다(장7도 허용). (패턴, 슬롯)별 변환 결과를 먼저 만들어 두면 몇 초에 끝난다.

### 10-9. 함정

- **변환과 경계:** 표·재생·WAV가 모두 `resolvePattern`을 쓰므로 변환 규칙을 바꾸면 세 곳이 같이 바뀐다. 경계 판단은 '앞 마디와 코드가 다른 마디 머리'에서만 한다(같은 코드가 이어지는 마디 경계에서는 끊지 않는다).
- **화음 보이싱 상태:** chord·pad는 패턴 노트를 칸 순서로 훑으며 앞 화음(prev)을 기억한다. 루프 첫 노트는 앞 화음이 없어 3음·7음 우선 규칙으로 정해지므로 루프마다 같은 소리가 난다.
- **상태 맞바꾸기:** 슬롯 모드에서는 `state.relics`가 패턴 유물이다. 유물 악기 모드 전용 코드(설계서 `designData`, 프리셋 적용 등)를 슬롯 모드에서 부르지 않게 `isSlotMode()`로 나눈다.
- **상수 순서:** `SLOT_DEFAULTS`·`DEFAULT_PROGRESSION`·`SLOT_ROLES`는 `let state = loadState() || defaultState()`보다 앞에 있어야 한다(기본 상태를 만들 때 쓴다).
