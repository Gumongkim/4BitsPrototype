# 요청서: 유물 비트 메이커에 '슬롯 악기 모드' 추가

`relic-beat-tool/`에 새 작업 방식인 '슬롯 악기 모드'를 더한다. 이 모드에서는 **믹스 바 5칸(슬롯)이 악기를 정하고, 유물은 리듬과 음 높낮이(코드 기준 단계)만 정한다.** 유물을 얻은 순서대로 슬롯 1 → 5에 들어가고, 들어간 슬롯의 악기로 연주된다. 작업 전에 `relic-beat-tool/CLAUDE.md`를 먼저 읽는다. 용어(칸, 박, 루프, 사이클, 프리셋, 믹스 설정, 유물 설정, 설계서)는 그 문서를 따른다.

## 0. 배경

- 지금 방식(이 문서에서는 '유물 악기 모드')은 유물마다 악기·음·리듬이 모두 정해져 있다. 그래서 어떤 5개가 모이느냐에 따라 베이스가 없거나(딥하우스 v4에서 게임식 추첨 기준 31%), 중음 악기가 몰리고, 화음 충돌을 설계서마다 손으로 막아야 했다.
- 슬롯 악기 모드에서는 악기·음역·쌓이는 순서가 고정이라 이런 조합 문제가 원천적으로 사라진다. 유물의 정체성은 '리듬감과 높낮이'가 된다(예: 에어 드럼 = 16분 당김음으로 위로 튀는 리듬).
- 쌓이는 순서가 곧 곡의 형식이 된다(`mc-style-edm` §5.1a: 층의 등장 순서가 구조다). 유물을 하나 얻을 때마다 곡이 한 층씩 자란다.
- 유물-BGM 연동은 폐기됐다(2026-11-08). 이 모드는 툴 안에서 듣고 설계서로 남기는 기능이다. 게임 코드는 건드리지 않는다.
- 기준 장르는 딥하우스 v4(`relic-beats-deephouse-v4.md`, `deephouse-v4-roles.md`)다. 사용자가 지금까지 중 가장 좋다고 한 설계다. 슬롯 기본 악기를 거기서 가져온다.

## 1. 범위

| 단계 | 내용 |
|---|---|
| 1 | 모드 전환, 슬롯 설정(악기·역할·음역·믹스 설정), 코드 진행, 유물 패턴 데이터와 편집기, 역할별 변환(패턴 → 실제 음), 재생·WAV |
| 2 | 설계서 내보내기·불러오기(슬롯 모드 파일), '쌓기 미리듣기'(슬롯 1개 → 5개 순서로 듣기) |
| 3 | 슬롯 모드 예시 설계서 1개(딥하우스, 패턴 17개) 작성과 조합 검증 |

세 단계 모두 이번 요청의 범위다. 단계마다 6장 검증을 하고 다음으로 간다.

**공통 규칙 (지침서 9-1 호환성):**
- **유물 악기 모드는 그대로 둔다.** 기본 모드다. 모드를 바꾸지 않으면 화면·저장·소리·설계서가 지금과 같아야 한다. 기존 `relic-beats-*.md` 전부의 렌더가 같아야 한다.
- 슬롯 모드의 유물 목록·슬롯 설정·코드 진행은 **유물 악기 모드의 유물 목록과 따로 저장**한다(`state.slotMode = { slots, progression, relics, mix, … }`). 모드를 오가도 서로의 작업이 지워지지 않는다.
- 전역 설정(템포, 격자, 키, 스케일, 스윙, 사이클, 딜레이, 데모 드럼, 펌핑 기준)은 두 모드가 같이 쓴다.
- 스키마 이름 `4bit-prototype-relic-beat-tool/v1`은 바꾸지 않는다. 슬롯 모드 설계서는 최상위 `mode: "slot"`으로 구분한다(4장).
- 소리 경로(`makeChain`, 버스, 이펙트, `renderLoop`)는 새로 만들지 않고 그대로 쓴다. 슬롯이 '악기와 믹스 설정을 가진 가상의 유물'처럼 체인을 만든다.
- localStorage의 이전 상태가 열려야 한다(`loadState`가 `slotMode`가 없으면 기본값으로 채운다).

## 2. 단계 1: 모드, 슬롯, 코드 진행, 패턴, 변환

### 2-1. 모드 전환

- 위쪽 첫 줄 맨 앞에 '모드' 선택을 둔다: **유물 악기**(기본) / **슬롯 악기**. 재생 중에 바꾸면 재생을 멈춘다.
- 슬롯 악기 모드에서는 왼쪽 유물 목록이 슬롯 모드 유물(패턴) 목록이 된다. 오른쪽 패널은 선택한 대상(패턴 유물 또는 슬롯)의 설정을 보인다.
- 상태: `state.mode`(`'relic'` 기본 / `'slot'`).

### 2-2. 슬롯 설정 (5칸)

믹스 바 5칸이 각자 악기를 갖는다. 칸을 누르면 오른쪽에 그 슬롯 설정이 보인다.

| 값 | 범위 | 뜻 |
|---|---|---|
| `preset` | 프리셋 id | 슬롯의 악기 |
| `role` | `chord` / `bass` / `lead` / `pad` / `perc` | 패턴을 실제 음으로 바꾸는 규칙(2-5) |
| `octaveShift` | -2 ~ 2 | 음역 이동(프리셋 옥타브 기준) |
| `voices` | 2 ~ 4 | `chord`·`pad` 역할의 화음 음 수 |
| `volume` | 0 ~ 1.5 | 슬롯 볼륨 |
| 믹스 설정 | 유물 악기 모드와 같은 항목 전부 | `sidechain`, `reverbSend`, `delaySend`, `lofi`, `lowCut`, `highCut`, `chorus`, `hallSend`, `tape`, `pan`, `filterSweep`, `swing` |

- 슬롯에 들어간 유물은 그 슬롯의 악기·역할·믹스 설정으로 연주된다. 유물 자체에는 악기가 없다.
- `loops`(등장 루프)는 패턴 유물 쪽에 둔다(유물의 성격이라서).
- 기본 슬롯(딥하우스 v4에서 가져옴, 상수 `SLOT_DEFAULTS`):

| 슬롯 | 악기 | 역할 | 옥타브 | 주요 믹스 설정 |
|---|---|---|---|---|
| 1 | `rhodes_trem` 로즈 트레몰로 | `chord` (voices 4) | 0 | 사이드체인 0.25, 코러스 0.35, 홀 0.25, 테이프 0.3 |
| 2 | `deep_bass` 딥 베이스 | `bass` | -1 | 사이드체인 0.35, 테이프 0.2 |
| 3 | `shaker` 셰이커 | `perc` | - | 스윙 0.25 |
| 4 | `vocal_oo` 보컬 챱 (우) | `lead` | 0 | 딜레이 0.2, 홀 0.3, 테이프 0.25 |
| 5 | `vocal_pad` 보컬 패드 (우) | `pad` (voices 3) | 0 | 사이드체인 0.4, 홀 0.45, 코러스 0.3, 필터 스윕 0.7 ↔ 0.15 `upDown` |

- 1번 슬롯이 로즈인 이유: 유물이 1개일 때 혼자 들려도 화음과 리듬이 같이 들려야 한다. 베이스가 첫 슬롯이면 1개일 때 너무 비어 들린다.

### 2-3. 코드 진행

- 슬롯 모드 전역 설정에 `progression`을 둔다: 마디별 코드 목록. 루프의 마디 수(4마디)만큼 `{ root, size }`를 둔다.
  - `root`: 스케일 행(0~6, 스케일 첫 음 기준 몇 번째 음). 키(`root` 전역 값)와 스케일이 실제 음을 정한다.
  - `size`: 3(3화음), 4(7화음), 5(9화음). 코드는 `root` 행부터 **스케일 위로 3도씩**(행 +2씩) `size`개를 쌓는다. 지금 '코드 찍기 도우미'(`CHORD_SHAPES`)와 같은 방식이다.
- 화면: 위쪽 둘째 줄에 '코드' 4칸(마디마다 근음 선택 + 3/7/9 선택). 근음 선택지는 스케일 음 이름으로 보인다(F 단조면 F, G, A♭ …).
- 기본값: `[{ root: 0, size: 5 }, { root: 0, size: 5 }, { root: 3, size: 5 }, { root: 3, size: 5 }]`. 딥하우스 v4와 같은 키·스케일(C 자연 단음계 + root 5 = F 단조)이면 Fm9, Fm9, B♭m9, B♭m9다.
- 코드 경계에서 끊기는 규칙은 2-5의 '경계 처리'를 따른다.

### 2-4. 패턴 유물 (데이터와 편집기)

- 슬롯 모드 유물은 `{ id, name, pattern: [...], loops?, checked }`다. 악기·믹스 설정이 없다.
- 패턴 노트: `{ step, degree, length?, velocity?, repeat? }`
  - `step`: 칸 번호(격자에 따라 0~31 / 0~63).
  - `degree`: **코드 기준 단계**. 0 = 근음, 1 = 3음, 2 = 5음, 3 = 7음, 4 = 근음(한 옥타브 위), 5 = 3음(위), 6 = 5음(위), 7 = 9음(위). 즉 `degree` d는 그 칸의 코드 음 목록(3도씩 쌓은 음)의 `d % 4`번째 음 + `floor(d / 4)` 옥타브이고, d = 7은 9음이다. 코드가 3화음(size 3)이면 7음 자리는 근음 한 옥타브 위로, 9음 자리는 5음 위로 바꾼다(없는 음을 내지 않는다).
  - `length`, `velocity`, `repeat`: 유물 악기 모드와 같다.
- 편집기: 세로 8행 = degree 0~7(아래 = 근음). 행 이름은 'R, 3, 5, 7, R', 3', 5', 9''. 마디마다 그 마디 코드의 실제 음 이름을 행 옆에 흐리게 보인다. 찍기·지우기·세기·길이·롤 조작은 지금 편집기와 같다. '코드 찍기 도우미'는 이 모드에서 꺼진다.
- 패턴 유물을 단독 재생하면 **지금 선택된 슬롯**의 악기로 들린다. 오른쪽 패널에 '미리듣기 슬롯' 선택(1~5)을 둔다.

### 2-5. 역할별 변환 (패턴 → 실제 음)

슬롯에 들어간 패턴의 노트마다, 그 칸의 코드와 슬롯 역할로 실제 MIDI 음(들)을 만든다. 노트 시각·세기·롤은 패턴 그대로다.

| 역할 | 변환 |
|---|---|
| `bass` | 단음. `degree`의 코드 음을 슬롯 음역의 가장 낮은 옥타브에 둔다. 위 옥타브 단계(`degree` 4~6)는 한 옥타브 위. 7음(`degree` 3)과 9음(`degree` 7)은 베이스에서 탁하므로 근음(각각 아래·위 옥타브)으로 바꾼다 |
| `chord` | 화음. `degree`의 코드 음을 **맨 위 음**으로 두고, 그 아래에 코드 음을 `voices - 1`개 채운다(맨 위에서 한 옥타브 안, 아래로). 앞 노트의 화음과 가까운 자리를 고른다(성부 진행: 두 화음의 음 이동 합이 가장 작은 자리) |
| `lead` | 단음. `degree`의 코드 음을 슬롯 음역(프리셋 옥타브 + `octaveShift`)에 둔다 |
| `pad` | `chord`와 같은 화음이다. 단, 길이를 **다음 패턴 노트 직전 또는 코드가 바뀌는 칸 직전까지** 늘인다(긴 음) |
| `perc` | 음높이는 버리고 타악 프리셋을 그 칸·세기·롤로 친다 |

- **경계 처리:** 노트가 코드가 바뀌는 칸을 넘으면, 넘는 지점에서 끊는다. 단, 그 음이 다음 코드에도 있는 음(공통음)이면 끊지 않고 이어 간다. 화음이면 음마다 따로 판단한다.
- **음역 제한:** 결과 MIDI가 슬롯 음역(프리셋 옥타브 + `octaveShift`의 C ~ 두 옥타브 위)을 벗어나면 옥타브 단위로 안으로 접는다.
- 변환은 재생·WAV·설계서 표가 모두 같은 함수(`resolvePattern(relic, slot, progression)`)를 쓴다. 결과는 유물 악기 모드의 노트 형식(`{ step, midi, length, velocity, repeat }`)으로 내어 `scheduleRelicStep`과 렌더가 그대로 쓰게 한다. 유물 악기 모드 노트는 `row`로 음을 정하므로, 변환 결과용으로 `midi`를 직접 받는 경로를 하나 더한다(유물 악기 모드에는 영향이 없게).

### 2-6. 믹스 바, 재생, WAV

- 믹스 바 칸 = 슬롯. 칸의 + 로 패턴 유물을 넣는다. 칸마다 슬롯 악기 이름이 위에 보이고, 들어간 유물 이름이 아래에 보인다.
- **'순서대로 채우기'**(지금 '랜덤 믹스' 자리, 슬롯 모드에서만): 무작위로 고른 유물을 1번 칸부터 채운다. 게임에서 유물을 얻는 순서를 흉내 낸다.
- 재생·WAV는 지금과 같다(슬롯마다 체인 하나). WAV 파일 이름은 `relic-slot-슬롯번호-유물이름-시각.wav`와 믹스 1개.
- 사이드체인·필터 스윕·등장 루프·사이클은 지금 규칙 그대로다(등장 루프는 패턴 유물의 `loops`).

### 2-7. 완료 기준 (단계 1)

- 모드를 바꾸지 않으면 기존 설계서 전부의 렌더가 수정 전과 같다.
- 변환 단위 확인(코드 Fm9, F 단조):
  - `bass` degree 0 → F, degree 2 → C, degree 3 → F(7음은 근음으로)
  - `chord` voices 4, degree 4 → 맨 위가 F이고 아래 3음이 코드 음
  - `lead` degree 7 → G(9음)
  - `perc` → 타악 1타
- 경계 확인: Fm9 → B♭m9 경계를 넘는 C(공통음) 노트는 이어지고, E♭(B♭m9에 없음) 노트는 경계에서 끊긴다.
- 한 패턴 유물을 슬롯 1~5에 차례로 넣어 렌더하면 슬롯마다 다른 악기·음역으로 들리고, 무음·NaN이 없고 피크가 0.95 이하다.
- 슬롯 모드 믹스 WAV(5칸, 사이클)가 이음매 없이 반복된다.

## 3. 단계 2: 설계서와 쌓기 미리듣기

### 3-1. 슬롯 모드 설계서 (`relic-beats-slot-장르-버전.md`)

- 구성은 지금 설계서와 같은 순서다(제목 → 읽는 법 → 요약 → 항목별 상세 → JSON). 다만:
  - **읽는 법**에 슬롯 모드 설명을 넣는다: 슬롯이 악기, 유물이 패턴, degree 표, 역할별 변환, 경계 처리.
  - **슬롯 표**: 슬롯 번호, 악기, 역할, 옥타브, voices, 믹스 설정.
  - **코드 진행 표**: 마디, 코드 이름(예: Fm9), 실제 음.
  - **유물 상세**: 패턴의 박 단위 표와 한 줄 패턴(음 대신 degree 기호 `R 3 5 7 R' 3' 5' 9'`, 세기·길이·롤 표기는 지금과 같다), 등장 루프. 그리고 **슬롯 1에 넣었을 때의 실제 음** 예시 한 줄.
- JSON (스키마 이름 그대로):

```json
{
  "schema": "4bit-prototype-relic-beat-tool/v1",
  "mode": "slot",
  "bpm": 120, "grid": 16, "root": 5, "cycleLoops": 4, "delayNote": "3/16",
  "scale": { "name": "C 자연 단음계" },
  "progression": [{ "root": 0, "size": 5 }, { "root": 0, "size": 5 }, { "root": 3, "size": 5 }, { "root": 3, "size": 5 }],
  "slots": [
    { "preset": "rhodes_trem", "role": "chord", "voices": 4, "volume": 0.35, "sidechain": 0.25, "chorus": 0.35, "hallSend": 0.25, "tape": 0.3 }
  ],
  "relics": [
    { "name": "에어 드럼", "pattern": [{ "step": 2, "degree": 0, "length": 3 }, { "step": 10, "degree": 4, "velocity": 0.7 }], "loops": [true, true, true, true] }
  ]
}
```

- 선택 항목은 지금 규칙대로 기본값이면 생략한다. `slots`는 항상 5개를 쓴다.
- **불러오기:** `mode`가 `"slot"`이면 슬롯 모드로 읽는다. 슬롯 모드 유물 목록·슬롯·진행을 파일 내용으로 바꾸고(이름이 같은 패턴 유물은 덮어쓰기, 지금 규칙과 같음), 툴을 슬롯 모드로 바꾼다. 확인 창에 알린다.
- `mode`가 없으면 지금과 똑같이 유물 악기 모드로 읽는다.
- 슬롯 모드 파일을 이전 툴로 열면 `notes`·`preset`이 없어 거부된다. 이것을 지침서에 적는다(의도한 비호환).
- 유물 악기 모드에서 '설계서 내보내기'는 지금과 같다. 슬롯 모드에서는 체크한 패턴 유물과 슬롯·진행을 내보낸다.

### 3-2. 쌓기 미리듣기

- 슬롯 모드 믹스 바 옆에 '쌓기 재생' 버튼을 둔다. 누르면 슬롯 1만 → 1·2 → 1·2·3 → … → 5개 순서로 한 사이클씩(사이클이 1이면 한 루프씩) 늘려 가며 재생하고, 마지막 단계는 반복한다. 지금 단계가 화면에 보인다("쌓기 3/5").
- 게임에서 유물을 하나씩 얻을 때 곡이 어떻게 자라는지 듣는 용도다.

### 3-3. 완료 기준 (단계 2)

- 슬롯 모드 설계서를 내보냈다 불러오면 같은 JSON이 나온다(왕복).
- 슬롯 모드 파일을 불러와도 유물 악기 모드의 유물 목록이 그대로 남는다.
- 쌓기 재생에서 단계가 박 밀림 없이 넘어간다(`Player.stats`의 늦은 예약 0개).

## 4. 단계 3: 예시 설계서 (딥하우스 슬롯 v1)

- 위 기본 슬롯과 진행으로 패턴 유물 17개를 만든다. 파일 이름은 `relic-beats-slot-deephouse-v1.md`.
- 패턴은 **리듬 성격**으로 나눠 어떤 5개가 모여도 서로 빈 곳을 채우게 한다:
  - 정박형(박 머리·킥 칸 위주)
  - 뒷박형(8분 뒷박)
  - 당김형(3-3-2, 16분 a 칸)
  - 성긴 긴음형(마디에 1~2음, 길게)
  - 16분 촘촘형(세기 강약으로 그루브)
  - 부름·응답형(마디 1·3에 몰리거나 2·4에 몰림)
- 각 성격에 3~4개씩 배분하고, 높낮이(degree 윤곽)도 오르는 것·내리는 것·한 음 반복으로 섞는다.
- 등장 루프는 장식 성격의 패턴 2~3개에만 쓴다(딥하우스 v4에서 정한 원칙: 뼈대가 늦게 나오면 첫 루프가 빈다).
- 같은 칸 강한 음 몰림을 줄이기 위해, 킥 칸(0·4·8·12)을 쓰는 패턴은 17개 중 5개 이하로 둔다.
- **검증:**
  - 17개 중 5개를 고르는 모든 조합(6188가지)과 모든 순서(조합당 5! = 120가지 순서 중 무작위 20가지)를 슬롯에 넣어 변환 결과로 단2도 계열(1·13·25반음) 충돌을 센다. 장7도는 허용한다.
  - 조합마다 64칸 중 아무도 치지 않는 칸 수의 평균과 최소를 본다.
  - 무작위 순서 12개를 렌더해 피크(0.95 이하), NaN, 이음매를 본다.
- 결과와 "어떤 순서로 무엇을 들으면 되는지"를 설계서 인용문과 역할표(`slot-deephouse-v1-roles.md`)에 적는다.

## 6. 검증 (지침서 9-4 방법)

1. **기준 렌더:** 수정 **전에** 기존 `relic-beats-*.md` 전부를 렌더해 50ms 구간 RMS를 저장하고, 단계마다 같은지 비교한다(레이어 볼륨은 각 유물 `volume`, 데모 드럼 '없음', `Math.random` 시드 고정).
2. **변환 단위:** 2-7의 확인 항목을 코드로 검사한다(역할 5종 x degree 8종 x 코드 크기 3종, 경계 처리).
3. **노트 하나·피크:** 슬롯 기본 악기 5종으로 모든 degree를 렌더해 무음·NaN·피크(0.95 이하).
4. **이음매·박자:** 슬롯 모드 믹스(루프, 사이클)에서 이음매와 `Player.stats`.
5. **저장:** 이전 버전 localStorage 상태가 열리고, 모드를 오가도 두 모드의 작업이 남는다.
6. **왕복:** 두 모드 모두 내보내기 → 불러오기에서 같은 JSON.
7. **화면:** 패턴 편집기 조작(`MouseEvent`), 슬롯 선택, 순서대로 채우기, 쌓기 재생.
8. 동작 확인은 내장 브라우저로 한다. 임시 로컬 서버(`.claude/launch.json`, PowerShell `HttpListener`, 스크립트는 한글 없는 경로)를 쓰고 끝나면 `.claude/`를 지운다. 긴 렌더(사이클)는 브라우저 스크립트 한 번에 45초를 넘기므로, 백그라운드로 돌리고 결과를 전역 변수에 담아 나눠서 확인한다. file:// 실행은 사용자에게 직접 확인을 부탁한다.
9. 소리의 좋고 나쁨은 코드로 판단할 수 없다. 끝나면 "슬롯 모드에서 예시 설계서를 불러와 쌓기 재생"처럼 무엇을 들으면 되는지 짧게 알려 준다.

## 7. 구현 전에 정할 것 (기본값)

질문 없이 정하면 아래 기본값을 쓰고 답변에 적는다.

- 순서: 단계 1 → 2 → 3. 각 단계 검증이 통과하면 다음으로 간다. 기존 렌더가 달라지면 멈추고 알린다.
- 모드 기본값은 유물 악기. 슬롯 모드 상태는 따로 저장한다.
- 슬롯 기본 악기·역할·믹스 설정은 2-2 표(딥하우스 v4 기준).
- 코드 진행은 마디 단위(4마디)만 지원한다. 마디 안에서 코드가 바뀌는 진행은 이번 범위가 아니다.
