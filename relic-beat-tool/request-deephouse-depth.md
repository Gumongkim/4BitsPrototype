# 요청서: 유물 비트 메이커에 딥하우스의 깊이(공간·질감·긴 흐름) 더하기

`relic-beat-tool/`에서 딥하우스를 레퍼런스 곡에 가깝게 만들 수 있도록 이펙트, 질감, 긴 흐름 기능을 더한다. 작업 전에 `relic-beat-tool/CLAUDE.md`를 먼저 읽는다. 용어(칸, 박, 루프, 프리셋, 믹스 설정, 유물 설정, 설계서)는 그 문서를 따른다.

## 0. 배경

- 지금 툴(130BPM 기본, 템포·16분 격자·키·유물별 스윙·필터 스윕·보컬 챱 등이 있는 상태)로 하우스 v1 설계서(`relic-beats-house-v1.md`)를 만들었다. 조합은 잘 섞이지만, 딥하우스 레퍼런스와 비교하면 세 가지가 모자라다.
  1. **질감:** 딥하우스의 맛은 샘플링한 소울 보컬, 실제 로즈의 트레몰로, 테이프의 흔들림과 포화에서 많이 나온다. 툴은 오디오 파일을 쓰지 않고(지침서 1장 기술 제약), 보컬 챱은 '아' 모음 하나뿐이고, 로즈는 정적인 합성음이다.
  2. **긴 흐름:** 딥하우스는 16~32마디에 걸쳐 필터를 천천히 열고 층을 넣고 뺀다. 툴은 4마디 루프 하나이고, 필터 스윕도 4마디마다 처음으로 돌아간다.
  3. **공간:** 공통 리버브가 하나(1.6초 고정)뿐이고, 코러스 같은 모듈레이션 이펙트가 없다. 딥하우스 패드와 로즈의 넓고 흔들리는 공간을 만들기 어렵다.
- 유물-BGM 연동은 폐기됐다(2026-11-08). 게임 코드는 건드리지 않는다.
- 킥·스네어를 유물 프리셋으로 넣지 않는 정책은 유지한다. 데모 드럼 킥 음색 추가는 미리듣기용이므로 괜찮다.

## 1. 범위와 순서

| 단계 | 내용 | 해결하는 문제 |
|---|---|---|
| 1 | 코러스(유물별), 긴 홀 리버브(두 번째 리버브 버스) | 3. 공간 |
| 2 | 테이프 질감(유물별 포화 + 흔들림), 보컬 모음 프리셋 4종, 로즈 트레몰로 프리셋, 딥 킥(데모 드럼) | 1. 질감 |
| 3 | 사이클(여러 루프에 걸친 흐름): 긴 필터 스윕, 유물별 등장 루프 | 2. 긴 흐름 |

- 효과가 큰 순서라 단계 1부터 한다. 각 단계가 끝날 때마다 6장 검증을 하고, 사용자에게 들어 볼 설정을 알린 뒤 다음 단계로 간다.
- 세 단계 모두 이번 요청의 범위다.

**공통 규칙 (지침서 9-1 호환성):**
- 스키마 이름 `4bit-prototype-relic-beat-tool/v1`을 바꾸지 않는다. 새 필드는 모두 선택 항목이다. 기본값이면 내보내지 않고, 없으면 기본값으로 읽는다. 범위를 벗어나면 맞추고, 모르는 필드는 무시한다.
- 새 기능이 기본값이면 소리가 지금과 같아야 한다. 기본값일 때는 노드를 만들지 않는다. `chainKey`에 새 노드의 유무를 더해 실시간 재생에서 체인을 다시 만든다.
- 기존 프리셋의 id·이름·파라미터·옥타브를 바꾸지 않는다. 새 프리셋은 뒤에 붙이고 `category`로 묶는다.
- localStorage에 저장된 이전 상태가 열려야 한다(`loadState`가 없는 항목을 채운다).
- **이음매 규칙(이번 요청에서 가장 중요):** WAV는 한 바퀴를 이음매 없이 반복해야 한다(`renderLoop`). LFO처럼 시간에 따라 움직이는 것은 **한 바퀴(또는 3장의 사이클)에 정수 번 돌도록** 주기를 템포에서 계산한다. 예: 1박에 한 번, 1마디에 한 번, 루프에 한 번. 그리고 위상을 루프 머리에서 0으로 맞춘다. Hz를 고정값으로 두면 템포에 따라 이음매에서 위상이 튄다.
- 시각은 곱셈 하나로 계산한다(지침서 9-3).

## 2. 단계 1: 공간

### 2-1. 코러스 (유물별)

- 믹스 설정에 `chorus`(0~1)를 더한다. **없으면 0.** 0이 아니면 유물 체인의 로파이 뒤, 팬 앞에 스테레오 코러스를 넣는다.
- 구성: 입력을 왼쪽·오른쪽 두 갈래의 `DelayNode`(기본 지연 15ms)로 보낸다. 사인 LFO 하나가 두 지연 시간을 ±3ms로 반대 위상에 흔든다(왼쪽 +, 오른쪽 -). 젖은 소리(wet) = `chorus` 값, 마른 소리(dry) = 1 - `chorus` x 0.5. 왼쪽 지연은 왼쪽 채널, 오른쪽 지연은 오른쪽 채널로 `ChannelMergerNode`에서 합친다.
- LFO 주기: **1마디에 한 번**(rate = bpm / 240 Hz). 재생과 WAV 모두 루프 머리에서 위상 0이 되게 시작 시각을 맞춘다(실시간 재생은 재생 시작 시각에 LFO를 시작하고, 템포를 바꾸면 체인을 새로 만든다).
- 리버브·딜레이 센드는 지금처럼 팬 앞에서 뽑으므로 코러스를 지난 소리에서 뽑는다. 순서를 지침서 5장에 적는다.
- 화면: 믹스 설정 슬라이더에 '코러스'(0~100%)를 더한다. 설계서 JSON 유물 항목에 선택 필드 `chorus`, 믹스 설정 줄과 읽는 법에 설명을 더한다.

### 2-2. 긴 홀 리버브 (두 번째 리버브 버스)

- 마스터에 두 번째 리버브 버스 '홀'을 더한다. 유물 믹스 설정에 `hallSend`(0~1)를 더한다. **없으면 0.** 어떤 유물도 0보다 크지 않으면 홀 버스를 만들지 않는다(기존 렌더와 같게).
- 임펄스: 기존 리버브처럼 시드 고정 감쇠 노이즈. 길이 `HALL_SECONDS` 4.0초, 감쇠 곡선 지수 `HALL_DECAY_POWER` 2.2, 프리딜레이 `HALL_PREDELAY` 0.03초(임펄스 앞에 무음), 시드 `HALL_SEED`는 기존과 다른 값. 왼쪽·오른쪽 채널을 다른 시드로 만들어 넓게 한다. 임펄스 뒤쪽일수록 어둡게 한다(간단히: 임펄스를 만든 뒤 한 단 로우패스를 시간에 따라 낮아지게 적용하거나, 리턴에 로우패스 `HALL_RETURN_LOWPASS` 6000Hz).
- 리턴에 하이패스 `HALL_RETURN_HIGHPASS` 250Hz를 건다(저음이 꼬리에서 뭉개지지 않게). 기존 리버브 버스는 바꾸지 않는다.
- 홀 출력은 기존 리버브처럼 마스터 입력 게인 앞에서 합친다(압축기·리미터 앞).
- **WAV 꼬리:** `renderLoop`는 루프 끝을 넘은 꼬리를 한 번 접는다. 홀 꼬리(최대 노트 끝 + 4.03초)가 한 바퀴보다 길면 한 번 접기로 모자라다. 가장 빠른 설정(180BPM, 8분 격자)의 루프는 약 5.33초라 4초 꼬리는 들어가지만, **첫 번째 렌더 길이를 바퀴 수 = ceil((loopSeconds + HALL_SECONDS + 0.1) / loopSeconds)로 잡고 바퀴마다 모두 접어 더하도록** `renderLoop`를 일반화한다. 접는 바퀴 수가 1이면 지금과 결과가 같아야 한다.
- 화면: 믹스 설정에 '홀 리버브' 슬라이더. JSON 유물 항목에 선택 필드 `hallSend`. 읽는 법에 두 리버브의 차이(짧은 룸 1.6초 / 긴 홀 4초, 프리딜레이, 리턴 필터)를 적는다.

### 2-3. 완료 기준 (단계 1)

- 새 필드가 없는 기존 설계서 전부의 렌더가 수정 전과 같다(6장 1번).
- `chorus` 1인 유물을 단독 렌더하면 왼쪽·오른쪽 채널이 서로 다르다(상관계수가 1보다 뚜렷하게 작다). `chorus` 0이면 같다(팬 0일 때).
- `chorus`와 `hallSend`를 건 유물의 WAV를 이어 붙였을 때 이음매의 샘플 변화가 평소 변화보다 크지 않다. 100, 124, 180BPM에서 확인한다.
- 홀 꼬리 접기를 일반화한 뒤에도 `hallSend`가 없으면 접는 바퀴 수가 1이고 렌더가 같다.

## 3. 단계 2: 질감

### 3-1. 테이프 질감 (유물별)

- 믹스 설정에 `tape`(0~1)를 더한다. **없으면 0.** 0이 아니면 유물 체인의 고음 깎기·필터 스윕 뒤, 로파이 앞에 넣는다.
  - **포화:** tanh `WaveShaper`. drive = 1 + 4 x `tape`. 출력 레벨은 drive가 올라도 비슷하게 유지되게 보정한다(예: 곡선을 tanh(drive x x) / tanh(drive)로).
  - **흔들림(wow):** 짧은 `DelayNode`(기본 8ms)의 지연 시간을 사인 LFO로 ±(0.6 x `tape`)ms 흔든다. 음높이가 아주 조금 흔들리는 테이프 느낌이다. 주기는 **2박에 한 번**(rate = bpm / 120 Hz), 위상은 루프 머리에서 0.
  - **고음 감쇠:** 로우패스 18000 x (6000 / 18000)^`tape` Hz.
- 화면: 믹스 설정에 '테이프'. JSON 유물 항목에 `tape`. 읽는 법에 세 가지 처리를 적는다.
- `lofi`(비트 감소)와는 다른 기능이다. 지침서에 차이를 한 줄로 적는다(로파이 = 디지털 샘플러, 테이프 = 아날로그 녹음).

### 3-2. 보컬 모음 프리셋 4종

- 기존 `vocal_chop`('아')과 같은 형식(`formants`)으로 모음을 더한다. 소리 합성만 쓴다.
- 초안 (포먼트 주파수는 성인 남녀 평균값을 섞은 출발점. 들어 보고 조정한다):

| id | 이름 | 포먼트 [freq Hz, Q, gain] |
|---|---|---|
| `vocal_oo` | 보컬 챱 (우) | [300, 8, 1], [870, 10, 0.4], [2240, 12, 0.15] |
| `vocal_oh` | 보컬 챱 (오) | [500, 8, 1], [880, 10, 0.6], [2500, 12, 0.2] |
| `vocal_ee` | 보컬 챱 (이) | [300, 8, 1], [2300, 12, 0.6], [3000, 12, 0.3] |
| `vocal_eh` | 보컬 챱 (에) | [530, 8, 1], [1850, 10, 0.6], [2500, 12, 0.3] |

- 오실레이터, 비브라토, 엔벨로프는 `vocal_chop`과 같게 시작한다. 숨소리처럼 노이즈를 조금 더한다(`noise: { gain: 0.08 }`, 포먼트를 함께 지나게 한다. 지금 `noise.filter`가 없으면 노이즈가 메인 필터를 지나는데, `formants`가 있을 때 노이즈가 포먼트를 지나는지 코드를 확인하고 지침서에 적는다).
- 지속음용 프리셋 `vocal_pad`(보컬 패드 '우', 합창 느낌)도 하나 더한다: 오실레이터 3개 디튠 + `spread` 0.7, 어택 0.3초, 서스테인 0.8, 릴리스 0.6초, 포먼트는 `vocal_oo`와 같다.
- 각 프리셋의 피크를 0.95 이하로 `gain`을 맞추고, 조정 값을 답변에 표로 적는다.

### 3-3. 로즈 트레몰로 프리셋

- 프리셋 파라미터에 선택 항목 `tremolo: { beats, depth, stereo }`를 더한다. 노트 게인을 사인 LFO로 1 - depth ~ 1 사이에서 흔든다. 주기는 `beats`박에 한 번(템포를 따른다). `stereo`가 true면 왼쪽·오른쪽을 반대 위상으로 흔든다(오토팬, 서스펜스 로즈 앰프 느낌).
- LFO 위상은 **루프 머리 기준**으로 맞춘다(노트 시작 기준이 아님). 노트 시작 시각에서 루프 머리까지의 박 수로 위상을 계산한다. 그래야 같은 칸의 노트가 루프마다 같은 소리가 되고 이음매가 생기지 않는다.
- 새 프리셋 `rhodes_trem`(로즈 트레몰로, keys, 옥타브 3): `warm_rhodes`와 같은 오실레이터·FM·필터·엔벨로프에 `tremolo: { beats: 0.5, depth: 0.35, stereo: true }`. 기존 `warm_rhodes`는 바꾸지 않는다.

### 3-4. 딥 킥 (데모 드럼)

- `kickSound`에 `deep`을 더한다: 909보다 낮고(시작 120Hz → 45Hz, 0.12초), 길고(디케이 0.45초), 클릭이 거의 없는 둥근 킥. `DEMO_DRUM_SOUNDS`에만 넣고 유물 프리셋 목록에는 넣지 않는다. 설계서에도 넣지 않는다.

### 3-5. 완료 기준 (단계 2)

- 새 필드가 없으면 렌더가 같다. 새 프리셋은 모든 스케일 x 모든 행에서 무음·NaN이 없고 피크가 0.95 이하다.
- `tape` 1인 유물의 WAV 이음매가 깨끗하다(100, 124, 180BPM).
- `rhodes_trem` 노트가 루프의 같은 칸에서 루프마다 같은 소리다(두 바퀴 렌더에서 1바퀴째와 2바퀴째 해당 구간 RMS 상대 오차 1e-3 이하).
- 모음 5종(기존 '아' 포함)을 같은 음으로 렌더했을 때 스펙트럼 첫 두 봉우리가 표의 포먼트 근처에 있다(FFT로 대략 확인).

## 4. 단계 3: 긴 흐름 (사이클)

### 4-1. 사이클 길이

- 전체 설정에 `cycleLoops`(1, 2, 4, 8)를 더한다. **없으면 1**(지금과 같음). 사이클 = 루프 `cycleLoops`번 = 4 x `cycleLoops`마디(최대 32마디). 노트 데이터는 지금처럼 4마디 한 루프만 있다. 사이클은 그 위에 거는 자동화의 길이다.
- 재생은 몇 번째 루프인지(0 ~ cycleLoops-1) 센다. 위치 표시(편집기 위의 흰 선 옆)에 "루프 2/4"처럼 보인다.

### 4-2. 긴 필터 스윕

- `filterSweep`에 선택 항목 `shape`를 더한다: `up`(from → to, **기본**, 지금과 같음), `down`(to → from), `upDown`(사이클 앞 절반 from → to, 뒤 절반 to → from).
- 필터 스윕의 길이를 루프 대신 **사이클 전체**로 한다(`cycleLoops`가 1이면 지금과 같다). 사이클 머리마다 처음 값으로 돌아간다.
- `upDown`은 사이클 끝과 머리의 값이 같으므로 사이클을 반복해도 튀지 않는다. `up`·`down`은 지금처럼 머리에서 값이 돌아간다.

### 4-3. 유물별 등장 루프

- 유물에 선택 필드 `loops`를 더한다: 사이클 안 루프별 켜짐 배열(예: `cycleLoops` 4에서 `[false, true, true, true]` = 두 번째 루프부터 등장). **없으면 모든 루프에서 울린다.** 길이가 `cycleLoops`와 다르면 앞에서부터 쓰고 모자라면 켜짐으로 채운다.
- 꺼진 루프에서는 그 유물의 노트를 예약하지 않는다(꼬리·리버브는 자연스럽게 남는다). 사이드체인 덕킹·필터 스윕은 계속 진행한다.
- 화면: 유물 설정에 사이클 길이만큼의 작은 체크박스 줄('등장 루프'). 믹스 재생에서 층이 들어오고 빠지는 것을 들을 수 있다.
- 딥하우스 쓰임: 사이클 4(16마디)에서 패드는 1루프부터, 베이스는 2루프부터, 보컬은 3루프부터 넣고, 필터 스윕 `upDown`으로 16마디 동안 열었다 닫는다.

### 4-4. WAV 내보내기와 사이클

- 내보내기 옵션 'WAV 길이'를 더한다: '한 루프'(**기본**, 지금과 같음) / '한 사이클'.
- '한 사이클'이면 사이클 전체(루프 x `cycleLoops`)를 렌더하고, 사이클 끝을 넘는 꼬리를 앞으로 접어 사이클 단위로 이음매 없이 반복되게 한다. 유물별 `loops`와 사이클 필터 스윕이 반영된다.
- '한 루프'로 내보낼 때 `cycleLoops`가 1보다 크면, 사이클 자동화는 첫 번째 루프 구간의 값으로 렌더된다고 상태줄에 알린다.

### 4-5. 설계서

- JSON 최상위에 `cycleLoops`(1이 아닐 때만), 유물 항목에 `loops`(있을 때만), `filterSweep.shape`(`up`이 아닐 때만)를 쓴다.
- 유물 상세에 "등장 루프: 2, 3, 4 / 4" 한 줄, 요약 표 특징에 '등장 루프 있음'을 더한다. 읽는 법에 사이클 설명을 더한다.

### 4-6. 완료 기준 (단계 3)

- `cycleLoops`가 없거나 1이면 렌더가 같다.
- `cycleLoops` 4, 유물 `loops` [false, true, true, true]일 때, 사이클 WAV의 첫 루프 구간에 그 유물 소리가 없다(꼬리 제외).
- `upDown` 필터 스윕의 사이클 WAV가 이음매 없이 반복된다.
- 재생 중 사이클 위치가 맞다(`Player.stats`에 루프 번호를 더해 확인한다).

## 6. 검증 (지침서 9-4 방법)

1. **기준 렌더:** 수정 **전에** `relic-beats-*.md` 전부를 `parseDesign`으로 읽어 `renderLoop`로 렌더(`Math.random` 시드 고정, 데모 드럼 '없음', 레이어 볼륨은 각 유물 `volume`)하고 50ms 구간 RMS와 유물별 RMS를 저장한다. 단계마다 수정 후 같은 방법으로 비교한다(상대 오차 1e-6 안팎, 리버브를 쓰는 파일은 지침서 9-3의 흔들림 범위).
2. **이음매:** 새 기능(코러스, 홀, 테이프, 트레몰로, 사이클)을 각각 켠 유물의 WAV 끝 → 첫 샘플 변화를 평소 샘플 간 변화와 비교한다. 100, 124, 180BPM과 8분/16분 격자에서 본다.
3. **노트 하나:** 새 프리셋마다 `OfflineAudioContext`에 `scheduleNote`로 렌더해 무음·NaN·피크(0.95 이하)를 본다. 음높이 악기는 모든 스케일 x 15행, 키·옥타브 이동 극단값.
4. **박자:** `Player.stats`로 늦은 예약 0개, 루프 간격 = `loopSeconds()`, 사이클 위치가 맞는지.
5. **저장:** 이전 버전이 저장한 localStorage 상태가 열린다.
6. **왕복:** 새 필드를 모두 쓴 설계서를 내보냈다 불러오면 같은 JSON이 나온다.
7. **CPU:** 코러스·테이프·홀을 5개 유물 모두에 건 믹스를 재생해 늦은 예약이 0개인지 본다(탭이 보일 때와 가려졌을 때).
8. 동작 확인은 내장 브라우저로 한다. 임시 로컬 서버(`.claude/launch.json`, PowerShell `HttpListener`, 스크립트는 한글 없는 경로)를 쓰고 끝나면 `.claude/`를 지운다. file:// 실행은 사용자에게 직접 확인을 부탁한다.
9. 소리의 좋고 나쁨은 코드로 판단할 수 없다. 단계마다 "하우스 v1 설계서를 불러와 카운터포인트(로즈)에 코러스 40% + 홀 30%, 턴테이블(패드)에 홀 50%" 처럼 무엇을 어떤 값으로 들으면 되는지 짧게 알려 준다.

## 7. 구현 전에 정할 것 (기본값)

질문 없이 정하면 아래 기본값을 쓰고 답변에 적는다.

- 순서: 단계 1 → 2 → 3. 각 단계 검증이 통과하면 다음 단계로 간다. 중간에 사용자 확인을 기다리지 않는다. 단, 기존 렌더가 달라지는 문제가 생기면 멈추고 알린다.
- 코러스 LFO는 1마디에 한 번, 테이프 흔들림은 2박에 한 번, 트레몰로는 프리셋의 `beats`. 모두 루프 머리에서 위상 0.
- 홀 리버브: 4.0초, 프리딜레이 30ms, 리턴 하이패스 250Hz, 로우패스 6000Hz. 기존 리버브(1.6초)는 그대로 둔다.
- 모음 포먼트와 프리셋 `gain`은 2·3장 초안에서 시작해 피크 기준으로만 조정한다. 소리 판단은 사용자에게 맡긴다.
- 사이클 최대 8루프(32마디). WAV 기본 길이는 한 루프.
- 하우스 v1 설계서는 고치지 않는다. 새 기능을 쓴 딥하우스 설계서는 이 요청이 끝난 뒤 따로 만든다.
