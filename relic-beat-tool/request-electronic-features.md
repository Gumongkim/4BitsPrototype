# 요청서: 유물 비트 메이커에 하우스·일렉트로닉 팝용 기능 추가

`relic-beat-tool/`에서 하우스와 일렉트로닉 팝 비트를 제대로 만들고 판단할 수 있도록 툴을 고친다. 작업 전에 `relic-beat-tool/CLAUDE.md`를 먼저 읽는다. 용어(칸, 박, 프리셋, 믹스 설정, 설계서)는 그 문서를 따른다.

## 0. 배경

- 유물-BGM 연동은 폐기됐다(2026-11-08). 그래서 툴은 더 이상 게임 링 박자에 묶이지 않는다. 템포와 격자를 장르에 맞게 고를 수 있어도 된다.
- 지금 툴은 130BPM 고정이고, 1칸이 8분음표, 32칸 = 4마디다. 하우스(120~128BPM)와 일렉트로닉 팝(100~128BPM)의 그루브는 16분음표 위에서 만든다(16분 하이햇, 16분 베이스, e·a 칸 당김음). 지금은 이것을 롤(같은 세기 반복)로만 흉내 낼 수 있다.
- **버그:** `DEMO_DRUMS`의 박 번호가 템포 변경 전(1박 = 8분음표) 값 그대로다. 지금은 1박이 4분음표라 하우스 킥이 1·3박에만, 스네어·클랩이 마디마다 3박에만 나온다(하프타임). 장르를 판단하는 기준 소리가 틀어져 있다.
- 킥·스네어 음색을 유물 프리셋으로 추가하지 않는 정책은 유지한다(지침서 4-4). 킥·스네어는 데모 드럼만 낸다.
- 기존 요청서 `request-house-features.md`의 단계 3~6(유물별 스윙, 키, 팬, 보컬 챱)은 아직 구현되지 않았다. 그 문서는 1박 0.3초 시절 기준이라 수치가 다르다. 이 요청서가 그 항목들을 지금 기준으로 다시 정의하므로 이 문서를 따른다.

## 1. 범위와 우선순위

| 단계 | 내용 | 필수 |
|---|---|---|
| 1 | 16분 격자, 템포 선택, 데모 드럼 수정·추가, 보이지 않는 킥(펌핑 기준), 딜레이 시간 선택 | **필수** |
| 2 | 유물별 스윙, 키(루트)와 스케일 추가, 유물별 옥타브 이동, 행 수 선택(8/15행), 팬과 스테레오 폭 | 선택 |
| 3 | 필터 스윕, 보컬 챱(`formants`), 새 프리셋, 코드 찍기 도우미 | 선택 |

단계 1을 끝내고 검증한 뒤 사용자에게 들어 보게 하고, 단계 2·3을 할지 묻는다.

**공통 규칙 (지침서 9-1 호환성):**
- 스키마 이름 `4bit-prototype-relic-beat-tool/v1`을 바꾸지 않는다. 새 필드는 모두 선택 항목이다. 기본값이면 내보내지 않고, 없으면 기본값으로 읽는다. 범위를 벗어나면 맞추고, 모르는 필드는 무시한다.
- 새 기능이 기본값이면 소리가 지금과 같아야 한다. 기본값일 때는 노드를 만들지 않는다.
- 기존 프리셋의 id·이름·파라미터·옥타브를 바꾸지 않는다. 새 프리셋은 뒤에 붙이고 `category`로 묶는다.
- localStorage에 저장된 이전 상태가 열려야 한다(`loadState`가 없는 항목을 채운다).
- 시각은 곱셈 하나로 계산한다(지침서 9-3 '시각 계산' 함정). 예: `g * stepSeconds`.

## 2. 단계 1 (필수)

### 2-1. 16분 격자

- 전체 설정에 `grid`를 더한다. 값은 `8`(8분음표, 32칸) 또는 `16`(16분음표, 64칸)이다. **없으면 8**. 둘 다 루프는 4마디(16박)다.
- 칸 수와 칸 시간을 상수가 아니라 상태에서 계산한다.
  - `steps = grid === 16 ? 64 : 32`
  - `stepSeconds = (60 / bpm) / (grid / 4)`: 8분이면 30/bpm, 16분이면 15/bpm
  - `loopSeconds = steps * stepSeconds`
- `TOOL.STEPS`, `TOOL.STEP_SECONDS`, `TOOL.LOOP_SECONDS`를 쓰는 곳(재생 스케줄러, `stepTime`, `noteGate`, `scheduleRelicStep`, `renderLoop`, 편집기, 설계서, 불러오기 검사)을 모두 이 값으로 바꾼다. `TOOL`에는 기본값(`DEFAULT_GRID` 8, `DEFAULT_BPM` 130)과 범위만 둔다.
- **스윙:** 지금처럼 홀수 칸을 `swing x stepSeconds`만큼 늦춘다. 16분 격자에서는 16분 스윙(e·a 칸)이 된다.
- **격자 바꾸기:**
  - 8 → 16: 모든 노트의 `step`과 `length`를 2배로 한다. 소리(시각)가 같게 유지된다.
  - 16 → 8: 홀수 칸에서 시작하는 노트가 하나라도 있으면 확인 창에 개수를 알린다. 확인하면 그 노트들을 지우고(앞 칸으로 옮기지 않는다), 나머지는 `step`과 `length`를 반으로 한다. `length`가 홀수면 올림한다. 취소할 수 있다.
  - 롤 노트(`repeat`)는 그대로 둔다.
- **편집기:** 64칸일 때 칸 너비를 줄이거나 가로 스크롤을 쓴다. 마디 경계(16칸마다)는 가장 굵게, 박 경계(4칸마다)는 굵게 그린다. 노트 길이 선택은 격자에 따라 8분이면 [1, 2, 4, 8], 16분이면 [1, 2, 4, 8, 16]칸으로 둔다. 길이 손잡이(7px)가 좁은 칸에서도 잡히는지 확인한다.
- **설계서:**
  - JSON 최상위에 `grid`를 쓴다(16일 때만).
  - `timing`은 실제 값으로 쓴다(`bpm`, `grid`, `stepSeconds`, `steps`, `loopSeconds`).
  - 박 단위 표는 1박 = 4분음표 기준으로 행 16개에 열을 `.0 .5`(8분) 또는 `.0 .25 .5 .75`(16분)로 쓴다.
  - 한 줄 패턴의 토큰 수는 칸 수와 같다.
  - 읽는 법의 시간 기준 줄을 고친다.
- **불러오기:**
  - `grid`가 16이면 `step` 범위를 0~63으로 검사한다. 없거나 8이면 0~31이다.
  - 파일의 `grid`를 툴 전체에 적용하고, 지금 격자와 다르면 확인 창에 알린다(스케일·스윙 변경 알림과 같은 방식).

### 2-2. 템포 선택

- 전체 설정에 `bpm`을 더한다. 범위 60~180, 정수, **없으면 130**. 화면은 스윙 옆에 숫자 입력이나 슬라이더를 두고 '130' 같은 값을 보인다.
- JSON 최상위에 `bpm`을 쓴다(130이 아닐 때만). `timing.bpm`은 참고값으로 계속 쓰고, 불러올 때는 최상위 `bpm`만 읽는다.
- 재생 중에 템포를 바꾸면 다음 루프 머리부터 적용하거나 재생을 다시 시작한다. 박이 밀리지 않는 쪽이면 된다. 어느 방식인지 답변에 적는다.
- `wobble_bass`의 `filterLfo.rate`는 지금 `130 / 60`으로 고정되어 있다. 프리셋 파라미터를 바꾸지 않는 규칙 때문에 그대로 둔다. 템포가 130이 아니면 워블이 박과 어긋날 수 있다고 지침서에 적는다(박 동기 LFO는 단계 3의 범위다).

### 2-3. 데모 드럼 수정과 패턴 추가

- `DEMO_DRUMS`를 박 번호가 아니라 **한 마디 16분 칸(0~15)** 으로 다시 정의하고, 4마디에 반복한다. 8분 격자에서는 짝수 16분 칸만 쓴다(홀수 칸 타격은 8분 격자에서 빠진다고 지침서에 적는다).
- 패턴 (한 마디, 16분 칸 0~15, 0 = 1박, 4 = 2박, 8 = 3박, 12 = 4박):

| 패턴 | 킥 | 스네어 / 클랩 |
|---|---|---|
| 록/J-pop | 0, 7, 8, 10 | 4, 12 (스네어) |
| 붐뱁 | 0, 7, 10 | 4, 12 (스네어) |
| 하우스/EDM | 0, 4, 8, 12 | 4, 12 (클랩) |
| 일렉트로닉 팝 (새로) | 0, 6, 8, 11 | 4, 12 (클랩 + 스네어 겹침) |
| 투스텝/UK 개러지 (새로, 선택) | 0, 7, 10 | 4, 12 (스네어) |

- 데모 드럼 줄에 '킥', '스네어' 켜기/끄기 체크박스를 더한다(기본 둘 다 켜짐). 끈 소리는 내지 않는다. 사이드체인은 2-4의 펌핑 기준을 따른다.
- 킥 소리는 지금 것(`DEMO_DRUM_SOUNDS.kick`)을 그대로 쓴다. 909 계열 킥은 단계 3의 범위다.
- 설계서에는 넣지 않는다(지금처럼 미리듣기 전용). 상태에는 저장한다.

### 2-4. 보이지 않는 킥 (펌핑 기준)

- 전체 설정에 `pumpSource`를 더한다: `demo`(데모 드럼 킥에 덕킹, **기본**) 또는 `quarter`(소리 없이 4분음표마다 덕킹).
- `quarter`면 데모 드럼이 '없음'이거나 킥이 꺼져 있어도 매 박 머리에 `duckAt`을 건다. 데모 드럼 킥과 같은 칸에서 두 번 걸리지 않게 한다.
- 이 값은 사이드체인을 들어 보는 방법일 뿐이라 설계서에 넣지 않는다. 읽는 법의 사이드체인 설명에 "4분 정박 킥 기준으로 설계했다"는 문장을 둔다.
- '데모 드럼 필요' 안내는 `pumpSource`가 `demo`이고 데모 드럼이 없을 때만 보인다.

### 2-5. 딜레이 시간 선택

- 전체 설정에 `delayNote`를 더한다: `'1/8'`, `'3/16'`(점8분), `'1/4'`, `'3/8'`(점4분). **없으면 `'3/8'`**. 지금 딜레이(90/130초 = 130BPM 3칸 = 점4분)와 같게 두기 위해서다.
- 딜레이 시간 = 음표 길이 x 4 x (60 / bpm)초. `createDelay`의 최대 시간은 60BPM의 점4분(1.5초)보다 크게 잡는다.
- JSON 최상위에 `delayNote`를 쓴다(기본값이 아닐 때만). 불러오기는 모르는 값이면 기본값으로 맞춘다.

### 2-6. 완료 기준 (단계 1)

- 새 필드가 없는 기존 설계서(`relic-beats-*.md`) 전부의 렌더가 수정 전과 같다. 기준 렌더는 데모 드럼 '없음'으로 한다.
- 8분 격자의 기존 설계서를 16분으로 바꿨다가 다시 8분으로 바꾸면 노트가 같다(홀수 칸 노트가 없을 때).
- 16분 격자, 125BPM, 데모 드럼 하우스에서 킥이 칸 0, 4, 8 … 60, 클랩이 칸 4, 12 … 60에 울린다(예약 시각 기록으로 확인한다).
- `pumpSource: quarter`이고 데모 드럼이 '없음'일 때 사이드체인 유물이 4분마다 눌린다.
- `delayNote` '3/16', 125BPM에서 딜레이 시간이 0.36초다.
- 루프 간격이 `loopSeconds`와 같고, 늦은 예약이 0개다(`Player.stats`). 120, 125, 130BPM에서 각각 확인한다.

## 3. 단계 2 (선택)

### 3-1. 유물별 스윙

- 유물에 선택 필드 `swing`(0~0.5)을 더한다. **없으면 전체 스윙을 따른다.**
- `stepTime(g, swing)`, `noteGate(step, length, swing)`처럼 스윙을 인자로 받게 바꾸고, `scheduleRelicStep`에서 유물의 값을 넘긴다. 데모 드럼은 전체 스윙을 쓴다.
- 믹스 설정에 '스윙' 슬라이더와 '전체 따름' 선택을 둔다. 사이드체인 덕킹 시각은 펌핑 기준(킥)을 따르므로 유물 스윙과 상관없다.

### 3-2. 키(루트)와 스케일

- 전체 설정에 `root`(0~11, C에서 올린 반음 수)를 더한다. **없으면 0.** `rowMidi`에 `+ root`를 더한다. 화면은 스케일 옆에 '키'(C, C#, … B)를 둔다.
- `SCALES` 뒤에 스케일을 더한다: `C 프리지안` [0, 1, 3, 5, 7, 8, 10], `C 믹솔리디안` [0, 2, 4, 5, 7, 9, 10], `C 하모닉 마이너` [0, 2, 3, 5, 7, 8, 11], `C 리디안` [0, 2, 4, 6, 7, 9, 11], `C 반음계` [0, 1, 2, …, 11].
- 설계서 스케일 줄에 키를 함께 쓰고(예: "A 자연 단음계 (C 자연 단음계 + root 9)"), JSON 최상위에 `root`(0이 아닐 때만)를 쓴다. 노트의 `midi`·`pitch`는 `root`를 반영한 실제 음이다.

### 3-3. 유물별 옥타브 이동과 행 수

- 유물에 선택 필드 `octaveShift`(-2~+2, 정수)를 더한다. **없으면 0.** 행 0의 MIDI에 `12 x octaveShift`를 더한다. 화면은 믹스 설정 아래 '옥타브' 선택이다.
- 전체 설정에 `pitchRows`(8 또는 15)를 더한다. **없으면 8.** 15행이면 스케일 음을 두 옥타브 쌓는다(반음계 15행 = 15반음). 편집기 세로 크기를 행 수에 맞춘다. 15 → 8로 바꿀 때 행 8 이상 노트가 있으면 확인 창에 알리고 지운다.
- `row` 검사 범위는 `pitchRows - 1`까지다.

### 3-4. 팬과 스테레오 폭

- 유물에 선택 필드 `pan`(-1~1, 화면 -100~+100)을 더한다. **없으면 0.** 0이 아니면 `StereoPannerNode`를 로파이 뒤에 둔다. 리버브·딜레이 센드는 팬 앞(가운데)에서 뽑는다.
- 프리셋 파라미터에 선택 항목 `spread`(0~1)를 더한다. 있으면 오실레이터들을 좌우로 벌려 배치한다(첫 오실레이터는 -spread, 마지막은 +spread, 사이는 고르게). 기존 프리셋에는 넣지 않는다. 단계 3의 새 프리셋(슈퍼소 패드 등)에 쓴다.

### 3-5. 완료 기준 (단계 2)

- 새 필드가 없으면 렌더가 같다.
- 전체 스윙 0%, 한 유물만 25%일 때 그 유물의 홀수 칸만 `0.25 x stepSeconds` 늦다.
- `root` 9에서 `C3`이 A3으로 울린다. MIDI가 0~127 안에 있다(옥타브 이동과 함께 극단값 확인).
- `pan` -1이면 오른쪽 채널이 무음이다.
- 새 필드를 모두 쓴 설계서가 내보내기 → 불러오기에서 같은 JSON이 된다.

## 4. 단계 3 (선택)

### 4-1. 필터 스윕

- 유물에 선택 필드 `filterSweep: { from, to }`(각 0~1)를 더한다. 루프 머리에서 끝까지 유물 체인의 로우패스 컷오프를 `from`에서 `to`로 지수 램프로 움직인다. 0~1 → Hz 대응은 `highCut`과 같다(0 = 20kHz, 1 = 800Hz). 루프마다 처음 값으로 돌아간다.
- `highCut`과 같이 있으면 둘 중 더 낮은 컷오프가 아니라 직렬로 둘 다 건다. 렌더(`renderLoop`)에서도 같은 곡선이 나와 루프 이음매가 생기지 않게 한다(두 바퀴 렌더의 두 번째 바퀴에서도 같은 램프를 건다).

### 4-2. 보컬 챱

- 프리셋 파라미터에 선택 항목 `formants: [{ freq, Q, gain }]`을 더한다. 있으면 메인 필터 대신 병렬 밴드패스 여러 개를 거쳐 합친다.
- 프리셋 `vocal_chop`('아' 모음) 초안은 `request-house-features.md` 8장을 쓴다. 피크 0.95 이하로 `gain`을 맞춘다.

### 4-3. 새 프리셋

- 후보: `house_piano`(M1 계열 하우스 피아노 스탭), `future_chord`(디튠 톱니 + 필터 엔벨로프 + `spread`), `reese_bass`(디튠 톱니 2개, 느린 위상 맥놀이), `finger_snap`(타악), `noise_down`(다운리프터, 고음에서 내려가는 노이즈), `supersaw_pad`(`spread`). 데모 드럼용 909 킥(`DEMO_DRUM_SOUNDS`만, 유물 프리셋 아님).
- 각 초안을 답변에 표로 적고, 지침서 4-4 표에 묶음별로 더한다.

### 4-4. 코드 찍기 도우미

- 편집기 위에 '코드' 선택(없음, 3화음, 7화음, sus4, add9)을 둔다. 없음이 아니면 칸을 클릭할 때 그 행을 근음으로 스케일 위 3도씩(sus4는 4도, add9는 9도 추가) 쌓은 음들을 한 번에 찍는다. 행 범위를 넘는 음은 빼고 찍는다.
- 데이터는 지금처럼 노트 여러 개라 설계서 형식은 바뀌지 않는다.

## 5. 문서 갱신

기능을 바꾸면 아래를 함께 고친다(지침서 9-1).

- `relic-beat-tool/CLAUDE.md`: 2 시간 기준(격자, 템포, 칸 시간 식), 3 화면과 조작, 4-2 전역 값(`grid`, `bpm`, `pumpSource`, `delayNote`, `root`, `pitchRows`), 4-1 유물별 값(`swing`, `octaveShift`, `pan`, `filterSweep`), 4-2 데모 드럼 패턴 표, 4-3 상수, 4-4 프리셋, 4-5 파라미터(`spread`, `formants`), 5 소리 경로, 6 설계서 양식과 JSON 스키마, 6-4 불러오기 규칙, 9-2 코드 지도.
- 루트 `README.md`의 '유물 비트 메이커' 절.
- 루트 `CLAUDE.md`의 relic-beat-tool 항목(한 줄 요약의 "130BPM 4마디", 선택 항목 목록).
- `request-house-features.md` 맨 위에 "단계 3~6은 `request-electronic-features.md`로 옮겨 다시 정의했다"고 한 줄 적는다.
- 이 툴은 웹 링크(Artifact)에 넣지 않으므로 재게시하지 않는다. 유물-BGM 연동은 폐기됐으므로 게임 코드는 건드리지 않는다.

## 6. 검증 (지침서 9-4 방법)

1. **기준 렌더:** 수정 **전에** `relic-beats-*.md` 전부를 `parseDesign`으로 읽어 `renderLoop`로 렌더(`Math.random` 시드 고정, 데모 드럼 '없음')하고 50ms 구간 RMS와 유물별 RMS를 저장한다. 수정 후 같은 방법으로 비교한다(상대 오차 1e-6 안팎, 리버브를 쓰는 파일은 지침서 9-3의 흔들림 범위).
2. **박자:** `Player.stats`로 루프를 여러 번 돌려 늦은 예약 0개, 루프 간격 = `loopSeconds`. 8분/16분 격자 x 120/125/130BPM.
3. **데모 드럼:** `scheduleNote`를 감싸 예약 시각을 기록하고, 2-6의 칸 위치와 같은지 확인한다.
4. **이음매:** 내보낸 루프의 끝 → 첫 샘플 변화를 평소 샘플 간 변화와 비교한다. 16분 격자, 템포 변경, 유물별 스윙, 필터 스윕에서 모두 본다.
5. **노트 하나:** 새 프리셋마다 `OfflineAudioContext`에 `scheduleNote`로 렌더해 무음·NaN·피크(0.95 이하)를 본다. 음높이 악기는 모든 스케일 x 모든 행.
6. **저장:** 이전 버전이 저장한 localStorage 상태가 열린다. 새 필드가 없는 상태에서도 오류가 없다.
7. **왕복:** 새 필드를 모두 쓴 설계서를 내보냈다 불러오면 같은 JSON이 나온다. 16분 격자 설계서를 이전 툴 기준(8분, 0~31칸)으로 읽으면 범위 밖 칸 때문에 거부된다는 점을 지침서에 적는다.
8. **화면:** 64칸 편집기에서 찍기, 지우기, 드래그, 세기 바꾸기, 길이 끌기가 되는지 `MouseEvent`로 확인한다.
9. 동작 확인은 내장 브라우저로 한다. file:// 은 스크립트가 돌지 않으므로 임시 로컬 서버(`.claude/launch.json`, PowerShell `HttpListener`, 스크립트는 한글 없는 경로)를 쓰고 끝나면 `.claude/`를 지운다. file:// 실행은 사용자에게 직접 확인을 부탁한다.
10. 소리의 좋고 나쁨은 코드로 판단할 수 없다. 끝나면 "16분 격자, 125BPM, 데모 드럼 하우스, 펌핑 기준 4분"처럼 어떤 설정으로 무엇을 들으면 되는지 짧게 알려 준다.

## 7. 구현 전에 정할 것 (기본값)

질문 없이 정하면 아래 기본값을 쓰고 답변에 적는다.

- 범위: **단계 1만 하고**, 끝난 뒤 사용자에게 들어 보게 한 다음 단계 2·3을 할지 묻는다.
- 옛 설계서(1박 0.3초 시절, `bpm`·`grid` 없음)는 지금처럼 8분 격자·130BPM으로 읽는다. 원래 소리(16분 격자·100BPM·2마디)로 되살리는 변환은 하지 않는다.
- 새 툴의 기본 상태: 격자 8, 130BPM, 딜레이 점4분, 펌핑 기준 `demo`. 기존 사용자의 소리가 바뀌지 않게 하기 위해서다. 하우스 작업은 사용자가 16분·125BPM으로 바꿔서 한다.
- 템포 범위 60~180, 정수.
- 16 → 8 격자 변환에서 홀수 칸 노트는 지운다(확인 창을 거친다).
- 데모 드럼 패턴은 2-3 표의 값에서 시작한다. 들어 보고 바꿀 수 있도록 상수로 둔다.
