# 요청서: 유물 비트 메이커에 하우스·딥하우스용 프리셋과 믹스 기능 추가

`relic-beat-tool/`에서 하우스, 딥하우스 계열 비트를 만들 수 있도록 프리셋 몇 종과 유물별 믹스 기능을 더한다. 작업 전에 `relic-beat-tool/CLAUDE.md`를 먼저 읽는다. 용어(칸, 박, 프리셋, 믹스 설정)는 그 문서를 따른다.

## 0. 배경

- 하우스는 보통 120~128BPM, 딥하우스는 118~124BPM이다. 툴은 1박 0.3초(8분음표 기준 **100BPM**)로 고정이다.
- 루프 4.8초는 100BPM에서 정확히 2마디다. 125BPM이면 4.8초가 2.5마디라 반복이 어긋난다. 게임 링 박자(0.3초 격자)와도 묶여 있으므로 **이번 작업에서 템포는 바꾸지 않는다.** 대신 16분 밀도와 스윙으로 체감을 맞추고, 100BPM이므로 "느린 딥하우스, 다운템포 하우스" 쪽 감각이 된다.
- 킥·스네어 음색은 게임의 쿵(A)·짝(S) 판정 소리와 겹치므로 프리셋으로 **추가하지 않는다.** 하우스의 4분 정박 킥은 데모 드럼(하우스/EDM)과 게임의 킥이 맡고, 유물은 그 킥에 맞춘 사이드체인으로 펌핑만 받는다.
- 지금 38종 프리셋과 기능으로 가능한 것과 모자란 것은 1장에 정리했다. 모자란 것만 이 요청서의 범위다.
- 근거가 되는 측정(사이버펑크 설계 v1, 무작위 5개 조합 40개 렌더): 120~250Hz가 전체의 약 35%로 참고곡(약 12%)의 3배, 2kHz 이상은 참고곡의 1/5이었다. 유물 단위로 저음·고음을 깎을 수단이 없어서 음역 겹침을 설계서에서만 풀어야 했다. 또 리버브가 1.6초라 8칸(1.2초)마다 바뀌는 코드 위로 꼬리가 넘어갔다.

## 1. 하우스·딥하우스 요소별 현황

| 요소 | 지금 | 비고 |
|---|---|---|
| 4분 정박 킥 | 가능 | 데모 드럼 하우스/EDM (킥 칸 0, 4, 8 … 28) |
| 오프비트 오픈 하이햇, 클랩, 셰이커·탬버린 16분 | 가능 | `open_hat`, `hand_clap`, `shaker`, `tambourine` |
| 펌핑(사이드체인) | 가능 | 유물별 값, 데모 킥 기준. 어택 0.01초, 릴리스 0.2초 고정 |
| 딜레이 | 가능 | 0.45초 = 3칸 = 점8분이라 하우스에 맞음 |
| 셔플(스윙) | 부분 | **전체 공통** 값 하나뿐. 킥은 곧게, 하이햇만 흔드는 것이 안 됨 |
| 코드 스탭, 오르간 스탭 | 부분 | `chord_stab`(톱니파 스탭)은 있고, 하우스 특유의 짧은 오르간 스탭(M1 계열)이 없음 |
| 로즈 계열 건반 | 부분 | `electric_piano`(FM)는 있으나 따뜻한 로즈 음색이 아님 |
| 둥근 딥 베이스 | 부분 | `sub_bass`(피크 1.06), `sub_808`(디스토션), `synth_bass`(톱니파)뿐 |
| 콩가·봉고·클라베 등 라틴 퍼커션 | 없음 | `tap_perc`, `cowbell`로 대신하는 중 |
| 보컬 챱(모음 소리) | 없음 | 한 개의 필터만 있어서 모음(포르만트) 소리를 못 냄 |
| 저음 깎기(로우컷), 고음 깎기(하이컷) | **없음** | 유물별 EQ가 없어 음역 정리가 안 됨. 로파이 로우패스만 있음 |
| 키(루트) 선택 | **없음** | 모든 스케일이 C 기준이라 샘플의 키에 맞출 수 없음 |
| 좌우 위치(팬) | 없음 | 모든 소리가 가운데 |
| 필터 스윕(빌드업) | 부분 | 프리셋에 고정된 `from`/`sweep`, `filterLfo`뿐 |

## 2. 범위와 우선순위

| 단계 | 내용 | 필수 |
|---|---|---|
| 1 | 유물별 믹스 `lowCut`, `highCut` (3장) | 필수 |
| 2 | 새 프리셋 5종 (4장) | 필수 |
| 3 | 유물별 `swing` (5장) | 선택 |
| 4 | 키(루트) `root`와 스케일 추가 (6장) | 선택 |
| 5 | 유물별 `pan`, 리버브 저음 컷 (7장) | 선택 |
| 6 | `formants`와 프리셋 `vocal_chop` (8장) | 선택 |

단계 1, 2를 끝내고 검증한 뒤에 3~6으로 간다. 모든 새 항목은 **없으면 기본값(꺼짐)** 이어야 하고, 기본값이면 노드를 만들지 않아 소리가 이전과 같아야 한다.

## 3. 단계 1: 유물별 `lowCut`, `highCut`

### 3-1. 기능

- 믹스 설정에 `lowCut`(저음 깎기)과 `highCut`(고음 깎기)을 더한다. 값은 0~1, **없으면 0(꺼짐)**.
- 소리 경로(`makeChain`): 볼륨 → 사이드체인 덕킹 → **하이패스 → 로우패스** → (로파이) → 마스터와 센드. 센드는 필터를 지난 소리에서 뽑는다.
- 주파수 대응(지수): `lowCut` v > 0이면 하이패스 `20 x (800 / 20)^v` Hz (v = 1이면 800Hz). `highCut` v > 0이면 로우패스 `20000 x (800 / 20000)^v` Hz (v = 1이면 800Hz, v = 0.5면 약 4kHz). 필터는 `Q` 0.707, 12dB/oct 한 단이면 충분하다.
- 값이 0이면 필터 노드를 만들지 않는다. `makeChain`의 `key`에 두 값의 켜짐 여부를 더해, 켜고 끌 때 실시간 재생에서 체인을 새로 만든다.

### 3-2. 화면과 설계서

- 믹스 설정 슬라이더(사이드체인, 리버브 센드, 딜레이 센드, 로파이)에 '저음 깎기', '고음 깎기'를 더한다 (각 0~100%). `MIX_FIELDS`, `MIX_SETTING_LABELS`, `relicMix`를 고친다.
- 설계서의 믹스 설정 표와 JSON 유물 항목에 선택 필드 `lowCut`, `highCut`을 더한다 (기본값이면 내보내지 않는다). 스키마 이름 `4bit-prototype-relic-beat-tool/v1`은 **바꾸지 않는다.** 모르는 필드는 이전 툴이 무시한다.
- `parseDesign`은 범위를 벗어난 값을 0~1로 맞춘다. 읽는 법의 '믹스 설정' 줄에 두 항목을 덧붙인다.

### 3-3. 완료 기준

- 두 값이 없는 기존 설계서 `relic-beats-*.md` 전부의 렌더가 수정 전과 같다 (6장 검증의 상대 오차 기준).
- `lowCut` 0.5, `highCut` 0.5를 건 유물을 내보냈다 불러오면 같은 JSON이 나온다 (왕복).
- 하이패스 800Hz(v = 1)에서 `sub_808` 소리가 눈에 띄게 줄고, 로우패스 800Hz(v = 1)에서 `closed_hat` 소리가 거의 사라진다 (극단값 확인).

## 4. 단계 2: 새 프리셋 5종

### 4-1. 규칙

- `PRESETS` **맨 뒤**에 붙인다. 기존 프리셋의 id·이름·파라미터·옥타브는 바꾸지 않는다.
- 묶음은 기존 것을 쓴다: `house_organ`, `warm_rhodes`는 `keys`, `deep_bass`는 `bass`, 콩가·클라베는 `drums`.
- 프리셋 하나의 **노트 피크는 마스터 전 0.95 이하**로 맞춘다. 아래 `gain`은 출발값이고 검증 결과로 조정한다.
- 파라미터는 기존 형식만 쓴다. `scheduleNote`는 이 단계에서 **고치지 않는다.**
- 킥·스네어 음색은 만들지 않는다.

### 4-2. 프리셋 초안

```js
// 하우스 오르간 스탭: 짧고 밝은 사각파 스탭. 1칸(0.15초)으로 끊어 치면 M1 오르간 스탭 느낌.
{ id: 'house_organ', name: '하우스 오르간', pitched: true, octave: 3, category: 'keys', params: {
  oscs: [{ type: 'square', gain: 1 }, { type: 'square', ratio: 2, gain: 0.45 }, { type: 'triangle', ratio: 0.5, gain: 0.5 }],
  filter: { type: 'lowpass', freq: 3200, Q: 1.2, from: 5200, sweep: 0.05 },
  env: { attack: 0.003, decay: 0.12, sustain: 0.3, release: 0.06 }, gain: 0.2 } },

// 따뜻한 로즈: 사인에 FM 종소리 어택을 얹고 몸통은 길게 울린다. 딥하우스 코드용.
{ id: 'warm_rhodes', name: '따뜻한 로즈', pitched: true, octave: 3, category: 'keys', params: {
  oscs: [{ type: 'sine', gain: 1 }, { type: 'sine', ratio: 2, gain: 0.18 }],
  fm: { ratio: 14, index: 0.8, decay: 0.07 },
  filter: { type: 'lowpass', freq: 3000, Q: 0.7 },
  env: { attack: 0.004, decay: 0.7, sustain: 0.25, release: 0.3 }, gain: 0.3 } },

// 딥 베이스: 둥근 삼각파 + 서브. 필터가 살짝 닫히며 앞이 통통하다.
{ id: 'deep_bass', name: '딥 베이스', pitched: true, octave: 2, category: 'bass', params: {
  oscs: [{ type: 'triangle', gain: 1 }, { type: 'sine', ratio: 0.5, gain: 0.7 }],
  filter: { type: 'lowpass', freq: 450, Q: 2, from: 1400, sweep: 0.1 },
  env: { attack: 0.005, decay: 0.3, sustain: 0.6, release: 0.08 }, gain: 0.4 } },

// 콩가 (고음/저음): 짧게 떨어지는 사인과 약한 노이즈. 타악이라 1행.
{ id: 'conga_high', name: '콩가 (높은)', pitched: false, category: 'drums', params: {
  oscs: [{ type: 'sine', fixed: 330, gain: 1 }], pitchSlide: { semis: 3, time: 0.03 },
  noise: { gain: 0.1, filter: { type: 'bandpass', freq: 1200, Q: 1 } },
  env: { attack: 0.001, decay: 0.13, sustain: 0, release: 0.03 }, gain: 0.5 } },

// 클라베: 짧고 건조한 딱 소리.
{ id: 'clave', name: '클라베', pitched: false, category: 'drums', params: {
  oscs: [{ type: 'sine', fixed: 2400, gain: 1 }, { type: 'triangle', fixed: 3600, gain: 0.3 }],
  env: { attack: 0.001, decay: 0.05, sustain: 0, release: 0.02 }, gain: 0.4 } },
```

- 완료 시 프리셋은 **43종**이 된다. (`conga_low`는 `conga_high`와 소리 차이가 크지 않아 뺐다. 필요하면 `fixed: 220`으로 하나 더 만든다.)
- 설계서 읽는 법의 프리셋 설명과 `paramsText`는 새 프리셋 파라미터를 그대로 보여 주면 된다 (새 형식 항목은 없다).

### 4-3. 완료 기준

- 프리셋 목록의 '건반', '베이스', '드럼·타악'에 새 항목이 보이고 5종을 고를 수 있다. 목록은 38종에서 **43종**이 된다.
- 기존 설계서 렌더가 수정 전과 같다.
- 5종 모두 스케일 6종 x 8행(타악은 1행)을 렌더해 무음 없음, NaN 없음, 피크 0.95 이하.
- `house_organ`을 길이 1칸, 8분 뒷박(칸 2, 6, 10 …)에 두고 WAV로 내보냈을 때 루프 이음매에 튐이 없다.

## 5. 단계 3 (선택): 유물별 `swing`

하이햇·셰이커는 흔들고 코드·베이스는 곧게 두는 하우스 셔플을 위해서다. 지금은 전체 스윙 하나만 있다.

- 유물에 선택 필드 `swing`(0~0.5)을 더한다. **없으면 전체 스윙을 따른다.** 값이 있으면 그 유물만 이 값으로 홀수 칸을 늦춘다.
- `stepTime(g)`와 `noteGate(step, length)`가 전체 `state.swing`을 읽으므로 유물별 값을 받는 형태(`stepTime(g, swing)`, `noteGate(step, length, swing)`)로 확장하고, `scheduleRelicStep`에서 유물의 값을 넘긴다. 데모 드럼은 전체 값을 쓴다.
- 시각은 곱셈으로 계산한다 (CLAUDE.md 9-3의 '시각 계산' 함정).
- 화면은 믹스 설정에 '스윙' 슬라이더(0~50%)와 '전체 따름' 선택을 둔다. 설계서 JSON에는 값이 있을 때만 `swing`을 내보낸다.
- 완료 기준: `swing`이 없는 기존 설계서의 렌더가 같다. 전체 스윙 0%, 한 유물만 25%일 때 그 유물의 홀수 칸만 0.0375초 늦다.

## 6. 단계 4 (선택): 키(루트)와 스케일 추가

- 전체 설정에 `root`(0~11, C에서 올린 반음 수)를 더한다. **없으면 0.** `rowMidi`에서 `+ state.root`를 더한다. 화면은 스케일 선택 옆에 '키' 선택(C, C#, … B)을 둔다.
- 설계서의 스케일 줄과 JSON 최상위에 선택 필드 `root`를 더한다. 스케일 이름은 `C ...`로 남기고 읽는 법에 "음높이는 `root` 반음만큼 올린다"고 쓴다.
- 스케일 4종을 `SCALES` 맨 뒤에 더한다: `C 프리지안` [0, 1, 3, 5, 7, 8, 10], `C 믹솔리디안` [0, 2, 4, 5, 7, 9, 10], `C 하모닉 마이너` [0, 2, 3, 5, 7, 8, 11], `C 리디안` [0, 2, 4, 6, 7, 9, 11].
- 완료 기준: `root`가 없는 설계서의 렌더가 같다. `root` 2에서 `C3`이 D3으로 울린다. 옥타브가 낮은 프리셋 행 0이 `root` 11에서 한 옥타브 아래로 내려가지 않는지(MIDI 범위) 확인한다.

## 7. 단계 5 (선택): `pan`, 리버브 저음 컷

- **pan:** 믹스 설정에 `pan`(-1~1, 화면은 -100~+100)을 더한다. **없으면 0.** 0이 아니면 `StereoPannerNode`를 로파이 뒤에 둔다. 리버브·딜레이 센드는 팬 앞(가운데)에서 뽑는다.
- **리버브 저음 컷:** 전체 설정에 '리버브 저음 컷'(꺼짐/켜짐)을 더한다. 켜면 리버브 리턴(컨볼버 출력)에 하이패스 250Hz를 건다. **기본은 꺼짐.** 꺼두면 기존 소리와 같다. 근거: 꼬리가 낮은 대역에서 쌓여 탁해지는 것을 줄이기 위해서다.
- 설계서 JSON에는 유물의 `pan`(값이 있을 때)과 최상위 `reverbLowCut`(켜졌을 때)을 선택 필드로 내보낸다.
- 완료 기준: 값이 없으면 렌더가 같다. `pan` -1이면 오른쪽 채널이 무음이다.

## 8. 단계 6 (선택): `formants`와 `vocal_chop`

보컬 챱(모음이 들리는 짧은 목소리 소리)을 합성으로 흉내 낸다. 샘플 파일은 쓰지 않는다.

- 프리셋 파라미터에 선택 항목 `formants`를 더한다: `[{ freq, Q, gain }]`. 있으면 메인 필터를 쓰지 않고, 오실레이터 합이 **병렬 밴드패스 여러 개**를 지나 합쳐진다. `filter`와 같이 있으면 `formants`가 우선한다.
- 프리셋 초안 ("아" 모음):

```js
{ id: 'vocal_chop', name: '보컬 챱', pitched: true, octave: 3, category: 'synth', params: {
  oscs: [{ type: 'sawtooth', gain: 1 }, { type: 'sawtooth', detune: 6, gain: 0.6 }],
  formants: [{ freq: 730, Q: 8, gain: 1 }, { freq: 1090, Q: 10, gain: 0.7 }, { freq: 2440, Q: 12, gain: 0.3 }],
  vibrato: { rate: 5, depth: 10, delay: 0.1 },
  env: { attack: 0.01, decay: 0.15, sustain: 0.45, release: 0.08 }, gain: 0.3 } },
```

- 완료 시 프리셋은 **44종**이 된다. 피크 0.95 이하, 무음·NaN 없음, 스케일 6종 x 8행 검증은 4장과 같다.
- `formants`가 없는 기존 프리셋은 노드 구성이 같아야 한다.

## 9. 문서 갱신

기능을 바꾸면 아래를 함께 고친다 (`relic-beat-tool/CLAUDE.md` 9-1).

- `relic-beat-tool/CLAUDE.md`: 4-4 프리셋 표(38종 → 43종, 단계 6까지 하면 44종), 4-5 파라미터(`formants`), 5 소리 경로(필터 위치, 팬), 6-3 JSON 스키마의 선택 필드(`lowCut`, `highCut`, `swing`, `pan`, 최상위 `root`, `reverbLowCut`), 9-2 코드 지도.
- 루트 `README.md`의 '유물 비트 메이커' 절: 프리셋 수와 묶음별 목록, 믹스 설정 항목, 설계서 JSON의 선택 항목 절.
- 루트 `CLAUDE.md`의 relic-beat-tool 항목은 "노트 세기·길이, 유물별 사이드체인·리버브/딜레이 센드·로파이" 문장에 새 항목을 더한다.
- 이 툴은 웹 링크(Artifact)에 넣지 않으므로 재게시하지 않는다.

## 10. 검증 (9-4 방법)

1. **기준 렌더:** 수정 **전에** `relic-beats-*.md` 전부를 `parseDesign`으로 읽어 `renderLoop`로 렌더(`Math.random` 시드 고정)하고 50ms 구간 RMS와 유물별 RMS를 저장한다. 수정 후 같은 방법으로 비교한다 (상대 오차 1e-6 안팎).
2. **노트 하나:** 새 프리셋마다 `OfflineAudioContext`에 `scheduleNote`로 렌더해 무음·NaN·피크(0.95 이하)를 본다. 음높이 악기는 스케일 6종(단계 4 후 10종) x 8행을 모두 돈다.
3. **박자:** `Player.stats`로 루프를 여러 번 돌려 늦은 예약 0개, 루프 간격 4.8초.
4. **이음매:** 내보낸 루프의 끝 → 첫 샘플 변화를 평소 샘플 간 변화와 비교한다. 단계 3의 유물별 스윙, 단계 1의 필터로도 이음매가 생기지 않는지 본다.
5. **저장:** 이전 버전이 저장한 localStorage 상태가 열린다. 새 필드가 없는 상태에서도 오류가 없다.
6. **왕복:** 새 필드를 모두 쓴 설계서를 내보냈다 불러오면 같은 JSON이 나온다.
7. 동작 확인은 내장 브라우저로 한다. file:// 은 스크립트가 돌지 않으므로 임시 로컬 서버를 쓰고 끝나면 `.claude/`를 지운다. file:// 실행은 사용자에게 직접 확인을 부탁한다.
8. 소리의 좋고 나쁨은 코드로 판단할 수 없다. 어떤 유물을 어떤 값으로 들으면 되는지 짧게 알려 준다.

## 11. 구현 뒤 설계서 (후속)

프리셋과 기능이 생기면 하우스/딥하우스 설계서를 새로 만든다 (유물 이름과 무관하게 17종, 어떤 5개를 골라도 어울리게). 쓸 요소는 다음과 같다.

- 데모 드럼 하우스/EDM, 오프비트 오픈 하이햇·클랩, 16분 셰이커(유물별 스윙), `house_organ` 스탭, `warm_rhodes` 코드, `deep_bass`·`sub_808` 저음(사이드체인), 콩가·클라베 퍼커션, 필요하면 `vocal_chop`.
- `lowCut`으로 코드·퍼커션의 저음을 깎고 `highCut`으로 베이스의 고음을 깎아 음역을 나눈다.
- 키는 `root`로 맞춘다 (단계 4를 한 경우).

## 12. 구현 전에 정할 것 (기본값)

질문 없이 정하면 아래 기본값을 쓰고 답변에 적는다.

- 단계 3~6 포함 여부: **기본은 단계 1, 2만 하고, 끝난 뒤 사용자에게 3~6을 할지 묻는다.**
- `lowCut`, `highCut` 주파수 대응은 3-1의 값에서 시작한다.
- 프리셋 `gain`은 4-2의 초안에서 시작해 피크 0.95 이하가 되도록 조정하고, 조정한 값을 답변에 표로 적는다.
- 템포(1박 0.3초)와 킥·스네어 프리셋 정책은 바꾸지 않는다.
