# 4Bit_Prototype

리듬 + 로그라이트 + 아케이드 웹 게임 프로토타입. 탑다운 8x4 그리드에서 실시간으로 진행된다.

- 무기마다 쿵(A)과 짝(S)으로 이루어진 드럼 패턴이 있다. 링이 공격 범위에 맞는 순간 그 리듬의 키를 누른다.
- 이동하면 무기 리듬이 처음부터 다시 시작된다. 피할지, 서서 링을 맞출지 골라야 한다.
- 한 사이클 안에서 적을 맞힌 횟수(HIT)가 쌓일수록 노드 데미지가 오른다. 이동하면 HIT도 사라지므로 서서 맞출수록 사이클 후반이 강해진다.
- 3웨이브마다 유물을 하나 고른다. 유물은 최대 5개까지 가지며 데미지나 규칙을 바꾼다.

## 실행 방법

`index.html`을 더블클릭하면 된다. 빌드 도구와 서버, 외부 라이브러리가 필요 없다.

## 조작법

| 키 | 동작 |
|---|---|
| 방향키 | 한 번 누를 때마다 한 칸 이동 (누르고 있어도 반복하지 않음) |
| A | 쿵 공격 (형광 초록 링) |
| S | 짝 공격 (형광 보라 링). 리듬과 다른 키를 누르면 Miss. A와 S 모두 꾹 누르고 있어도 한 번만 눌린 것으로 친다 |
| Enter | 타이틀에서 시작, 무기와 보상 확정, 게임오버에서 재시작 |
| ← → / 숫자키 | 무기나 보상·유물 카드 선택 / 바로 선택 |
| 1 / 2 | 전투 중, 턴테이블 유물이 있을 때 무기 슬롯 전환 |
| R / T | 게임오버에서 재시작 / 타이틀로 |
| M | 음소거 |
| D | 디버그 오버레이 (판정 윈도우, 리듬 번호, 매치 시점 오차, FPS, 그리드 좌표, 적 이름, HIT n/N과 다음 노드의 난이도 d_i·추가 배율, 유물 지급 커서) |
| [ ] / P | 디버그 모드에서만: 유물 지급 커서를 옮기고 / 그 유물을 지급하거나 회수한다. 슬롯이 가득 찼으면 맨 왼쪽 유물과 바꾼다 |
| E / Shift+E | 타이틀·게임오버 화면에서만: 저장된 로그를 JSON / CSV로 내려받고 저장소에서 지운다 |
| Shift+L | 타이틀·게임오버 화면에서만: 직전에 내보낸 로그 묶음을 다시 내려받는다 (복구용) |
| Y | 게임오버 화면에서만: 방금 판의 로그 JSON을 클립보드로 복사한다 |

화면 표시:

연출은 무기 제작 툴의 시연과 같다.

- **링:** 리듬마다 하나씩 나오며, 그 리듬의 공격 범위 모양으로 줄어드는 ㄱ자들이다. ㄱ자는 범위 모양의 바깥으로 튀어나온 모서리에만 놓이고, 안쪽으로 꺾인 모서리에는 나오지 않는다 (예: L자 범위면 5개). 쿵은 형광 초록, 짝은 형광 보라다. 성공 이펙트, 키 표시, 리듬 막대도 같은 색을 쓴다. 투명하게 나타나 리듬 순간에 가장 진해진다. 리듬이 지나도 늦은 입력이 인정되는 동안은 범위 안쪽으로 계속 줄어들고, 공격에 성공한 링은 바깥으로 퍼지며 사라진다.
- **공격 범위:** 평소에는 보이지 않는다. 링이 보이는 동안 그 리듬의 드럼 색으로 점점 진하게 채워지고, 리듬 순간 진하게 채워졌다가 흐려진다. 공격 키를 누르면 그 리듬의 범위 칸 테두리가 하얗게 나타났다가 사라진다.
- **키 표시:** 플레이어 위에 A와 S가 있고, 지금 눌러야 할 키만 선명하다.
- **HIT:** 플레이어 몸통 왼쪽에 흰색 "n HIT"가 칸 높이 가운데로 오른쪽 정렬되어 나온다. HIT가 오르면 이전 숫자가 위로 밀려나며 흐려지고 새 숫자가 아래에서 올라오며 한 번 팝한다. 글자는 사이클 진행에 따라 8에서 12까지 커진다. 사이클이 바뀌면 0.4초 동안 흐려지며 사라지고, 이동하면 바로 사라진다. 게임오버 화면에는 사이클 하나에서 달성한 최고 HIT가 나온다.
- **위쪽 HUD:** 왼쪽에 HP 바(수치 "현재/최대"는 바 안 가운데), 가운데에 웨이브, 오른쪽 위에 유물 칸 5개가 한 줄로 있고 그 아래에 무기 이름이 오른쪽 정렬로 나온다. 유물 칸은 아이콘 대신 등급 색 테두리와 이름 첫 글자이며 왼쪽부터 채운다. 공격 키(A / S)와 쿨다운 막대는 없다. 실드가 있으면 HP 바 오른쪽 끝에 하늘색 칸이 이어 붙고 그 안에 "+실드"가 나온다. 실드 칸 길이는 HP 1점과 같은 비율이며 12~40픽셀로 제한한다.
- **리듬 막대:** 화면 아래 가운데에 무기 패턴 한 바퀴를 8칸으로 나눠 그린다. 각 리듬 위치에 노드와 눌러야 할 키가 있고, 흰 선이 현재 시점이다.
- **디버그 타임라인:** 디버그 오버레이 오른쪽 아래 막대는 매치 시점을 가운데로 둔 타임라인이다. 노란색은 Perfect, 초록색은 Good, 흰 선은 현재 시점, 빨간 선은 마지막 입력이다.

## 무기 제작 툴 (`weapon-tool/`)

플레이어 무기를 만드는 별도 웹 툴이다. `weapon-tool/index.html`을 더블클릭해 연다. 게임 코드와는 독립되어 있다.

- **비트라인 (가운데 아래):** 4/4 박자 8박 = 2.4초 (1박 0.3초). 1박마다 눈금이 있고 박 번호는 그 박이 끝나는 눈금에 쓴다. 노드는 0.5박(0.15초)부터 8박(2.4초)까지 0.5박 단위로 놓는다. 8박은 다음 사이클 시작과 같은 순간이라 0초 자리는 없다. 빈 자리를 클릭하면 배치할 노드(A 쿵 형광 초록, S 짝 형광 보라)가 놓이고, 노드를 클릭하면 선택된다. 우클릭이나 Delete로 지운다.
- **그리드 필드 (가운데 위):** 8열 x 4행, 플레이어는 게임 시작 위치인 열 1, 행 1 (0부터 셈)에서 시작한다. 플레이어를 드래그하면 다른 칸으로 옮길 수 있고, 더블클릭하면 시작 위치로 돌아간다. 범위는 플레이어 기준 상대 위치라 플레이어를 따라 움직이며, 그리드 밖으로 나간 칸은 화면에서만 숨는다. 플레이어 위치는 모든 무기에 공통인 화면 설정이라 내보내기에 들어가지 않는다. 선택한 노드의 공격 범위를 칸 클릭으로 넣고 뺀다. 범위는 노드 색으로 보인다. 새 노드는 앞 1칸, 공격력 1로 시작한다.
- **오른쪽 패널:** 무기 이름, 선택한 노드의 드럼 종류·공격력·'가장 가까운 적 1명만' 옵션, 시연 버튼(Space). 시연은 게임처럼 링이 0.5초 동안 각 노드의 공격 범위로 줄어들고, 리듬 순간 범위가 번쩍이며 쿵/짝 소리와 메트로놈이 난다.
- **왼쪽 목록:** + 로 새 무기 작업을 만들고, 목록에서 작업을 골라 편집한다. 체크한 작업만 내보낸다. 작업은 브라우저 저장소에 자동 저장된다.
- **불러오기:** 내보내기 옆 '불러오기' 버튼으로 파일을 고르거나, .json 파일을 툴 화면에 끌어다 놓는다. 내보내기와 같은 양식을 읽어 항상 새 작업으로 목록 끝에 추가하고, 이름이 겹치면 '이름 (2)'처럼 번호를 붙인다. 위치는 `time`(초)을 기준으로 읽는다. 잘못된 값은 고쳐서 읽고 고친 내용을 목록으로 보여준다: 0.5박 단위가 아닌 위치는 가장 가까운 0.5박으로 맞추고, 0초 노드는 8박으로 옮기며, 사이클 밖·같은 자리 겹침·드럼 종류를 알 수 없는 노드와 그리드보다 먼 범위 칸(열 차이 ±7, 행 차이 ±3 초과)은 뺀다.
- **내보내기:** 체크한 무기를 JSON으로 만들어 `weapons-날짜-시각.json` 파일로 저장하고 클립보드에도 복사한다. JSON의 `howToRead`에 읽는 법이 있고, `gameConfig`에는 `config.js` `WEAPONS` 형식의 `intervals`, `startOffset`, `drums`, `damages`, 노드별 범위 `ranges`가 들어 있고, 모두 그대로 옮기면 된다.

## 유물 비트 메이커 (`relic-beat-tool/`)

유물마다 고유한 16박 비트(악기 1종)를 찍고, 최대 5개를 겹쳐 들어 보고, 설계서와 WAV로 내보내는 별도 웹 툴이다. 원래 게임 BGM의 유물별 층으로 쓸 데이터를 만들려 했으나, **유물과 BGM을 연동하는 작업은 구현이 어려워 폐기했다(2026-11-08). 툴과 설계서는 보존만 하고 게임에는 반영하지 않는다.** `relic-beat-tool/index.html`을 더블클릭해 연다. 게임 코드와 독립이고 웹 링크(Artifact)에 넣지 않는다. 소리는 외부 파일 없이 Web Audio API로 합성한다. 수치 상수는 `tool.js` 맨 위 `TOOL`에 있다. Claude용 지침서(사용법, 조정할 수 있는 값, 설계서 양식과 JSON 스키마, 설계서를 직접 쓰거나 게임에 옮길 때의 규칙, 툴 수정 규칙과 검증 방법)는 `relic-beat-tool/CLAUDE.md`다.

- **시간 기준:** 템포(60~180BPM, 기본 130, 4분음표 기준)와 격자(8분 = 32칸, 16분 = 64칸, 기본 8분)를 위쪽에서 고른다. 1박 = 4분음표, 루프는 항상 16박 = 4마디다(130BPM이면 약 7.385초, 125BPM 16분이면 1칸 0.12초, 루프 7.68초). 재생 중에 템포·격자를 바꾸면 처음부터 다시 재생한다. 격자를 8 → 16으로 바꾸면 모든 노트의 칸과 길이가 2배가 되어 소리가 같고, 16 → 8로 바꾸면 16분 홀수 칸(e·a)에서 시작하는 노트를 확인 창을 거쳐 지우고 나머지를 반으로 한다(길이는 올림). 이전 버전(1박 0.3초, `bpm`·`grid` 없음)에서 만든 설계서는 8분 격자·130BPM으로 읽는다. 재생은 AudioContext 시간으로 미리 예약하고 노트 시각을 칸 번호로 매번 계산하므로 루프를 돌아도 박이 밀리지 않는다. 탭이 가려지면 더 멀리 예약한다.
- **왼쪽:** 유물 목록. + 로 추가하고(이름 중복 불가, 30자까지) 체크박스(내보내기 포함), ✎ 이름 변경, × 삭제가 있다. 아래 '체크한 유물 삭제'는 체크한 유물을 확인 창을 거쳐 한 번에 지운다(믹스 바에서도 빠진다). 유물을 클릭하면 가운데 편집기에 나온다. 아래 악기 프리셋 56종에서 선택한 유물의 악기를 고른다. 목록은 머리글로 묶여 있다: 드럼·타악(클로즈드 하이햇, 오픈 하이햇, 라이드 심벌, 미드 톰, 하이 톰, 탬버린, 셰이커, 콩가 (높은), 클라베, 핑거 스냅), 베이스(일렉 베이스, 딥 베이스, 리스 베이스), 기타(디스토션 파워코드, 팜뮤트 기타, 클린 기타, 리드 기타), 건반(어쿠스틱 피아노, 일렉 피아노, 오르간, 하우스 오르간, 따뜻한 로즈, 하우스 피아노, 로즈 트레몰로), 신스(신스 베이스, 신스 플럭, 슈퍼소 리드, 808 서브, 코드 스탭, 워블 베이스, 보컬 챱, 퓨처 코드, 슈퍼소 패드, 보컬 챱 우·오·이·에, 보컬 패드), 효과음(노이즈 라이저, 레이저 잽, 노이즈 다운리프터), 기존 악기(로우 톰, 핸드 클랩, 서브 베이스, 워킹 베이스, 마림바, 글로켄슈필, 브라스 스탭, 플루트 리드, 아르페지오 신스, 상승 스트링, 지속 패드, 카우벨, 탭 퍼커션, 스크래치 노이즈, 크래시 심벌). 킥·스네어는 게임 판정 소리와 겹쳐 넣지 않았고, 파라미터는 고정이다. 맨 아래에 오디오 내보내기, 설계서 내보내기, 불러오기가 있다.
- **가운데 편집기:** 세로는 음높이, 가로는 32칸 또는 64칸(마디 경계 가장 굵게, 박 경계 굵게, 16분 격자는 8분 경계 중간 굵기, 64칸은 화면이 좁으면 가로 스크롤). 칸을 누르면 찍히고 다시 누르면 지워지며, 드래그하면 처음 누른 칸 기준으로 연속 찍기·지우기를 한다. 같은 칸에 여러 음(화음)을 찍을 수 있다. 찍을 때 그 음이 한 번 들린다. 재생 중에는 흰 선이 현재 위치다.
- **세기(벨로시티):** 편집기 위 '입력 세기'(강 1.0 / 중 0.7 / 약 0.4)로 새 노트의 세기를 고른다. 찍힌 노트는 Shift+클릭이나 우클릭으로 강 → 중 → 약 → 강 순서로 바뀐다. 중·약은 노트 색이 흐리다. 재생할 때 노트 게인에 곱한다(타악·음높이 악기 모두, 필터 밝기는 그대로).
- **노트 길이:** 음높이 악기만 쓴다(타악은 1칸). 편집기 위 '새 노트 길이'(8분 격자 1/2/4/8칸, 16분 격자 1/2/4/8/16칸)로 새 노트 길이를 고르고, 찍힌 노트는 마지막 칸 오른쪽 끝(밝은 테두리)을 끌어 늘이거나 줄인다. 같은 행에서 노트끼리 겹치지 않는다: 늘이다가 다음 노트를 만나면 거기서 멈추고, 긴 노트가 이어지는 칸에 새 노트를 찍으면 앞 노트가 그 칸 직전까지 줄어든다. 노트 시작 칸을 누르면 지운다. 루프 끝을 넘는 길이는 루프 끝에서 자른다. 게이트 = max(길이 x 1칸, 어택+디케이, 프리셋 hold).
- **롤:** 편집기 위 '롤'(없음/2/3/4번)을 고르면 새 노트가 한 칸(스윙 반영) 안에서 그 횟수만큼 균등하게 나눠 치는 롤 노트가 된다(하이햇·스네어 롤). 모든 타격은 노트 세기와 같고 한 번의 게이트는 그 간격이다. 롤 노트는 1칸이라 길이를 쓰지 않으며, 칸 안에 (롤 수 - 1)개의 가는 세로 선이 보인다.
- **코드 찍기:** 편집기 위 '코드'(없음 / 3화음 / 7화음 / sus4 / add9)를 고르면 칸을 누를 때 그 행을 근음으로 스케일 위에 쌓은 음들(3화음은 행 +0 +2 +4, 7화음은 +6 추가, sus4는 +0 +3 +4, add9는 +8 추가)을 한 번에 찍는다. 행 범위를 넘는 음은 빼고, 음높이 악기에만 쓴다. 데이터는 노트 여러 개라 설계서 형식은 그대로다.
- **음높이:** 툴 위쪽에서 키(C~B), 스케일, 행 수를 고른다. 스케일은 11종(마이너·메이저 펜타토닉, 자연 단음계, 장음계, 도리안, 블루스, 프리지안, 믹솔리디안, 하모닉 마이너, 리디안, 반음계)이고 이름은 C 기준이며, 키는 모든 음을 C에서 그 반음만큼 올린다. 음높이 악기는 8행(기본) 또는 15행(스케일 음을 두 옥타브 남짓, 15 → 8로 바꾸면 행 8 이상 노트를 확인 창을 거쳐 지운다), 타악·노이즈 악기는 1행이다. 노트는 행 번호로 저장하므로 스케일·키·악기를 바꾸면 같은 행이 새 음으로 바뀐다. 타악으로 바꾸면 노트가 1행으로 모인다.
- **위쪽 믹스 바:** 칸 5개(게임의 유물 소지 상한과 같다). 빈 칸의 + 로 유물을 넣고(이미 들어간 유물은 고를 수 없다), 찬 칸에는 이름, × 빼기, 볼륨(기본 100%, 최대 150%)이 있다. '믹스 재생'은 찬 칸의 유물을 동시에 반복 재생하고 다시 누르면 멈춘다. '랜덤 믹스'는 전체 유물 중 서로 다른 유물을 무작위로 골라 5칸을 새로 채운다(유물이 5개보다 적으면 있는 만큼 앞 칸부터, 칸 볼륨은 100%로). 믹스 재생 중이면 바로 새 조합으로 들린다. 재생 중 편집·볼륨 변경·칸 변경이 바로 반영된다.
- **위쪽 둘째 줄 (전역 설정, 자동 저장):**
  - **템포·격자:** 위 시간 기준 참고.
  - **딜레이:** 공통 딜레이 시간을 8분 / 점8분 / 4분 / 점4분(기본) 중에서 고른다. 시간 = 음표 박 수 x 60 / BPM초(125BPM 점8분 = 0.36초, 130BPM 점4분 = 약 0.692초).
  - **데모 드럼:** 없음 / 록·J-pop / 붐뱁 / 하우스·EDM / 일렉트로닉 팝 / 투스텝·UK 개러지와 킥·스네어 켜기 체크박스, 킥 음색(기본 / 909 / 딥: 120Hz에서 45Hz로 낮고 길며 클릭이 거의 없다), 드럼 볼륨. 장르를 판단하려고 단일·믹스 재생에 얹는 미리듣기 전용 킥·스네어다. 소리는 `tool.js`에서 합성하지만 유물 프리셋 목록에는 없다. 패턴은 한 마디 16분 칸(0 = 1박, 4 = 2박, 8 = 3박, 12 = 4박)으로 4마디에 반복한다: 록 킥 0 7 8 10, 붐뱁 킥 0 7 10, 하우스 킥 0 4 8 12(클랩), 일렉트로닉 팝 킥 0 6 8 11(클랩 + 스네어 겹침), 투스텝 킥 0 7 10, 스네어·클랩은 모두 4 12. 8분 격자에서는 짝수 16분 칸만 울린다. 설계서에 넣지 않는다.
  - **사이클:** 1 / 2 / 4 / 8루프(4~32마디). 노트는 4마디 한 루프 그대로이고, 필터 스윕과 유물별 등장 루프가 사이클 전체에 걸친다. 재생 중에는 편집기 제목 옆에 '루프 2/4'처럼 보인다.
  - **펌핑 기준:** 사이드체인을 거는 시각. 데모 킥(기본)은 데모 드럼 킥이 울리는 칸, 4분 정박은 소리 없이 매 박 머리다(데모 드럼이 없거나 킥을 꺼도 펌핑을 들어 볼 수 있다).
  - **스윙:** 0~50%. 홀수 칸(뒤 반박: 1.5, 2.5 …)의 시작과 노트 끝 경계를 swing x 1칸 늦춘다. 33% 근처가 셔플이다. 8분 격자는 8분 스윙, 16분 격자는 16분 스윙(e·a 칸)이다. 모든 유물과 데모 드럼에 같게 적용하고 편집기 격자는 그대로다.
  - **바이닐 노이즈:** 아주 작은 노이즈와 가끔 튀는 크랙. 재생에만 얹고 설계서·WAV에는 넣지 않는다.
- **오른쪽:** 선택한 유물만 반복 재생/정지, 유물 볼륨(믹스에서는 유물 볼륨 x 칸 볼륨), 노트 모두 지우기, 믹스 설정, 유물 설정, 악기·음높이 범위·노트 수·특징 정보. 단일 재생과 믹스 재생은 동시에 돌지 않는다.
- **유물 설정 (유물별, 설계서에 들어간다):**
  - **스윙:** 기본은 '전체 스윙 따름'이다. 체크를 풀면 그 유물만 0~50% 스윙을 쓴다(예: 하이햇·셰이커만 흔들고 코드·베이스는 곧게). 데모 드럼과 펌핑은 전체 스윙을 따른다.
  - **팬:** -100(왼쪽) ~ +100(오른쪽). 마스터로 가는 소리만 움직이고 리버브·딜레이 센드는 가운데에서 뽑는다.
  - **옥타브:** -2 ~ +2옥타브 이동(음높이 악기만). MIDI 0~127을 넘으면 옥타브 단위로 안으로 접는다.
  - **필터 스윕:** 켜면 사이클(사이클 1이면 한 루프) 머리에서 끝까지 로우패스가 움직이고 사이클마다 처음으로 돌아간다(0% = 20kHz, 100% = 800Hz, 켤 때 80% → 0%로 열리는 빌드업). '스윕 모양'은 시작 → 끝(기본) / 끝 → 시작 / 시작 → 끝 → 시작(사이클 앞 절반 열고 뒤 절반 닫아 반복해도 튀지 않는다). 고음 깎기와 따로 직렬로 건다.
  - **등장 루프:** 사이클이 2루프 이상이면 루프마다 체크박스가 생긴다. 끈 루프에서는 그 유물의 노트를 치지 않아(꼬리는 남는다) 층이 들어오고 빠지는 흐름을 만든다(예: 사이클 4에서 패드 1루프, 베이스 2루프, 보컬 3루프부터).
- **믹스 설정 (유물별, 0~100%, 기본 0):**
  - **사이드체인:** 펌핑 기준 칸마다 유물 소리를 (1 - 값)까지 0.01초에 눌렀다가 0.2초에 되돌린다(램프라 클릭이 없다). 펌핑 기준이 데모 킥인데 데모 드럼이 '없음'이면 효과가 없고 '데모 드럼 필요'라고 안내한다.
  - **리버브 센드·딜레이 센드:** 마스터의 공통 리버브(시드 고정 감쇠 노이즈 임펄스 1.6초)와 공통 딜레이(위 '딜레이' 설정, 피드백 0.35, 피드백 경로 로우패스 3000Hz)로 보내는 양. 두 버스의 출력은 압축기·리미터 앞에서 합친다.
  - **로파이:** 계단 곡선(값에 따라 12비트에서 3비트로) + 로우패스(18kHz에서 2.5kHz로). 샘플레이트는 낮추지 않는다.
  - **저음 깎기·고음 깎기:** 유물마다 하이패스(저음 깎기)와 로우패스(고음 깎기)를 건다(12dB/oct, Q 0.707). 값 v에 따라 저음 깎기는 20 x 40^v Hz(50% 126Hz, 100% 800Hz), 고음 깎기는 20000 x (1/25)^v Hz(50% 4kHz, 100% 800Hz)이고 슬라이더 옆에 Hz가 보인다. 음역이 겹치는 유물끼리 저음·고음을 나눌 때 쓴다.
  - **코러스:** 좌우 두 지연(15ms)을 ±3ms 반대 위상으로 흔드는 스테레오 코러스. 흔들림은 1마디에 한 번이고 루프 머리에서 맞춰 WAV 이음매가 없다. 패드·로즈를 넓게 만든다.
  - **홀 리버브:** 두 번째 리버브(4초, 프리딜레이 30ms, 좌우 다른 꼬리, 뒤쪽일수록 어둡고 리턴에 하이패스 250Hz·로우패스 6000Hz)로 보내는 양. 짧은 룸 리버브(1.6초)와 따로 쓴다. 쓰는 유물이 없으면 홀 버스를 만들지 않는다.
  - **테이프:** 아날로그 테이프 질감. tanh 포화(레벨 보정), 2박에 한 번 아주 작게 음높이가 흔들리는 지연(8ms ± 0.6ms x 값), 고음 감쇠(18kHz → 6kHz). 비트를 줄이는 로파이(디지털 샘플러)와 다르다.
  - 유물 출력 경로: 볼륨 → 사이드체인 덕킹 → (저음 깎기) → (고음 깎기) → (필터 스윕) → (테이프) → (로파이) → (코러스) → (팬) → 마스터, 그리고 팬 앞에서 리버브·홀·딜레이 센드. 값이 0이면 그 노드를 만들지 않아 이전과 소리가 같다.
- **설계서 내보내기:** 체크한 유물을 `relic-beats-YYYYMMDD-HHMMSS.md` 한 파일로 저장한다. 읽는 법(시간 기준, 표기법, 게임 반영 시 주의) → 요약 표(유물, 악기, 음높이 범위, 노트 수, 특징) → 유물별 상세(악기와 합성 파라미터, 박 단위 표 `.0 / .5`(16분 격자는 `.0 / .25 / .5 / .75`), 한 줄 패턴 `1.0:C4 1.5:- …`) → 맨 아래 JSON 코드블록(스키마 `4bit-prototype-relic-beat-tool/v1`) 순서다. 사람이 읽는 표는 모두 JSON에서 만든다. 쉬는 칸은 `-`, 타악은 `X`, 화음은 `+`로 잇는다. 세기는 음 뒤 `@m`(중)·`@w`(약)(강은 표기 없음, 타악은 `X@m`), 2칸 이상 노트는 시작 칸에 `C3*4`처럼 `*길이`, 그 노트가 이어지는 칸은 `=`, 롤 노트는 `X/3`처럼 `/횟수`다(순서: 음, 길이, 롤, 세기). 믹스 설정이 하나라도 있으면 유물 상세에 '믹스 설정' 한 줄(사이드체인 / 리버브 센드 / 딜레이 센드 / 로파이 / 저음 깎기 / 고음 깎기, 깎기는 Hz도)을 쓰고, 요약 표의 특징에 강약·긴 노트·믹스 설정 유무를 덧붙인다. 읽는 법에 세기·길이·스윙 계산식·믹스 설정 상수·'데모 드럼은 데이터에 없음'을 적는다.
- **설계서 JSON의 선택 항목:** 스키마 이름은 그대로(`v1`)이고 새 항목은 기본값이면 넣지 않는다. 노트 `velocity`(0~1, 없으면 1)·`length`(칸 수, 없으면 1)·`repeat`(롤 1~4, 없으면 1, 2 이상이면 length 1), 유물 `sidechain`·`reverbSend`·`delaySend`·`lofi`·`lowCut`·`highCut`(0~1, 없으면 0)·`swing`(없으면 전체 스윙)·`octaveShift`(-2~2, 없으면 0)·`pan`(-1~1, 없으면 0)·`filterSweep`({ from, to, shape? }, 없으면 없음)·`loops`(루프별 켜짐, 없으면 모두)·`chorus`·`hallSend`·`tape`(0~1, 없으면 0), 전체 `groove.swing`(0~0.5, 없으면 0)·`bpm`(60~180, 없으면 130)·`grid`(16만 16분, 없으면 8)·`root`(0~11, 없으면 0)·`pitchRows`(15만 15행, 없으면 8)·`cycleLoops`(1·2·4·8, 없으면 1)·`delayNote`(없으면 점4분 `3/8`). `timing`은 참고값이다. 16분 격자 설계서(칸 0~63)는 8분만 아는 이전 툴에서 범위 밖 칸으로 거부된다.
- **불러오기:** 버튼으로 고르거나 .md 파일을 화면에 끌어다 놓는다. JSON 코드블록만 읽고 스키마 이름·버전·스케일·악기·칸·행을 검사해 잘못되면 이유를 보여준다. 새 항목은 범위를 벗어나면 범위 안으로 맞추고, 모르는 항목은 무시한다. 이름이 같은 유물은 덮어쓰고(파일 내용이 곧 그 유물이라 파일에 없는 새 항목은 기본값으로 돌아간다), 없는 이름은 새로 추가하며, 목록에만 있는 유물과 믹스 바는 그대로다. 파일의 스윙(없으면 0)을 적용한다. 덮어쓰기·스케일 변경·스윙 변경이 있으면 확인 창에 알리고 취소할 수 있다. 파일의 키·행 수·템포·격자·딜레이도 적용하고(바뀌면 확인 창에 알린다), 격자가 바뀌면 파일에 없는 유물의 노트를 같은 시각으로 옮긴다.
- **오디오 내보내기:** 체크한 유물마다 WAV 1개(`relic-이름-시각.wav`)와 체크한 유물을 모두 합친 믹스 WAV 1개(`relic-mix-시각.wav`)를 저장한다. 44.1kHz 16비트 스테레오, 길이는 정확히 한 바퀴(4마디, 130BPM이면 약 7.385초)다. '데모 드럼 포함'을 체크하면 데모 드럼 소리가 들어가고(기본 제외), 사이드체인은 체크와 상관없이 펌핑 기준을 따른다. 바이닐 노이즈는 넣지 않는다. 여러 파일을 내려받으므로 브라우저가 허용을 물을 수 있다. MP3는 외부 라이브러리가 필요해 지원하지 않는다. 'WAV 길이'가 한 사이클이면 루프 x 사이클 길이를 렌더하고 사이클 단위로 이음매 없이 반복된다(등장 루프·사이클 필터 스윕 반영). 한 루프(기본)인데 사이클이 2 이상이면 필터 스윕은 첫 루프 구간 값이고 등장 루프는 무시한다고 상태줄에 알린다.
- **이음매 없는 루프:** 한 바퀴의 노트를 압축기 앞까지 두 바퀴 길이로 렌더해, 루프 끝을 넘은 릴리스·리버브·딜레이 꼬리를 앞으로 접어 더한다(다음 바퀴 킥의 사이드체인도 꼬리에 건다). 그 한 바퀴를 두 번 반복 재생하며 압축기·리미터를 거치고 두 번째 바퀴를 쓴다. 음높이 슬라이드·FM·비브라토처럼 주파수가 움직이는 소리는 브라우저가 렌더 시각마다 위상을 조금씩 다르게 만들기 때문에, 예전 방식(두 바퀴를 렌더해 두 번째를 자르기)으로는 이음매가 어긋났다. 홀 리버브 꼬리가 한 바퀴보다 길 수 있어, 홀을 쓰면 꼬리 길이만큼 여러 바퀴를 렌더해 모두 접는다. 코러스·테이프·트레몰로처럼 움직이는 것은 주기를 템포에서 계산하고(1마디·2박·프리셋의 박 수) 위상을 루프 머리에 맞춰 이음매가 없다.
- **자동 저장:** 작업 상태를 브라우저 저장소(`relicBeatTool.state`)에 자동 저장한다. 저장에 실패하면(저장 공간 부족 등) 안내만 하고 계속 쓸 수 있다.
- **합성 파라미터:** 프리셋은 오실레이터(`oscs`), 노이즈, 필터(시작 주파수에서 이동 가능), 음높이 슬라이드, 엔벨로프, 겹친 타격(`bursts`), 최대 게인으로 만든다. 선택 항목으로 `distortion`(WaveShaper tanh 곡선, `drive`가 클수록 강하고 필터 앞에 온다), `fm`(사인 모듈레이터가 주파수를 변조, 깊이 `index` x 모듈레이터 Hz가 `decay`초 동안 0으로), `vibrato`(LFO가 detune을 `rate` Hz, ±`depth`센트로 흔들고 `delay`초 뒤 시작), `hold`(게이트의 하한. 게이트 = max(노트 길이, 어택+디케이, hold)), `filterLfo`(사인 LFO가 메인 필터 주파수에 ±`depth` Hz를 `rate` Hz로 더한다. 노트 시작에 위상 0, 메인 필터가 있어야 한다)가 있다. 노트마다 만든 노드는 소리가 끝나면 연결을 끊는다. 디케이 끝과 게이트 끝은 한 번만 계산해 게이트 끝이 디케이 끝보다 앞서지 않게 한다(예전에는 따로 더해, 시각이 클 때 반올림으로 감쇠 램프가 무시되고 노트가 최대 음량으로 남는 경우가 있었다). 선택 항목 `spread`(오실레이터를 좌우로 벌림)와 `formants`(메인 필터 대신 병렬 밴드패스로 모음 소리, 보컬 챱)도 있다. `tremolo`(노트 게인을 박 단위 주기로 흔들고 좌우 반대 위상도 가능, 위상은 루프 머리 기준)도 있다. 보컬 프리셋은 숨소리 노이즈도 포먼트를 지난다.
- **마스터:** 게인 0.6 → 압축기(-10dB, 4:1) → 리미터(`LIMITER_THRESHOLD_DB` -3dB, 20:1, 어택 0). 리버브·딜레이 버스는 게인 뒤 압축기 앞에서 합친다. 5개 층이 같은 박에 화음으로 겹쳐도 출력이 1.0을 넘지 않는다. 재생과 WAV 내보내기가 같은 합성 경로다.

### HIT
HIT는 한 사이클(무기 `intervals` 한 바퀴) 안에서 성공한 공격 횟수다. 노드 하나의 최종 데미지는 `기본 데미지 x 판정 배율 x (1 + 추가 배율)`이고, 여러 적을 맞혀도 같은 배율을 쓴다.

- **카운트:** 판정이 Good 이상이고 그 공격 범위에서 적을 하나 이상 맞혔을 때만 1 오른다. 빈 범위를 친 입력, Miss, 피격은 HIT를 올리지도 초기화하지도 않는다.
- **사이클:** 링이 (재)시작될 때마다 사이클 0부터 센다. 이동, 무기 교체, 보상 후 웨이브 시작은 모두 링을 다시 시작하므로 HIT 0이 된다. 노드가 속한 사이클은 `Math.floor(ring / intervals.length)`(`ring`은 `matchBeat`의 값)이라, 사이클이 넘어가는 순간 늦게 들어온 입력은 이전 사이클 HIT로 센다. 더 큰 사이클의 노드가 성공하면 0부터 다시 센다.
- **추가 배율:** `min(HIT_BONUS_CAP, HIT_MAX_BONUS x (n - 1) / (N - 1) x d_i)`. n은 이번 노드를 포함한 HIT, N은 노드 수(1이면 분모 1)다. 첫 HIT는 +0%이고, 한 사이클을 전부 성공하면 마지막 노드가 d_i가 1일 때 +50%다.
- **노드 난이도 d_i:** 원값은 간격 계수(`HIT_GAP_DIFFICULTY`, 간격 0.15 이하 2.0, 0.3 이하 1.5, 0.45 이하 1.2, 그 외 1.0) x (직전 노드와 드럼이 다르면 `HIT_KEY_CHANGE_MULT`)다. 간격은 `intervals[i]`, 직전 노드는 순환해서 잡는다. 원값을 무기 평균으로 나눠 평균이 1이 되게 한다. 무기를 정할 때(`setWeapon`) 한 번 계산한다. 예: 플로우 8 너클 `0.64 1.47 0.88 0.64 1.47 0.88`, 더블타임 소드는 모든 노드가 같아 전부 1.
- 최고 HIT(`bestHit`)는 사이클 하나에서 도달한 가장 큰 HIT이며 게임오버 화면에 나온다.

| 상수 | 기본값 | 설명 |
|---|---|---|
| `HIT_MAX_BONUS` | 0.5 | 사이클을 다 맞혔을 때 마지막 노드의 추가 배율 (d_i가 1일 때) |
| `HIT_BONUS_CAP` | 0.75 | 추가 배율 상한 |
| `HIT_GAP_DIFFICULTY` | 0.15 → 2.0, 0.3 → 1.5, 0.45 → 1.2, 그 외 1.0 | 노드 간격별 난이도 계수 |
| `HIT_KEY_CHANGE_MULT` | 1.15 | 직전 노드와 드럼이 다를 때의 난이도 배수 |
| `HIT_UI_BASE_SIZE`, `HIT_UI_MAX_SIZE` | 8, 12 | HIT 글자 크기. `(n - 1) / (N - 1)`에 비례해 커진다 |
| `HIT_UI_GAP` | 4 | 플레이어 몸통 왼쪽 가장자리와 글자 사이 |
| `HIT_UI_POP_SCALE`, `HIT_UI_POP_TIME` | 1.4, 0.15 | 숫자가 오를 때의 팝 배율과 시간 |
| `HIT_UI_ROLL_TIME` | 0.12 | 이전 숫자가 위로, 새 숫자가 아래에서 올라오는 시간 |

### 무기
`WEAPONS`에 무기별 값이 있다. 작성 방법은 `config.js`의 주석에 있다. 무기 24개의 리듬(`intervals`, `startOffset`, `drums`)과 노드별 공격 범위는 무기 제작 툴에서 만든 `weapons-export-v4.json` 그대로다. 데미지는 툴 값(전부 1)을 쓰지 않고 아래 데미지 기준으로 맞춘 값을 유지했다. `DEFAULT_WEAPON`(`backbeat_sword`)은 선택 전 기본값이다.

- **티어:** 무기마다 1~4티어(`tier`)가 있다. 런 시작 화면에는 1티어 무기 4개만 나오고, 2~4티어는 보상 화면의 무기 카드로 얻는다. 무기 카드는 티어 색 테두리에 범위 그림, 리듬 막대, 데미지를 보여준다.
- **공격 범위:** 리듬마다 다른 범위를 `ranges`에 리듬 순서대로 넣는다. `ranges`에 없는 리듬은 `range`를 쓴다. 범위마다 `firstTargetOnly`를 따로 둘 수 있다. 무기 카드와 시작 화면의 범위 그림은 게임과 같은 8x4 격자에 시작 위치 기준으로 그린다.
- **데미지:** 한 사이클 데미지 총량을 쿵 1 : 짝 1.5 비율로 리듬에 나누고 0.25 단위로 반올림했다. 총량은 봇 시뮬레이션의 웨이브당 처치 시간이 티어별 목표(`WEAPON_TIER_CLEAR_TARGET`, 9 / 7.5 / 6 / 4.5초)에 가깝도록 무기마다 맞췄다. 그래서 같은 티어여도 범위가 좁은 무기는 데미지가 높다.
- **쿨다운과 판정 윈도우:** 무기마다 두지 않고 모든 무기가 같다. 공격 쿨다운 0.1초, Miss 쿨다운 0.6초, Perfect ±0.05초, Good ±0.12초다. Good 윈도우가 쿨다운보다 길어 한 리듬을 두 번 누를 수 있으므로, 이미 성공한 리듬에 맞춘 입력은 판정과 쿨다운 없이 버린다. 이때 반대쪽 리듬(다음 리듬 또는 지나간 리듬)이 Good 윈도우 안이고 아직 성공하지 않았으면 그 리듬으로 판정한다. 공격 키를 꾹 누르고 있을 때의 키 반복 입력은 `input.js`에서 버린다.

리듬은 입력과 상관없이 패턴대로 계속 돌아간다. 이동하면 1번 리듬부터 다시 시작한다. 최종 데미지는 리듬 데미지 x 판정 배율(Perfect는 `perfectMult`, Good은 `goodMult`) x (1 + HIT 추가 배율)이다.

### 적
적은 idle → attack(공격 위치로 접근 → 공격 1회 → 오른쪽 구역으로 복귀) → idle을 반복한다. attack 상태의 적은 빨간 테두리로 표시된다.

- **공격 위치:** 공격 범위가 플레이어에게 닿는 칸 중, 다른 적이 없는 가장 가까운 칸이다. 거리가 같으면 플레이어와 같은 행에 가까운 칸, 그다음 오른쪽 칸을 고른다. 모든 후보가 막혔으면 가장 가까운 후보 쪽으로 가서 기다린다. 이동할 때마다 다시 고른다.
- **비켜서기:** idle 적이 다른 적의 공격 위치에 서 있으면 이동 간격을 기다리지 않고 바로 옆 빈 칸으로 비킨다. 다른 적이 노리지 않는 칸, 그중 대기 구역 안의 칸을 먼저 고른다.
- **복귀:** 대기 구역에서 가장 가까운 빈 칸으로 돌아간다.

`ENEMIES`에 종류별 수치와 공격 범위(`attack`)가 있다. 이동하지 않는 적은 `stationary: true`를 둔다. 작성 방법은 `config.js`의 주석에 있다. 새 적을 넣을 때는 `renderer.js`의 `ENEMY_LOOKS`에도 모양을 추가한다.

HP와 데미지는 계열별로 같다. 근접은 HP 4.5, 데미지 2이고 원거리는 HP 3, 데미지 1이다. 실제 HP는 웨이브 증가율을 곱한 뒤 반올림하므로 근접은 1웨이브부터 5다.

### 유물
유물 정의(이름, 등급, 카드 설명, 수치)는 `config.js`의 `RELICS`에, 효과 로직은 `relics.js`의 `RELIC_LOGIC`에 같은 키로 둔다.

- **획득:** 웨이브 3, 6, 9, …(`RELIC_ENCOUNTER_EVERY`의 배수)를 클리어하면 무기 보상 화면 앞에 유물 선택 화면이 나온다. 보유하지 않은 유물 카드 3장과 '건너뛰기' 카드 중 하나를 고른다. 조작과 진입 직후 입력 잠금은 무기 보상 화면과 같다. 고를 유물이 하나도 없으면 바로 무기 보상 화면으로 간다.
- **추첨:** 카드마다 등급을 가중치(일반 60, 희귀 30, 에픽 10)로 뽑고 그 등급에서 보유하지 않았고 이미 나오지 않은 유물 하나를 고른다. 에픽은 9웨이브를 클리어한 선택 화면부터 나온다. 남은 유물이 없는 등급은 뽑지 않는다.
- **보유:** 최대 5개, 같은 유물은 중복 소지할 수 없다. 슬롯이 가득 찬 상태에서 카드를 고르면 교체할 보유 유물을 고르는 화면이 나온다 (맨 끝 '취소'는 유물 선택으로 돌아간다). 새 유물은 바꾼 유물의 칸에 들어간다.
- **카드:** 이름, 한 줄 설명, 등급 색 테두리(일반 회색, 희귀 파랑, 에픽 보라)다. 선택한 카드는 바깥에 흰 테두리가 생긴다. 유물 선택·유물 교체·무기 교체 화면은 같은 카드 선택 화면(`openPicker`)을 쓴다.
- **데미지:** 노드 하나의 최종 데미지는 `기본 x 판정 배율 x (1 + HIT 추가 배율) x (1 + 유물 % 합) x 유물 배율`이다. 유물 % 합은 `damagePct` 질의의 합이다. 유물 배율은 `damageMult` 질의의 곱으로, % 풀과 따로 곱하는 효과에 쓴다.

유물 효과로 맞은 적(인접 피해, 추가 타격, 프리스타일)에는 입자 `PARTICLES_RELIC`(4)개가 튄다. 수치는 모두 `RELICS`의 각 항목에 있다.

**프리스타일:**
- **게이지:** 0~100. 노드가 Good 이상이고 적을 맞혔을 때(에어 드럼으로 센 빈 범위 노드 포함) `100 / (N x 2)`씩 오른다 (N은 무기 `intervals.length`). 일반 상태에서는 줄지 않고 웨이브가 바뀌어도 남는다. 리듬 막대 바로 아래(화면 맨 아래)의 가는 막대이며, 평소에는 파랑, 모드 중에는 노랑이다.
- **모드:** 가득 차면 시작한다. 링이 멈추고 사라지며 리듬 막대의 현재 시점 선도 사라진다. 게이지는 초당 20씩 준다. A 또는 S를 누를 때마다 플레이어 오른쪽 3칸 `[(1,0),(2,0),(3,0)]`의 모든 적을 공격한다 (쿨다운 0.3초, 박자와 판정 없음). 공격 칸은 노란 테두리로 보인다. 데미지는 `무기 damages 합 / 8 x 1.5 x (1 + 유물 % 합)`이고 판정·HIT 배율과 따로 곱하는 유물 배율은 쓰지 않는다. 유물 % 합의 드럼은 누른 키를 따른다.
- **상호작용:** 이동할 수 있고 이동해도 모드는 계속된다. 노드 판정이 없으므로 Perfect·HIT 기반 유물은 발동하지 않는다. 처치 이벤트(스포르찬도 등)와 이동 이벤트(탭 댄스)는 발동한다. 턴테이블 전환은 허용되고 데미지 기준은 현재 무기다.
- **종료:** 게이지가 0이 되거나 웨이브를 클리어하면 끝나고, 링을 새로 시작한다 (새 사이클, HIT 0, 무기의 `startOffset`부터).

**턴테이블:**
- 무기 슬롯이 2개다. 빈 슬롯이 있으면 무기 보상 카드는 교체 대신 추가되고, 장착 무기는 그대로다. 슬롯이 가득 찬 상태에서 무기 카드를 고르면 바꿀 무기를 고르는 화면이 나온다 ('취소'는 무기 보상으로 돌아간다). 장착 중이던 슬롯을 바꾸면 새 무기를 장착한다. 무기 보상 카드에는 두 슬롯의 무기가 나오지 않는다.
- 전투 중 숫자키 1, 2로 장착 무기를 바꾼다. 전환은 교체가 아니며 (리허설 카운트 유지) 링을 다시 시작한다. 전환 후 첫 성공 노드(적을 맞힌 Good 이상) 데미지 x1.5 (유물 배율). 이동으로 링이 리셋되면 이 보너스는 사라진다.
- 화면 오른쪽 위에 두 무기 이름이 번호와 함께 두 줄로 나오고 장착 무기만 선명하다.
- 턴테이블을 잃으면 장착 중인 무기만 남는다.

**훅 구조:** 게임은 `game.emit(이벤트, data)`로 보유 유물에 이벤트를 슬롯 순서대로 전달한다. 유물은 `RELIC_LOGIC[키]`에 같은 이름의 함수 `(game, data, state, def)`를 두면 받는다 (`state`는 그 유물의 상태 객체, `def`는 `CONFIG.RELICS[키]`). 규칙을 바꾸는 유물은 질의 함수를 둔다. 자세한 인자는 `relics.js` 맨 위 주석에 있다.

### 보상
웨이브를 클리어하면 (유물 선택 화면이 있으면 그다음에) 보상 화면에서 무기 카드 3장과 '지금 무기 유지' 카드 중 하나를 고른다. 무기 카드는 서로 다르고 지금 무기는 나오지 않는다. 카드마다 티어, 범위 그림, 리듬 막대, 데미지가 보인다. 능력치 보상 카드는 없다.

| 상수 | 설명 |
|---|---|
| `REWARD_WEAPON_CARDS` | 무기 카드 수 (3) |
| `REWARD_INPUT_LOCK` | 보상·유물 선택·교체 선택 화면 진입 직후 입력을 막는 시간 (0.4) |
| `WEAPON_TIER_UNLOCK_WAVE` | 이 웨이브를 클리어하면 그 티어 무기 카드가 나올 수 있다 (1·2티어 1, 3티어 4, 4티어 8) |
| `WEAPON_TIER_WEIGHTS` | 무기 카드 티어 가중치. 고정값이다 (1티어 17.5, 2티어 37.5, 3티어 30, 4티어 15). 카드마다 열린 티어 중에서 티어를 먼저 뽑고, 그 티어에서 아직 나오지 않았고 지금 무기가 아닌 무기 하나를 고른다 |
| `WEAPON_TIER_CLEAR_TARGET` | 무기 데미지를 맞출 때 쓴 티어별 봇 처치 시간 목표. 게임 중에는 쓰지 않는다 |
| `STAT_LIMITS` | `player.stats`가 효과로 도달할 수 있는 수치 한계. 지금은 쓰는 곳이 없고 유물용으로 남겨 두었다 |

`rewards.js`의 `apply`는 카드의 `effects: [{ stat, add }]`와 `heal`도 적용한다. 지금 카드는 효과가 없지만 유물에서 같은 형식을 쓸 수 있게 남겨 두었다. `stat`에는 `player.js`의 `stats` 키(`maxHp`, `moveTick`, `windowBonus`, `perfectMult`, `goodMult`)를 쓴다. `windowBonus`는 판정 윈도우에 더해진다 (`STAT_LIMITS`로 최대 0.03).

### 게임오버 로그
밸런스 분석용으로 한 판의 요약과 웨이브별 기록을 남긴다 (`logger.js`). 읽기 전용 집계라 게임 규칙에는 영향이 없다. 게임 코드는 `Logger.*`만 부르고, 모든 진입점은 `try/catch`로 감싸 로거 오류가 게임을 멈추지 않는다 (오류는 콘솔 경고만 남긴다).

- **수집:** 플레이 중 가볍게 집계하고, 게임오버(`hurtPlayer`에서 HP가 0이 되는 순간)에 `Logger.finishRun()`이 한 번 런 기록 1건을 만든다. 새 런을 시작하면 집계를 초기화한다. 수집 지점: `startRun`(런 시작), `nextWave`(웨이브 시작), `updatePlay`(play 시간), `resolveAttack`(적을 맞힌 공격의 판정과 오차), `updateTelegraphs` → `hurtPlayer(피해, 적 종류)`(피격), `enterReward`(웨이브 종료), 무기·유물 보상 화면(제시 카드와 선택), 무기 슬롯 변경, 턴테이블 전환, `Relics.add`(유물 획득 웨이브).
- **누적:** 런 기록 배열을 `localStorage`의 `LOG_STORAGE_KEY`에 JSON으로 쌓는다. 최근 `LOG_MAX_RUNS`(500)판만 남기고 넘치면 오래된 것부터 지운다. 용량이 넘치면(`QuotaExceededError`) 오래된 기록을 10%씩 지우며 다시 시도하고, 그래도 안 되거나 저장소를 쓸 수 없으면 메모리에만 보관한다 (페이지를 닫으면 사라진다). 웹 링크처럼 저장소가 유지되지 않는 곳에서도 메모리 보관분으로 내보낼 수 있다.
- **화면:** 타이틀과 게임오버 화면 아래에 작은 글씨로 `저장된 로그 N판 · E: JSON · Shift+E: CSV`가 나온다 (게임오버에서는 `· Y: 이번 판 복사`가 붙는다). 내보내기 결과는 그 위에 2.5초 동안 노란 글씨로 나온다. 플레이 중에는 로그 키가 동작하지 않는다.
- **내보내기와 삭제:** E는 `logs-날짜-시각.json` 하나, Shift+E는 `runs-날짜-시각.csv`와 `waves-날짜-시각.csv` 두 파일을 내려받는다. 내려받기를 실행한 직후 저장소와 메모리 보관분을 지우므로 같은 판이 두 번 내려가지 않는다. JSON 파일에는 `exportedAt`, `build`, `count`, `firstRunId`, `lastRunId` 메타 정보와 `runs` 배열이 들어 있다. CSV는 런 요약의 중첩 필드를 `death.enemyKind`처럼 펼쳐 한 줄로 쓰고, 배열·객체 필드(`weapons`, `relics`, `rewards`, `hits.damageByEnemy`)는 셀 안에 JSON 문자열로 넣는다. 웨이브 행은 `runId`로 런과 연결한다. 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM을 붙인다. 내보낼 기록이 없으면 파일을 만들지 않고 화면에 알린다.
- **저장 위치:** 크롬·엣지에서 `index.html`을 직접 열면 내보낼 때 저장 위치를 고르는 창이 뜬다. JSON(파일 하나)은 '다른 이름으로 저장' 창, CSV(파일 두 개)는 폴더 선택 창 한 번으로 고른 폴더에 두 파일을 함께 쓴다. 창은 지난번 위치를 기억한다(`LOG_PICKER_ID`). 창에서 취소하면 로그를 지우지 않는다. 이 창을 쓸 수 없는 브라우저(파이어폭스·사파리 등)나 권한이 거부되면 브라우저 기본 다운로드 폴더로 내려받는다. 웹 링크 안에서는 페이지가 위치를 고를 수 없고 저장 확인 창 뒤 브라우저 설정을 따른다 (크롬 설정 > 다운로드 > '다운로드 전에 각 파일의 저장 위치 확인'을 켜면 매번 위치를 고를 수 있다).
- **웹 링크에서 내보내기:** claude.ai 웹 링크(Artifact) 안에서는 페이지가 직접 파일을 내려받을 수 없어 Artifact의 `downloads` 기능(`claude.use('downloads')`)으로 저장 확인 창을 띄운다. 파일이 여러 개면(CSV) 확인 창이 차례로 하나씩 뜬다. 모든 파일을 저장해야 저장소에서 지우고, 뷰어가 취소하거나 저장할 수 없으면 로그를 그대로 두고 화면에 알린다. 게시할 때 `capabilities: { downloads: true }`를 선언해야 한다. 그 밖(`index.html` 직접 실행 등)에서는 `<a download>`로 바로 내려받고 실행 직후 지운다. 저장 확인 창이 열려 있는 동안 다시 누른 내보내기 키는 무시한다.
- **복구용 백업:** 내보낸 파일 묶음 1회분을 `LOG_BACKUP_KEY`에 보관하고 다음 내보내기 때 덮어쓴다 (저장소를 쓸 수 없으면 메모리). Shift+L로 그 묶음을 다시 내려받는다. 백업은 지우지 않는다.
- **참고 출력 (삭제 안 함):** 게임오버 때 `console.table`로 요약과 웨이브 행을 출력한다. Y는 방금 판의 JSON을 클립보드로 복사하고, 클립보드를 쓸 수 없으면 조용히 무시한다.
- **원격 수집 (선택):** `LOG_WEBHOOK_URL`이 빈 문자열이 아니면 게임오버 때 런 기록 JSON을 `fetch`로 POST한다 (`mode: 'no-cors'`, `Content-Type: text/plain`, `keepalive: true`). 실패는 조용히 무시하고 재시도하지 않는다. 설정 방법은 `tools/log-webhook.gs` 맨 위 주석에 있다: 구글 시트의 Apps Script에 붙여 넣고 웹 앱(액세스 '모든 사용자')으로 배포한 뒤 그 URL을 `LOG_WEBHOOK_URL`에 넣는다. 스크립트는 `runs` 시트에 한 판을 한 줄로, `waves` 시트에 웨이브 행을 추가하고 이미 있는 `runId`는 건너뛴다.
- **`BUILD_VERSION`:** 무기·적·유물 수치, 판정, 규칙 등 밸런스에 영향을 주는 변경을 할 때마다 손으로 올린다 (형식 `연.월.일-번호`, 같은 날 여러 번이면 번호를 올린다). 연출이나 로그만 바꿨을 때는 올리지 않는다. 로그를 빌드별로 나눠 비교할 때 쓴다.

런 기록 (한 판 1건). 저장할 때는 웨이브 행을 `waves` 배열로 중첩한다.

| 필드 | 내용 |
|---|---|
| `schema` | 로그 형식 버전 (1) |
| `runId` | 시각 + 난수로 만든 고유 ID (중복 제거용) |
| `sessionId` | 페이지를 연 뒤 한 번 만든 익명 ID. 개인 정보는 없다 |
| `build` | `BUILD_VERSION` |
| `endedAt` | 게임오버 시각 (ISO 문자열) |
| `playSeconds` | `play` 상태에서 흐른 게임 시간(초). 보상 화면 시간은 빠진다 |
| `weapons` | 무기 슬롯에 들어온 순서 `[{ kind, tier, fromWave }]`. 시작 무기와 보상으로 받은(교체·턴테이블 추가) 무기다. `fromWave`는 그 무기를 처음 쓸 수 있는 웨이브다 |
| `weaponSwitches` | 턴테이블 전환 횟수 |
| `relics` | 게임오버 시점의 보유 유물 `[{ id, name, fromWave }]`. `fromWave`는 효과가 처음 적용되는 웨이브(보상 화면에서 얻으면 다음 웨이브, 디버그 지급이면 그 웨이브) |
| `reachedWave` | 도달 웨이브 |
| `death` | `{ enemyKind, wave }` 마지막으로 HP를 깎은(사망을 일으킨) 공격의 적 종류와 웨이브 |
| `judge` | `{ perfect, good, miss }` 적을 맞힌 공격의 판정 횟수 (게임오버 화면의 통계와 같다. 빈 범위를 친 입력은 빠진다) |
| `timing` | `{ meanError, meanAbsError }` `judge`에 센 공격 중 Miss가 아닌 판정의 입력 오차 평균과 절대값 평균(초). 이름 음수, 늦음 양수. 없으면 null |
| `hits` | `{ taken, shieldAbsorbed, damageByEnemy }` 적 공격에 맞은 횟수(실드가 다 막은 것 포함), 실드가 막은 피해 합, 적 종류별로 실제로 깎인 HP 합 |
| `bestHit` | 최고 HIT |
| `rewards` | 보상 화면 기록 `[{ wave, kind, offered, chosen }]`. `kind`는 `weapon` 또는 `relic`, `offered`는 제시된 카드(무기 키·`keep`, 유물 키·`skip`), `chosen`은 고른 카드다. 턴테이블 빈 슬롯에 넣으면 `added: true`, 슬롯을 바꾸면 `replacedSlot`(1부터), 유물을 바꾸면 `replaced`(빠진 유물 키)가 붙는다. 교체 선택에서 취소하면 같은 항목을 이어서 쓴다 |
| `waves` | 웨이브 행 배열 |

웨이브 행 (한 웨이브 1건)

| 필드 | 내용 |
|---|---|
| `runId`, `wave` | 런 기록과 연결 |
| `weaponKind` | 그 웨이브를 마칠 때 장착 중이던 무기 |
| `cleared` | 클리어 여부. 사망한 마지막 웨이브는 false |
| `seconds` | 웨이브 시작부터 보상 화면이 뜰 때까지(마지막 처치 후 대기 `WAVE_CLEAR_DELAY` 포함, 봇 시뮬레이션 처치 시간과 같은 기준) 또는 사망까지의 게임 시간 |
| `damageTaken` | 그 웨이브에서 실제로 깎인 HP 합 (실드가 막은 양 제외) |
| `perfectRate` | `perfect / (perfect + good + miss)`, 판정이 없으면 null |

| 상수 | 기본값 | 설명 |
|---|---|---|
| `BUILD_VERSION` | `'2026.11.07-1'` | 빌드 버전. 밸런스를 바꿀 때 손으로 올린다 |
| `LOG_MAX_RUNS` | 500 | 저장소에 남기는 최근 판 수 |
| `LOG_STORAGE_KEY` | `'4bit_prototype_logs'` | 로그 저장 키 |
| `LOG_BACKUP_KEY` | `'4bit_prototype_logs_backup'` | 직전 내보내기 백업 키 |
| `LOG_WEBHOOK_URL` | `''` | Apps Script 웹훅 주소. 빈 문자열이면 보내지 않는다 |
| `LOG_DOWNLOAD_GAP_MS` | 400 | 파일 여러 개를 내려받을 때 사이 간격(밀리초) |

| `LOG_NOTICE_TIME` | 2.5 | 내보내기 결과 알림 표시 시간 |
