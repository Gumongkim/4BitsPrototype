# 타이밍 그리드 (가제)

리듬 + 로그라이트 + 아케이드 웹 게임 프로토타입. 탑다운 8x4 그리드에서 실시간으로 진행된다.

- 무기마다 쿵(A)과 짝(S)으로 이루어진 드럼 패턴이 있다. 링이 공격 범위에 맞는 순간 그 리듬의 키를 누른다.
- 공격 판정이 정확할수록 더 좋은 등급의 보상이 나온다.
- 이동하면 무기 리듬이 처음부터 다시 시작된다. 피할지, 서서 링을 맞출지 골라야 한다.

## 실행 방법

`index.html`을 더블클릭하면 된다. 빌드 도구와 서버, 외부 라이브러리가 필요 없다.

## 조작법

| 키 | 동작 |
|---|---|
| 방향키 | 한 번 누를 때마다 한 칸 이동 (누르고 있어도 반복하지 않음) |
| A | 쿵 공격 (형광 초록 링) |
| S | 짝 공격 (형광 보라 링). 리듬과 다른 키를 누르면 Miss |
| Enter | 타이틀에서 시작, 무기와 보상 확정, 게임오버에서 재시작 |
| ← → / 숫자키 | 무기나 보상 카드 선택 / 바로 선택 |
| R / T | 게임오버에서 재시작 / 타이틀로 |
| M | 음소거 |
| D | 디버그 오버레이 (판정 윈도우, 리듬 번호, 매치 시점 오차, FPS, 그리드 좌표, 적 이름) |

화면 표시:

- **링:** 공격 범위를 감싼 네 모서리의 ㄱ자다. 쿵은 형광 초록, 짝은 형광 보라다. 성공 이펙트, 키 표시, 리듬 막대도 같은 색을 쓴다. 투명하게 나타나 리듬 순간에 가장 진해진다. 리듬이 지나도 늦은 입력이 인정되는 동안은 범위 안쪽으로 계속 줄어들고, 공격에 성공한 링은 바깥으로 퍼지며 사라진다.
- **공격 범위:** 옅게 채워져 있고, 공격 키를 누르면 테두리가 잠깐 선명해진다.
- **키 표시:** 플레이어 위에 A와 S가 있고, 지금 눌러야 할 키만 선명하다.
- **리듬 막대:** 화면 아래 가운데에 무기 패턴 한 바퀴를 8칸으로 나눠 그린다. 각 리듬 위치에 노드와 눌러야 할 키가 있고, 흰 선이 현재 시점이다.
- **디버그 타임라인:** 디버그 오버레이 오른쪽 아래 막대는 매치 시점을 가운데로 둔 타임라인이다. 노란색은 Perfect, 초록색은 Good, 흰 선은 현재 시점, 빨간 선은 마지막 입력이다.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `config.js` | 모든 상수, 무기와 적 정의, 보상 데이터 |
| `input.js` | 키 상태, 입력 시각 큐 |
| `grid.js` | 좌표 변환, 빈 칸 탐색, 길찾기, 칸별 거리 계산 |
| `player.js` | 이동 틱, 무기 리듬, 공격 범위, 판정 |
| `enemy.js` | 적 행동, 공격 위치와 범위 계산, 웨이브 스폰 |
| `telegraph.js` | 적 공격 예고 |
| `rewards.js` | 보상 추첨과 적용 |
| `renderer.js` | 모든 그리기 코드. 스프라이트로 바꿀 때는 이 파일만 고치면 된다 |

### 무기
`WEAPONS`에 무기별 값이 있다. 작성 방법은 `config.js`의 주석에 있다. 시작 무기는 런 시작 화면에서 고르고, 이후 보상 화면에 다른 무기 카드가 나오면 바꿀 수 있다. `DEFAULT_WEAPON`(`sword`)은 선택 전 기본값이다.

리듬은 입력과 상관없이 패턴대로 계속 돌아간다. 이동하면 1번 리듬부터 다시 시작한다. 최종 데미지는 리듬 데미지 x 판정 배율이다. 판정 윈도우는 네 무기 모두 Perfect ±0.05, Good ±0.12다.

| 무기 (키) | 패턴 | 리듬 간격 | 리듬별 데미지 | 쿨다운 | 공격 범위 |
|---|---|---|---|---|---|
| 한손검 (`sword`) | 쿵 짝 쿵 짝 | 0.6 0.6 0.6 0.6 | 0.5 1.5 0.5 1.5 | 0.5 | 앞 1칸 |
| 단검 (`dagger`) | 쿵 쿵 짝 쿵 쿵 짝 | 0.6 0.3 0.3 0.6 0.3 0.3 | 0.5 0.5 1.25 0.5 0.5 1.25 | 0.25 (Miss 시 0.6) | 앞 1칸 |
| 양손검 (`greatsword`) | 쿵 짝 (하프타임) | 1.2 1.2, 시작 시 0.3초 지난 상태 | 2 3.5 | 0.85 | 앞 열 위아래 3칸, 범위 안의 적 모두 |
| 활 (`bow`) | 쿵 쿵 짝 (트레실로) | 0.6 0.9 0.9 | 1 1 1.5 | 0.55 | 같은 행 오른쪽 끝까지, 가장 가까운 적 1명 |

### 적
적은 idle → attack(공격 위치로 접근 → 공격 1회 → 오른쪽 구역으로 복귀) → idle을 반복한다. attack 상태의 적은 빨간 테두리로 표시된다.

- **공격 위치:** 공격 범위가 플레이어에게 닿는 칸 중, 다른 적이 없는 가장 가까운 칸이다. 거리가 같으면 플레이어와 같은 행에 가까운 칸, 그다음 오른쪽 칸을 고른다. 모든 후보가 막혔으면 가장 가까운 후보 쪽으로 가서 기다린다. 이동할 때마다 다시 고른다.
- **비켜서기:** idle 적이 다른 적의 공격 위치에 서 있으면 이동 간격을 기다리지 않고 바로 옆 빈 칸으로 비킨다. 다른 적이 노리지 않는 칸, 그중 대기 구역 안의 칸을 먼저 고른다.
- **복귀:** 대기 구역에서 가장 가까운 빈 칸으로 돌아간다.

`ENEMIES`에 종류별 수치와 공격 범위(`attack`)가 있다. 이동하지 않는 적은 `stationary: true`를 둔다. 작성 방법은 `config.js`의 주석에 있다. 새 적을 넣을 때는 `renderer.js`의 `ENEMY_LOOKS`에도 모양을 추가한다.

HP와 데미지는 계열별로 같다. 근접은 HP 4.5, 데미지 2이고 원거리는 HP 3, 데미지 1이다. 실제 HP는 웨이브 증가율을 곱한 뒤 반올림하므로 근접은 1웨이브부터 5다.

공격 위치 후보는 플레이어 칸을 (0, 0), 오른쪽을 +열, 아래를 +행으로 적었다.

| 적 (키) | 계열 | 첫 등장 | idle 지속 | 텔레그래프 | 공격 범위 | 공격 위치 후보 |
|---|---|---|---|---|---|---|
| 검병 (`sword`) | 근접 | 1 | 5.5 | 0.6 | 왼쪽 1칸 | (+1, 0) |
| 창병 (`spear`) | 근접 | 3 | 6.5 | 0.7 | 왼쪽 2칸 일렬 | (+1, 0), (+2, 0) |
| 쌍검병 (`twinblade`) | 근접 | 7 | 4 | 0.6 | 인접 4방향 | 플레이어의 상하좌우 |
| 대검병 (`greatsword`) | 근접 | 9 | 7.5 | 0.9 | 왼쪽 열 위아래 3칸 | (+1, -1), (+1, 0), (+1, +1) |
| 궁수 (`archer`) | 원거리 | 2 | 6.5 | 1.0 | 왼쪽 끝까지 자기 행 | 같은 행, 플레이어보다 오른쪽 |
| 산탄병 (`shotgun`) | 원거리 | 5 | 5.5 | 0.8 | 왼쪽 2열 x 위아래 3행 | 오른쪽 1~2열, 위아래 1행 안의 6칸 |
| 포격병 (`mortar`) | 원거리 | 11 | 7.5 | 1.2 | 공격 시작 시점의 플레이어 칸 중심 십자 | 이동 없음 |
| 광선병 (`beam`) | 원거리 | 13 | 8.5 | 1.3 | 왼쪽 끝까지 자기 행과 위아래 행 | 플레이어 행과 위아래 행, 플레이어보다 오른쪽 |

공통 행동:

| 상수 | 기본값 | 설명 |
|---|---|---|
| `ENEMY_HOME_COLS` | 4 | idle 구역 (오른쪽에서 몇 개 열인지) |
| `ENEMY_MOVE_TICK` | 0.5 | attack 상태의 이동 틱 (접근과 복귀, 전 종류 공통) |
| `ENEMY_MOVE_ANIM_TIME` | 0.1 | 새 칸으로 미끄러지는 시간. 이동 틱의 나머지는 멈춰 있다 (지금은 0.1초 이동 후 0.4초 정지). idle 이동도 같은 시간으로 미끄러진다 |
| `ENEMY_IDLE_MOVE_INTERVAL` | 3 | idle 상태의 이동 간격 (전 종류 공통) |
| `ENEMY_IDLE_JITTER` | 0.2 | idle 지속 시간을 흩뜨리는 비율 (±) |

### 보상
| 상수 | 설명 |
|---|---|
| `REWARDS` | 보상 데이터 배열. 새 보상은 여기에만 추가한다 |
| `RARITY_WEIGHTS` | Perfect 비율 0%(`low`)와 100%(`high`)의 등급 가중치. 그 사이는 선형 보간 |
| `STAT_LIMITS` | 보상으로 도달할 수 있는 수치 한계 |
| `REWARD_CARD_COUNT` | 카드 수 (3) |
| `REWARD_INPUT_LOCK` | 보상 화면 진입 직후 입력을 막는 시간 (0.4) |
| `WEAPON_CARD_CHANCE` | 마지막 카드 자리에 다른 무기 카드가 나올 확률 (0.35) |

새 보상 예시:

```js
{ id: 'my_reward', name: '이름', desc: '설명', rarity: 'rare',
  effects: [{ stat: 'maxHp', add: 1 }], heal: 0 },
```

`stat`에는 `player.js`의 `stats` 키를 쓴다. `windowBonus`는 무기의 판정 윈도우에 더해지며, 한 리듬에 두 번 성공하지 못하도록 쿨다운 절반 미만으로 제한된다.
